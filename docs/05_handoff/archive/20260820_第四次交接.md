## 二、关键改动详解

### 1. 串口同步/异步执行机制分离（核心）

- 抽离统一安全发送 `_write_safe(text)`：只负责分片 + 片间延时 + 记 TX，不感知业务。
- `exec_sync`：保留哨兵，发 `cmd\necho "哨兵"\n`，等哨兵定界（哨兵只表示"命令已返回"）。
- `exec_async`：**不再发送哨兵**，只发 `cmd\n`，直接等业务 expect。
- rtmp 的 expect 从命令回显改为真实业务字符串：
  - `rtmp_video_start` → `publish ready|Push Start`
  - `rtmp_video_stop` → `Push Stop|Stop requested`

### 2. RTMP 持续性检测（heartbeat）

- 新增独立 `RTMPMonitor` 模块：订阅串口原始数据，匹配板端 `[RTMP] f_index`（约 2~4s 一条）作心跳。
- `SerialConsole` 新增 `add_listener()/remove_listener()`：读线程转发原始文本，串口层不含业务逻辑。
- `rtmp.py` 保持阶段从盲等 `sleep(600)` 改为循环检测：每 1s 查超时，**30s**（`heartbeat_timeout`，默认 30s，初版 5s 过极端已放宽）无 `[RTMP] f_index` 判 FAIL 提前停止。
- 判据合并：ffprobe 探测到流 **且** 无 timeout 才 PASS；FAIL 时 detail 含结构化 Monitor Result。
- 崩溃案例回放验证：`logs/20260819_031823` 最后一条 f_index 在 `03:28:08.701`，ImuThread 崩溃在 `03:28:13.058`，30s 超时能捕捉到。

## 三、非代码调研结论（重要，勿当 bug 改）

1. **`auto.crt`/`auto.key` 是孤儿文件**：MediaMTX 时代的自签名证书（`CN=mediamtx`），换 nginx-rtmp 后无任何引用，可安全删除。
2. **串口"不下电重联就连不上"真因**：板端固件卡死（RTMP/FTP 崩溃），非脚本未释放串口。代码层面正常跑完会 `console.close()` 释放。
3. **⚠️ 残留挂起进程**：有 2 个 Ctrl+Z 挂起的 ATS 进程（PID 3280/3633，状态 `T`）占着旧 `ttyUSB0` fd 未释放。**接手后先 `kill -9 3280 3633`**。
