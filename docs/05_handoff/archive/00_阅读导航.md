## 一、这个项目是干什么的

为 **VX100 EVB 板**（双核异构 RISC-V，RT-Thread msh shell）开发的**上位机自动化测试脚本**，替代人工手动测试，用于功能验证 / 产测。

**测试链路**：PC 通过串口发命令控制 EVB，通过 WiFi/FTP 验证拍照录像等功能产物。

```
PC (Python 脚本)  ──串口 2000000bps──>  EVB (msh shell)
     │                                        │
     │  WiFi/FTP/RTMP                         │ 摄像头
     ◄────────────────────────────────────────┘
```

**EVB 硬件连接**：
- **UART0**（USB-串口 FT2232）接 PC，跑 msh，波特率 **2000000** bps
- **WiFi** 连局域网（默认 G-Demo / `Gdemo@123`）
- **FTP 服务**（RT-Thread 自带，端口 21，loogg/loogg）

**测试项**（按固定流程）：WiFi 连接 → eMMC → FTP → 拍照 → 录像 → RTMP 推流，每环节验证成功/失败并生成报告。

## 二、项目架构（分层 + 注册解耦）

```
ATS/
├── main.py                 # 入口：CLI/串口探测/板子预清理/WiFi交互/调度/报告
├── config/test_config.yaml # 数据驱动配置（增删测试项只改这里）
├── core/                   # 框架核心（稳定，加用例不改这里）
│   ├── ansi.py             # ANSI 转义剥离
│   ├── logger.py           # 常驻读线程全量串口日志
│   ├── context.py          # 跨模块共享上下文（evb_ip/ftp_client/pc_ip 等）
│   ├── config.py           # YAML加载 + ${ENV}替换 + schema校验
│   ├── result.py           # Response/TestResult 数据结构
│   ├── serial_console.py   # 串口：哨兵机制+自动探测+波特率回退（核心）
│   ├── runner.py           # 拓扑排序+执行+重试+fail-fast（SKIP不阻断依赖）
│   └── reporter.py         # JSON + JUnit + HTML 报告
├── modules/                # 功能模块（每模块一文件，@register 注册）
│   ├── base.py             # TestModule 基类 + @register 装饰器
│   ├── wifi.py  emmc.py  ftp.py  photo.py  video.py  rtmp.py
├── drivers/                # PC 端辅助
│   ├── ftp_client.py       # ftplib 封装（主动模式+断点续传）
│   ├── rtmp_receiver.py    # ffprobe 实时探测 RTMP 流
│   └── rtmp_server.py      # nginx-rtmp 就绪检查（不启停 nginx）
└── tools/                  # PC 端工具（独立于测试框架）
    └── serial_terminal.py  # --terminal 交互式串口终端（类 Xcom）

tools/                      # 内置二进制（随项目走，离线可用）
└── ffmpeg/                 # ffmpeg + ffprobe + ffplay（BtbN 静态构建，零依赖）
                            # 注：RTMP 服务端用系统 nginx-rtmp（apt 装），不内置
```

**核心设计原则**：
1. **数据驱动**：增删测试项只改 `config/test_config.yaml` + modules 加文件，**不改 core**
2. **注册解耦**：模块用 `@register("xxx")` 注册，通过 `ctx`（共享上下文）传数据，不互相 import
3. **串口哨兵机制**：msh 提示符被后台日志打碎粘连，用 `echo "TOKEN"` 换行定界；异步命令用 `exec_async` 等正则不依赖哨兵

**测试流程与依赖**：
```
wifi_check → wifi_scan → wifi_join → emmc → ftp → photo
                                  │              └→ video
                                  └────────────────→ rtmp
```

## 四、目前遇到的问题（按优先级）

### 🔴 P0 — 脚本自动跑 RTMP 受 pc_ip 探测影响（主要待办）
- **现象**：手动用 `rtmp://10.1.90.128/live/cam`（EVB 同网段 IP）成功；脚本 `auto` 探测到 `10.1.64.35` 可能 EVB 连不上
- **原因**：PC 有多个 IP（有线 + WiFi 等），`_detect_pc_ip` 可能探到 EVB 不可达的那个
- **解法**：跑测试前 `ip -4 addr show` 确认 EVB 能 ping 通 PC 哪个 IP，把 `test_config.yaml` 的 `rtmp.pc_ip` 写死成那个
- **这是接手者第一步要做的事**

### 🟡 P1 — RTMP 推流命令会卡死板子（固件 bug）
- 发 `rtmp_video_start` 时若 EVB 未联网或状态异常，板子 msh 完全卡死（串口零响应），需物理重启
- 规避：确保 WiFi 已连 + 摄像头就绪后再发推流命令；卡死用 `--terminal` 复现排查

### 🟡 P1 — 固件 FTP 不稳定（已知固件 bug，沿用）
- 拍照录像后 FTP 常崩溃循环 `service go wrong`（每1.5s刷屏）
- 已规避：ensure_ftp 恢复 + 断点续传 + exec_async 抗刷屏；极不稳定时重启板子

### 🟢 P2 — ffplay 直连抗乱序帧（待真机验证）
- MediaMTX 时代曾因 `too many reordered frames` 断 ffplay 直连；改 nginx-rtmp 后是否复现待真机验证
- 绕开手段：判据用 ffprobe 实时探测（不依赖 ffplay），ffplay 仅作可选画面确认（无 DISPLAY 自动跳过）

## 七、环境要求（新机器参考）

- **OS**：Linux x86_64（Windows 不支持串口终端 termios/tty）
- **Python**：3.7+，依赖 `pyserial` `pyyaml`（仅 2 个第三方包）
- **内置工具**：ffmpeg/ffprobe/ffplay 全在 `tools/` 下，无需系统安装；RTMP 服务端用系统 nginx-rtmp（`sudo apt install nginx libnginx-mod-rtmp`）
- **串口权限**：用户在 dialout 组，或临时 `chmod 666 /dev/ttyUSB*`
- **防火墙**：放行 1024-65535 高端口（RTMP 1935 + FTP 数据端口）
- **网络**：EVB 能路由到 PC 的 IP（多网卡注意 pc_ip 选对）

> 一键检查：`./migrate.sh`，详见 `迁移指南.md`
