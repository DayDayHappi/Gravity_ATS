# ADR-015：串口上下电控制模块（PowerSwitch）

## Background

需要给 VX100 EVB 板提供「断电重启」能力：电脑通过**独立串口**连接一个上下电控制模块，板子电源线接该控制模块。脚本需要重启板子时，电脑发命令给控制模块，控制模块执行下电/上电，达到板子重启效果。

引入该能力后，系统新增一条边界：**PC →（串口）→ 上下电控制模块 →（电源线）→ EVB 板**，区别于现有「PC →（串口）→ EVB」直接链路。属于 Level 3 系统边界变更，必须建 ADR。

控制模块与板子是两个串口设备，同时插在 PC 上，须可靠区分，防止把控制模块误当板子（或反之）。

## Protocol（实测，人工真机确认）

`res/串口控制器log.txt` 实测，控制模块波特率 `115200`，帧为 4 字节 hex（**二进制线协议**，末字节 = 前三字节求和 `& 0xFF`）。注：log 中 `A00103A4`/`A0 01 01 A2 ` 为串口助手的 hex 文本渲染，线协议本体是 4 字节二进制，实现发/收均为 `bytes`：

| 方向 | 帧 | 语义 |
|------|-----|------|
| PC → 控制器 | `A0 01 03 A4` | 上电 |
| PC → 控制器 | `A0 01 02 A3` | 下电 |
| 控制器 → PC | `A0 01 01 A2` | 状态 `01`=ON |
| 控制器 → PC | `A0 01 00 A1` | 状态 `00`=OFF |

- 换行符**可不加**（已实测）。
- **响应帧返回「切换前状态」**：下电前 ON → 回 `01`（ON），已 OFF → 回 `00`（OFF），**发一次即生效，不轮询**。压测中每轮下电前必为 ON（上电帧刚执行），故每轮下电都回 `01` 且下电均生效（真机 TC-PS-001 验证）。

## Problem

1. 需要一个可复用、可配置、不破坏现有架构的上下电能力封装。
2. 控制模块串口（115200）与 EVB 串口（2000000）同时在线，需可靠探测区分（防接反）。
3. 「何时触发重启」与「如何执行上下电」必须解耦，二者不能耦合。
4. 协议字节若散落业务代码，违背 ADR-011（命令/判据/超时沉淀 drivers 唯一来源）。

## Decision

1. **封装形态 = driver 能力，非测试模块**：新增 `ATS/drivers/power_switch.py`，暴露被动能力接口：
   - `power_on()`：发上电帧。
   - `power_off()`：发下电帧。
   - `reboot()`：下电 → 延时 → 上电（延时值可配置，默认待真机确定，见 Impact）。
   - **不感知「何时触发」**：由另一独立模块决策触发时机，通过直接 `import` 调用上述接口通知本模块。本模块禁止反向 import 触发模块（单向依赖，禁止耦合）。

2. **协议唯一来源（ADR-011）**：新增 `ATS/drivers/power_commands.py`，只存协议常量：
   - `POWER_ON_FRAME = bytes([0xA0,0x01,0x03,0xA4])`
   - `POWER_OFF_FRAME = bytes([0xA0,0x01,0x02,0xA3])`
   - 判据帧：`POWER_STATE_ON = bytes([0xA0,0x01,0x01,0xA2])`、`POWER_STATE_OFF = bytes([0xA0,0x01,0x00,0xA1])`
   - 超时：`POWER_*_TIMEOUT`
   - **不写 IO、不 import console/ctx**，只存协议字节/判据/超时。

3. **端口区分 = 上电指令探测**：启用控制器时，对候选串口逐个按 115200 打开并发上电帧，**回正确响应帧 `A0 01 01 A2` 者 = 控制器，其余 = 非控制器**。
   - 原理自洽：上电帧发给真控制器 → 回 `A0 01 01 A2`；发给 EVB 串口（msh）→ 回乱码/无该帧，不误认。探测后控制器保持上电（幂等，板子本就在线，无副作用）。
   - **探测完全独立**：不改变现有 `serial_init` 的 `detect_port`（仍按 EVB 指纹 `JX009`/`msh />` 找板子）。控制器帧不含 EVB 指纹，`detect_port` 不会误认它；控制器探测也不抢板子串口。

4. **串口生命周期 = 长连接**：控制器独立供电，探测成功后串口保持打开（存 ctx），cleanup 时关闭。不必每次上下电临时 open/close。

5. **配置归属 = system.yaml（环境级硬件）**：与 `serial` 同级新增 `power_switch` 段：
   - `enabled: false`（默认关，不启用则零影响，符合 ADR-011「可选能力默认空→不启用」增量语义）
   - `baudrate: 115200`、`reboot_delay`（断电-上电间隔，默认待真机 TODO-CONFIRM）
   - 协议字节/判据/超时**不进 yaml**（ADR-011：协议属固件契约留代码），yaml 只存开关与硬件参数。

## Alternative

- **做成测试模块（modules/power.py，作为 task）**：上下电不是「测试动作」，是「环境/能力」，且触发时机由另一模块驱动，做成 task 会与模块红线（模块只做一次测试动作）和 Scenario/Runner 驱动模型冲突。否决。
- **触发逻辑内联进本模块（reboot 自动判断何时重启）**：违背用户「触发模块独立、禁止耦合」的明确要求。否决。
- **复用现有 `detect_port` 或 `serial_init` 顺带识别控制器**：两者目标与判据完全不同（EVB 指纹 vs 上电帧回包），混在一起会污染现有探测语义、破坏向后兼容。否决——采用独立探测。
- **协议字节放 yaml**：违背 ADR-011（协议留代码、yaml 只存运行参数）。否决。

## Impact

- 新增：`ATS/drivers/power_commands.py`（协议唯一来源）、`ATS/drivers/power_switch.py`（能力接口 + 独立探测 + 长连接）。
- 修改：`config/system.yaml` 增 `power_switch` 段（默认 `enabled: false`，**未启用时行为与现状完全一致，不影响现有功能**）。
- 接线：ctx 持有 power_switch 实例；探测与串口生命周期挂 prepare/cleanup（具体动作名由 Code Agent 定，保持幂等）。
- 触发时机：**不在本 ADR 范围内**，由另一独立模块实现，通过 `power_on/power_off/reboot` 直接调用。
- `reboot_delay`（断电-上电间隔，需满足板子电容放电）默认值待真机确定（TODO-CONFIRM）。
- 文档：本 ADR 登记到 `02_design/decision_record/README.md` 索引；`module_design.md`（或 system_architecture.md）补「上下电控制」系统边界；`interface_spec.md` 补 system.yaml 新字段；实施后由 Code Agent 写 devlog。
