# ADR-014：检测关键字符串集中化与配置选择（detect_strings）

## Background

2026-09-09 引入「录像/推流过程中检测固件关键错误串 `TT ERROR`」能力（devlog `20260909_1437`）：`TTErrorMonitor` 订阅串口原始数据、严格匹配 `TT ERROR`、命中**不判 FAIL**、仅追加到 `TestResult.detail` 由报告展示。

当时的实现把关键字符串**内联在代码逻辑里**，共 3 处硬编码：

1. `ATS/modules/tt_error_monitor.py`：`_TT_ERROR_RE = re.compile(r"TT ERROR")`（正则）
2. 同文件：`_SPLICE_TAILS = ("TT ERRO","TT ERR","TT ER","TT E","TT ","TT")`（跨 chunk 截断前缀）
3. `ATS/modules/video.py` 与 `ATS/modules/rtmp.py` 各一份 `_attach_tt_hits`：`"TT ERROR 命中 N 次"`（展示文案，重复两份）

这与 ADR-011「协议/判据/正则沉淀到 drivers 唯一来源，业务只 import 引用、不得内联」相抵触。`video_commands.py`/`rtmp_commands.py` 中均无 `TT ERROR` 相关定义。

用户新增需求：① 检测关键字符串**不写进代码逻辑**，单独一个文件专门保存这些字符串；② 该文件**不止这一个字符串**，后续会持续新增、随时修改，都放这一个文件，防止散落难维护；③ 通过**配置选择**「录像时检测哪些串」。

## Problem

1. `TT ERROR` 的正则与截断前缀内联在检测器/业务模块，后续新增字符串会继续散落，违背 ADR-011 单一来源。
2. 检测字符串需要「集中可扩展 + 可配置选择」，但既不能内联在业务逻辑，也不能把**正则本体**放进 yaml（ADR-013 已确立：正则属固件契约、留代码；yaml 只存选择键）。
3. 现有 `TTErrorMonitor` 只认一个硬编码串，无法按配置选择多个串，展示文案在 video/rtmp 重复两份。

## Decision

1. **唯一来源文件 `ATS/drivers/detect_strings.py`**（drivers 层，与 `video_commands.py`/`rtmp_commands.py` 同级），只存检测串定义，不写 IO/编排、不 import console/ctx：

   ```python
   @dataclass(frozen=True)
   class DetectString:
       key: str      # 配置选择键（yaml 引用）
       pattern: str  # 匹配正则/字面串
       label: str    # 报告展示名

   DETECT_STRINGS: Mapping[str, DetectString] = MappingProxyType({
       "tt_error": DetectString("tt_error", r"TT ERROR", "TT ERROR"),
       # 后续新增串在此追加，如 "xxx": DetectString(...)
   })
   ```

   - 首条即现有 `tt_error`，pattern 逐字不变（纯搬移，不改变判据语义，对齐 ADR-011）。
   - 之所以新建独立文件而非并入 `video_commands.py`/`rtmp_commands.py`：检测串是「监听命中串」，非命令/判据，且 video 与 rtmp 共用同一集合，单文件集中更利于统一维护（用户诉求②）。

2. **配置选择键放 modules 层 yaml**（运行参数，正则本体不进 yaml）：

   ```yaml
   # config/modules/video.yaml
   detect_strings: [tt_error]
   # config/modules/rtmp.yaml
   detect_strings: [tt_error]
   ```

   - 字段名 `detect_strings`，值为 `DetectString.key` 列表。
   - **默认行为**：yaml 显式写 `[tt_error]`；**未配置/空列表则不检测**（代码层不兜底默认）。这与「可选能力用默认空→不发送」的 ADR-011 增量语义一致。

3. **监听器泛化**：`TTErrorMonitor` → `StringHitMonitor`（`ATS/modules/string_hit_monitor.py`，重命名自 `tt_error_monitor.py`），构造时接收一个或多个 `DetectString`：
   - 跨 chunk 截断前缀由**字面 pattern** 自动推导（`pattern` 的全部非空真前缀按长度降序），与现 `_SPLICE_TAILS` 一致，不再手写。
   - 命中展示文案统一为 `{label} 命中 N 次：第 i 次…`，收敛到 monitor 类内，**消除 video/rtmp 两份 `_attach_tt_hits` 重复**。

4. **业务接线**：`video.py` / `rtmp.py` 读 `detect_strings`，逐 key 查 `DETECT_STRINGS`、实例化 `StringHitMonitor`、窗口内 `add_listener`/`remove_listener`（teardown 兜底）；命中**只收集、不判 FAIL**，追加到 `TestResult.detail`，由 reporter 展示（维持 20260909 既定语义）。

5. **正则与拼接的约束**：跨 chunk 前缀自动推导**仅对字面串成立**（`TT ERROR` 属字面串）。若未来新增串是含正则元字符的 pattern（如 `\s*`、`\d+`），则无法按字面前缀拼接，需在 `DetectString` 上显式提供截断前缀或降级为「不跨 chunk 拼接」（接受低概率漏检），届时在定义处标注。

## Alternative

- **并入 `video_commands.py`/`rtmp_commands.py`**：检测串不是命令/判据，且两模块共用同一集合，放单文件 `detect_strings.py` 更集中、扩展时只改一处。否决并入。
- **正则本体放 yaml**：否决——正则属固件契约，遵循 ADR-011/ADR-013「正则留代码、yaml 只存选择键」，避免正则散落配置层失去类型化与单一来源。
- **维持现状（内联 + 硬编码单串）**：改动最小，但后续每新增一个检测串都要改业务代码 + 复制 `_attach_tt_hits`，与用户诉求（集中、可扩展、可配置）相悖。否决。
- **代码层兜底默认 `[tt_error]`**：改动更小（yaml 可不写），但让「默认检测」与「显式选择」语义耦合，用户已拍板「未配置则不检测」，采用显式选择。

## Impact

- 新增：`ATS/drivers/detect_strings.py`（`DetectString` + `DETECT_STRINGS`）。
- 修改：`ATS/modules/tt_error_monitor.py` → `string_hit_monitor.py`（`TTErrorMonitor` → `StringHitMonitor` 泛化 + 前缀推导 + 展示收敛）；`video.py` / `rtmp.py`（改读 `detect_strings` 配置，删除两份 `_attach_tt_hits`）；`config/modules/video.yaml` / `rtmp.yaml`（加 `detect_strings: [tt_error]`）。
- 行为不变：`tt_error` 的 pattern 与「命中不判 FAIL、追加 detail」语义逐字一致；配置缺省由「默认检测」变为「默认不检测」（需在 yaml 显式写 `[tt_error]` 保持原行为）。
- 后续新增/修改检测串：只改 `drivers/detect_strings.py` 一处（加 `DetectString`），再在对应 yaml 的选择键列表里加/减 key，业务代码零改动。
- 文档：本 ADR 登记到 `02_design/decision_record/README.md` 索引；`module_design.md`（video/rtmp 输入 + 新增 string_hit_monitor 小节）、`interface_spec.md`（modules 层新字段）同步；实施后由 Code Agent 写 devlog。
