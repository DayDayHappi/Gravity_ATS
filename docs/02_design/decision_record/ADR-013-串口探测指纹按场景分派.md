# ADR-013：串口探测/就绪指纹按场景分派（utest 固件 msh > 提示符适配）

## Background

脚本通过 `serial_console.py` 的 EVB 指纹自动识别串口。指纹基于旧固件启动日志（`res/start.txt`）归纳，三组正则：

```python
_EVB_FINGERPRINTS = [
    r"JX009\b",                        # 启动 banner 板号
    r"GravityXR\.cn\s+Build",          # 编译指纹
    r"msh\s+/[^>]*>|msh\s*/>",         # msh shell 提示符（带斜杠，如 msh />、msh /emmc>）
]
_READY_RE = re.compile(r"FW\s+start\s+ok|msh\s+/[^>]*>|msh\s*/>")
```

近期新增的 **utest 自检固件**（实测样例 `res/utestlog.txt`）的 msh 提示符形态不同：

```
旧固件:  msh />              ← 带斜杠（根目录）
utest:   msh >               ← 不带斜杠，msh 后直接空格 + >
```

现有指纹正则第三条的两个分支都**要求 `msh` 后出现 `/`**（`msh\s+/[^>]*>` 与 `msh\s*/>`），均无法匹配 `msh >`。导致 utest 场景探测时对板子发回车、收到 `msh >` 却「无指纹匹配」，自动探测失败。同理 `_READY_RE` 也无法匹配 `msh >`，即使探测侥幸命中，`wait_for_ready()` 也会超时。

## Problem

1. utest 固件提示符 `msh >` 与旧固件 `msh />` 形态不同，现有指纹与就绪正则均不覆盖，utest 场景无法自动探测。
2. **不能全局放宽正则**：旧固件仍适用原指纹，若把 `msh\s*/>` 直接改成 `msh\s*[^>]*>` 会改变旧固件场景的探测语义，且破坏「原指纹逐字不动」的向后兼容原则。
3. 探测（`_EVB_FINGERPRINTS`）与就绪（`_READY_RE`）是两处独立正则，必须一起改，否则单改一处仍会卡在另一处。

## Decision

1. **场景声明 + 指纹集映射**：指纹正则本体留在 `serial_console.py`（遵守 ADR-011「协议不进 yaml」），场景 YAML 只声明「用哪套指纹」的**选择键**，默认 `default`（旧指纹，行为不变）。

2. **指纹集映射（唯一来源）**：
   ```python
   _FINGERPRINT_SETS = {
       "default": _EVB_FINGERPRINTS,                      # 原三条，逐字不动
       "utest":   _EVB_FINGERPRINTS + [r"msh\s+[^>]*>"],  # 追加认 msh >（无斜杠）
   }
   _READY_RE_SETS = {
       "default": _READY_RE,                              # 原正则不动
       "utest":   re.compile(r"FW\s+start\s+ok|msh\s+[^>]*>"),
   }
   ```
   - 新增指纹 `msh\s+[^>]*>` 同时匹配 `msh >`、`msh />`、`msh /emmc>`，是旧指纹的超集，但**只作为 utest 场景的追加项**，default 场景不受影响。

3. **接口透传（默认值保证旧调用不变）**：
   - `detect_port(..., fingerprint_set="default")` → `_probe_port_baud` 按 `_FINGERPRINT_SETS[fingerprint_set]` 编译正则。
   - `SerialConsole.__init__(..., ready_set="default")` → `wait_for_ready` 按 `_READY_RE_SETS[ready_set]` 匹配。
   - 旧调用方不传参，仍走 `default`，行为与现在逐字一致。

4. **场景声明字段**：`Scenario` dataclass 新增 `serial_fingerprint: str = "default"`；`scenario_manager` 解析 `sc.get("serial_fingerprint", "default")` 并透传到 `ctx.serial_fingerprint`，`_action_serial_init` 据此给 `detect_port` 与 `SerialConsole` 传参。

5. **utest 场景声明**：仅 `config/scenarios/utest.yaml` 加一行 `serial_fingerprint: utest`。其余所有场景 YAML 不加此字段 → 默认 `default` → 零影响。

## Alternative

- **场景名硬编码**：在 `_action_serial_init` 里 `if ctx.scenario_name == "utest": 追加指纹`。改动更小，但把「utest」特例写进核心编排层，违背「utest 不影响现有架构」的初衷，未来固件再变又得改核心。否决。
- **全局放宽正则**：把 `msh\s*/>` 直接改成 `msh\s*[^>]*>`。改动最小，但改变旧固件场景探测语义，破坏向后兼容，且未来无法区分固件变体。否决。
- **放 yaml 存正则**：把指纹正则写进 yaml。否决——正则本体是固件契约，属代码，遵循 ADR-011 单一来源原则放 `serial_console.py` 映射；yaml 只存选择键，避免正则散落配置层失去类型化与单一来源。

## Impact

- 修改：`ATS/core/serial_console.py`（加 `_FINGERPRINT_SETS`/`_READY_RE_SETS` 映射 + `detect_port`/`SerialConsole` 两个可选参数，默认 `default`）、`ATS/core/scenario.py`（dataclass 加 `serial_fingerprint` 字段）、`ATS/core/scenario_manager.py`（parse + run 透传 + serial_init 传参）、`ATS/config/scenarios/utest.yaml`（加 `serial_fingerprint: utest`）。
- 不改：任何现有场景 YAML、任何模块、runner、reporter；旧固件 default 路径逐字不动。
- 待真机确认：utest 固件 `health_check()` 的 `echo "EVBTEST_HELLO"`（带引号语法）是否同样支持；utest 固件冷启动是否也打印 `JX009`/`GravityXR.cn` banner（若打印，`msh >` 为冗余保险；若不打印，`msh >` 是唯一命中途径，当前方案均已覆盖）。
- 文档：本 ADR 登记到 `02_design/decision_record/README.md` 索引；`ADR-012` 补交叉引用；实施 + 真机验证后由 Code Agent 写 devlog。

## Status

Accepted（源码已实施：`_FINGERPRINT_SETS`/`_READY_RE_SETS` 映射 + `detect_port`/`SerialConsole` 可选参数 + `Scenario.serial_fingerprint` 字段 + `scenario_manager` 透传 + `utest.yaml` 的 `serial_fingerprint: utest`。真机已跑通 utest 探测命中 `msh >`，旧固件 default 路径未回归。）
