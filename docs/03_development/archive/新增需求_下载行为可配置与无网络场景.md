# 新增需求：下载行为可配置 + 无网络场景

> 提出方：Document Agent（按用户口述整理，交由 Code Agent 实施）
> 状态：已实施（devlog `20260916_0000`，待真机验证）
> 日期：2026-09-16

## 1. 背景（用户诉求）

测试场景按网络环境分两类，各用一个 scenario yaml 区分：

| 环境 | 拍照/录像后是否下载 |
|------|-------------------|
| 有网络 | 保持现状——拍完立即 FTP 下载 + 校验 |
| 无网络 | 不下载（完全不依赖 FTP，不触发 `wifi_connect`/`ftp_ready`） |

要求：**下载行为做成可配置项**，由场景层决定，而不是写死。

## 2. 现状（new_arch 分支，已核实）

- `ATS/modules/photo.py`：FTP 下载硬编码在 `_test_one` 第 4 步（`ftp2.download(...)`），
  用于 JPEG 头 + 大小校验。下载失败只降级为 PASS（message 标"下载验证失败"），不判 FAIL。
- `ATS/modules/video.py`：下载硬编码在第 5 步（`ftp2.size(...)` + `ftp2.download(...)`），
  用于大小校验 + 落盘。失败同样降级为 PASS，不判 FAIL。
- `ATS/config/modules/photo.yaml` / `video.yaml`：**无** download 开关。
- 现有场景 prepare 均含 `wifi_connect` + `ftp_ready`，无「无网络」场景。
- `video_integrity` 模块读**本地** `videos/` 目录做 H265 检测，依赖 video 先下载；
  无下载时它无输入（`empty_input_policy: skip` 会跳过）。

## 3. testvideo 分支已有类似实现（可参考，不可照抄）

| 项 | testvideo 现状 |
|----|---------------|
| `video_ftp_download: true` | `video.yaml` 开关；`video.py` 里 `if not ftp_enabled: return self._run_no_ftp(...)`，纯录像完全不碰 FTP |
| 独立 `download` 模块 | `modules/download.py` + `config/modules/download.yaml` + `config/scenarios/download.yaml`，`--scenario download` 仅下载 |
| photo 开关 | **没有**（photo 仍硬编码下载） |

注意：`new_arch` 的 `video.py` 已按 ADR-011 重构（协议沉淀到 `drivers/video_commands.py`、
查表下发完整 size 命令、TT ERROR 检测），testvideo 的 `video.py` 结构不同，**不能直接合并**，
需在 new_arch 现有实现上加开关。

## 4. 需求（建议方案，供 Code Agent 决策）

### 4.1 模块开关（配置三层 → modules 默认 + scenario override）

- `ATS/config/modules/photo.yaml` 新增 `ftp_download: true`（默认 true，行为与现状一致）。
- `ATS/config/modules/video.yaml` 新增 `ftp_download: true`（同上）。
- **命名已拍板：统一叫 `ftp_download`**（photo/video 一致），不用 testvideo 的 `video_ftp_download`。

### 4.2 业务代码

- `photo.py` / `video.py` 的 `run()` 读 `self.config.get("ftp_download", True)`：
  - `true`：现状不变（ensure_ftp → size/下载 → 校验）。
  - `false`：走「纯拍摄」分支，**不 ensure_ftp、不列目录、不 size、不下载**。

### 4.3 无下载时的降级判据（已拍板，见 §8）

- **video**：等 `Video recording completed successfully.` 即 PASS（同 testvideo `_run_no_ftp`），
  TT ERROR 检测仍保留（命中只标 detail，不判 FAIL）。
- **photo**：等 `Capture completed successfully.` 即 PASS，**不做 JPEG 头/大小校验**。
  判据依据：串口原始 log 里出现存盘打印（如 `/emmc/PIC/...`，见 §8），即视为拍照成功。

### 4.4 无网络场景 yaml

新增无网络场景（命名建议 `no_network`，最终名由 Code Agent 起，需与用户确认），
与 `normal.yaml` 对应：

- `prepare`：仅 `serial_init` + `preclean`（**去掉** `wifi_connect`、`ftp_ready`、`preview_start`）。
- `preview.enabled: false`。
- `tasks`：`emmc`、`photo`、`video`（**已拍板：去掉** `rtmp`、`video_integrity`）。
- photo/video task 用 `override.ftp_download: false`。

## 5. 关键技术事实（避免 Code Agent 重复调研）

- **配置三层**（ADR-005）：`ftp_download` 属模块行为参数 → 默认放 `modules/*.yaml`，
  场景层用 `task.override` 覆盖（`scenario_manager._apply_module_overrides` + runner params
  合并路径已支持 override 传入 `self.config`，参考 `video_integrity`/`rtmp.bitrate` 的 override 用法）。
- **FTP 红线**：`ftp_server` 全程只发一次；`ensure_ftp` 每次下载前重建连接。关闭下载后
  这些代码路径不应被触发，反而更稳（避开固件 FTP 崩溃问题）。
- **哨兵红线**：photo/video 已用真实业务判据（`Capture completed successfully.` /
  `Video recording completed successfully.`），关闭下载不涉及新判据。
- **ADR-011**：本需求新增的是**业务开关**，不新增串口协议，不涉及 `*_commands.py` 改动。

## 6. 验收标准

- `--list-scenarios` 出现新的无网络场景；`--list-modules` 不变。
- 无网络场景：无 `wifi_connect`/`ftp_ready` 动作日志；photo/video 判 PASS；
  全程无 FTP 连接/下载日志。
- 有网络场景（normal 等）：行为与现状一致（默认 `ftp_download: true`），拍完仍下载校验。
- 回归：`python3 -m ATS.main --scenario normal` 链路不回归。

## 7. 边界确认

- 独立 `download` 模块（testvideo 的 `--scenario download`）**不在本次范围**：用户诉求是
  「有网络拍完即下 / 无网络不下」，不需要事后批量下载。若后续需要再单独提需求。
- 若 Code Agent 实施中发现「photo 无下载时仍想做 JPEG 校验」必须依赖某种非 FTP 通道
  （如串口读文件大小），属能力缺口，**停下产出 Document Agent Request**，不要自行扩展协议。
- 工程红线 1：改 `ATS/` 代码 → 新建 `docs/03_development/devlog/<YYYYMMDD>_<HHMM>_<描述>.md`
  并更新其 README 索引。
