# 需求文档：日志目录按「场景/日期/运行时间戳」三级分层

> 提出方：Document Agent（按用户口述整理，交由 Code Agent 实施）
> 状态：待实施

## 1. 背景

当前日志目录乱，各场景的运行日志平铺在 `logs/` 下或场景目录下，没有按「天」聚合，
一天内跑多次就散成一堆 `20260828_174047` 之类的时间戳目录，难以按天查看。

**当前实际结构**（以代码为准）：

| 场景 | 日志路径 | 报告路径 | 问题记录路径 |
|------|---------|---------|-------------|
| `normal` | `logs/<run_ts>/`（平铺在 logs 根，`logs/normal/` 目录存在但为空） | `reports/<run_ts>/` | `logs/problem/` |
| 非 normal（stress 等） | `logs/<scenario>/logs/<run_ts>/` | `logs/<scenario>/report/<run_ts>/` | `logs/<scenario>/logs/problem/` |

`run_ts` 形如 `20260828_174047`（`%Y%m%d_%H%M%S`）。

## 2. 需求

日志目录改为「场景 / 日期 / 运行时间戳」三级结构，同一天内的多次运行都收进当天的日期目录：

```
logs/
  normal/20260828/20260828_174047/serial.log
  normal/20260828/20260828_174047/run.log
  normal/20260828/20260828_180512/serial.log
  stress/20260828/20260828_174047/serial.log
  ...
```

具体规则（已与用户确认）：

1. **所有场景（含 normal）**日志统一为 `logs/<scenario>/<日期>/<run_ts>/`。
   - normal 不再平铺在 `logs/` 根下，也纳入 `logs/normal/`。
2. **去掉中间冗余 `logs` 层**：非 normal 从 `logs/<scenario>/logs/<run_ts>/` → `logs/<scenario>/<日期>/<run_ts>/`。
3. **每次运行保留独立 `run_ts` 子目录**（同一天多次运行不互相覆盖）。
4. **报告也按天分**：`<report_root>/<日期>/<run_ts>/`。
   - normal 报告：`reports/<日期>/<run_ts>/`（report_root 仍为顶层 `reports`）。
   - 非 normal 报告：`logs/<scenario>/report/<日期>/<run_ts>/`。
5. **目录自动创建**：日期目录不存在时自动创建（`os.makedirs(..., exist_ok=True)`），
   首次运行当天即建好，后续同天运行复用。历史旧日志**不迁移**（只影响新日志）。

日期目录名格式：`%Y%m%d`（如 `20260828`）。

## 3. 实现方式

核心改动集中在 `ATS/main.py` 的 `_resolve_output_dirs()`（当前只按场景分，无日期层），
日志子目录由 `ATS/core/logger.py` 的 `init_logger(log_root)` 创建（`log_root/<run_ts>/`），
报告由 `ATS/core/reporter.py` 创建（`out_dir/<run_ts>` 传入，`makedirs` 已有）。
这两处已天然支持「root/<run_ts>」语义，**只需把 root 提前拼好日期**，改动最小。

### 3.1 `ATS/main.py::_resolve_output_dirs`

改为返回**已含日期**的 `(log_root, report_root)`：

```python
date = datetime.now().strftime("%Y%m%d")   # 每次运行取当天日期

# 日志：所有场景统一 logs/<scenario>/<date>/
log_root = os.path.join(log_dir, scenario_name, date)

# 报告：
#   normal        -> reports/<date>/
#   非 normal     -> logs/<scenario>/report/<date>/
if scenario_name != "normal" and output_dir_override is None:
    report_root = os.path.join(log_dir, scenario_name, "report", date)
else:
    report_root = os.path.join(output_dir_override or report_cfg["output_dir"], date)
```

> 注意 `output_dir_override`（`--output-dir`）语义保持：用户显式指定报告目录时，
> 报告走 `--output-dir/<date>/<run_ts>/`，日志路径不受其影响（维持现状）。

后续 `init_logger(log_root)` 会创建 `log_root/<run_ts>/`，`gen_report(report_root/<run_ts>)`
也照常工作，**无需改 logger.py 的目录创建逻辑、reporter.py**。

### 3.2 `ATS/main.py::_record_test_problem`（问题记录，需一并处理）

当前 `_record_test_problem(run_ts, log_root)` 用 `os.path.join(log_root, "problem")`。
`log_root` 现在含日期，若不处理，problem 目录会变成 `logs/<scenario>/<日期>/problem/`，
问题记录被按天打散，且 normal 的 problem 位置也会变。

建议：问题记录**不按天分**（`run_ts` 已含日期，且问题记录稀疏），统一为
`logs/<scenario>/problem/<run_ts>.log`：

- 非 normal：`logs/<scenario>/problem/`
- normal：`logs/normal/problem/`（或维持顶层 `logs/problem/`，由 Code Agent 确认二选一）

实现上需把 `problem` 根目录与「日志 log_root」解耦：让 `_record_test_problem` 接受一个
独立的 `problem_root`（不含日期），而不是复用含日期的 `log_root`。

### 3.3 文档注释同步

- `ATS/main.py::_resolve_output_dirs` 的 docstring（当前写死「normal 日志 logs/、非 normal logs/<scenario>/logs/」）需更新为新结构。
- `ATS/core/logger.py` 模块 docstring 第 4/6 行写 `logs/<run_ts>/serial.log`，需更新为 `logs/<scenario>/<日期>/<run_ts>/serial.log`（或改为「由 init_logger 的 log_root 决定」这类不写死路径的措辞）。

## 4. 不改动点

- `ATS/modules/video.py` / `photo.py` 里 `tmp_dir = os.path.join(logger.log_dir(), "videos"/"photos")`：`logger.log_dir()` 返回本次运行目录（`<run_ts>`），仍在运行目录下建 `videos/`、`photos/` 子目录，不受本次改动影响，**不动**。
- `ATS/drivers/preview_manager.py` 里 `logger.log_dir()` 写 `preview.log`：同上，**不动**。
- `ATS/core/logger.py` 的 `init_logger` 目录创建逻辑、`ATS/core/reporter.py`：**不动**（它们已支持 root/<run_ts>）。
- 历史旧日志目录：**不迁移、不清理**。

## 5. 验收标准

- 跑一次 normal：`python3 -m ATS.main --scenario normal --no-interactive-wifi`
  - 日志出现在 `logs/normal/<今天日期>/<run_ts>/serial.log` + `run.log`。
  - 报告出现在 `reports/<今天日期>/<run_ts>/`。
- 跑一次 stress：`python3 -m ATS.main --scenario stress --no-interactive-wifi`
  - 日志出现在 `logs/stress/<今天日期>/<run_ts>/`（中间**没有** `logs` 层）。
  - 报告出现在 `logs/stress/report/<今天日期>/<run_ts>/`。
- 同一天连续跑两次同场景：得到两个并列的 `<run_ts>` 子目录，serial.log/run.log 互不覆盖。
- 日期目录首次不存在时自动创建（`os.makedirs(exist_ok=True)`）。
- 测试结束输入问题后，问题记录写入 `logs/<scenario>/problem/<run_ts>.log`（不按天打散）。

## 6. 边界确认

- 本需求**只改 `ATS/main.py`**（`_resolve_output_dirs` + `_record_test_problem` 的目录拼接）+
  注释同步，**不改** logger.py 创建逻辑 / reporter.py / 各模块。
- 按工程红线 1，改动后需在 `docs/03_development/devlog/` 新建记录并更新其 README 索引。
- 若 `logs/<scenario>/logs/` 旧路径下还有近期需要参考的日志，建议人工移入新结构，
  脚本不做自动迁移（避免误删/误移历史数据）。
- 需 Code Agent 确认的细节（标记 TODO-CONFIRM）：
  1. normal 的问题记录目录：`logs/normal/problem/` 还是维持顶层 `logs/problem/`。
  2. 日期取「运行启动时刻」还是「跨零点长时间压测时以启动时刻为准」——默认取启动时刻，
     若跨零点压测需按结束时刻归档，另行确认（当前默认启动时刻即可）。
