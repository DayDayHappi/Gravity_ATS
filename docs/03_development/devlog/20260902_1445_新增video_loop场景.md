# 新增 video_loop 场景（录像 + FTP 下载 + H265 完整性检测循环）

## 日期
2026-09-02

## 变更来源
Code Agent Request（testvideo 分支）：新增「录像 + FTP 下载 + H265 完整性检测」循环场景（纯配置新增，非 bug、不改源码、不改架构）。

## 问题描述
需要一个整轮循环场景，每 cycle 完成「录像 → FTP 下载到本地 → 对本轮录像做 H265 完整性检测」的闭环，用于重复验证录像产物的码流完整性。

## 根因分析
属**配置新增**，非 bug。所需能力均已具备：
- `video` 模块已支持 `video_ftp_download` 开关（true=录像后校验+下载到 `<run>/videos/`）；
- `video_integrity` 模块已支持 `current_run` + `latest_unchecked`（manifest 去重）+ `empty_input_policy=skip`；
- `ftp_ready` 已在 prepare 幂等启动 FTP，video 下载走 `ensure_ftp`（每次重建连接）。

只需新增一个 YAML 场景即可，无任何源码改动。

## 修复内容
新增 `ATS/config/scenarios/video_loop.yaml`：

- `prepare`: `serial_init → wifi_connect → preclean → ftp_ready`（FTP 在 prepare 幂等启动，满足录像→下载闭环）。
- `loop`: enable + count=3（注释注明按需配置）。
- `tasks`:
  1. `video`（`duration: 40` + `override.video_ftp_download: true`）——录 40s 并下载；
  2. `video_integrity`（`override.input.source=current_run / selection=latest_unchecked / empty_input_policy=skip`）——检测本轮最新未检文件，无新文件则 SKIP。
- `cleanup`: `close_serial`。
- `preview.enabled: false`（无 RTMP 流可看）。

**与纯录像场景（stress_traverse_photo_mode）的区别**：本场景 `video_ftp_download=true` + 新增 `video_integrity` 检测 task。

**不改 core**：`video_integrity` 的嵌套 `override.input` 由模块内 deep-merge 处理（需求 §7），`base.py/runner.py` 均未改动。

## 如何验证
1. `python3 -m ATS.main --list-scenarios` → 出现 `video_loop`：**PASS**。
2. `python3 -m ATS.main --scenario video_loop --dry-run` → 「配置与依赖校验通过」，任务 `['video', 'video_integrity']`，两模块依赖均空：**PASS**。
3. 真机多 cycle（cycle2 检测本轮新文件、不重检 cycle1，manifest 去重生效）：**NOT RUN**（需板端 + FTP 真机链路）。

## 经验沉淀
纯配置新增场景无需触碰源码：模块能力（开关、去重、skip 策略）已在模块层具备时，场景组合只是「声明 task + override」，这正是 Scenario 层设计意图——流程/循环/组合与能力实现解耦。
