# video 新增 480p_1 组合（定义 profile + 解除禁用 + stress.yaml 接入）

## 1. 问题描述 / 需求

录像 size 命令表原有 11 个可用组合，`480p_1` 因「用户手测报错刷屏」被列入
`BLOCKED_VIDEO_PROFILES` 且 `VIDEO_PROFILES` 无其定义。用户反馈固件已修复，要求把
`480p_1` 重新纳入测试。

需求归档：`docs/03_development/archive/新增需求_video新增480p_1组合.md`。

## 2. 根因分析（为何无需改 video.py）

`video.py` 的 `resolve_video_profile` 只在 `BLOCKED_VIDEO_PROFILES` 命中时抛
`VideoProfileError`；定义好 profile + 移出禁用列表后，`480p_1` 自动可解析，
业务逻辑零改动。

`480p_1` 预期 `640×480 横屏` 是用户口述估计，与 `480p_0` 相同，需真机 ffprobe 实测
区分校准，故标 TODO-CONFIRM。

## 3. 修复内容

### 3.1 `ATS/drivers/video_commands.py`

**① 新增 profile**（插在 480p_0 与 480p_2 之间）：

```python
    "480p_1": VideoProfile("480p_1", "cam_set video 480p 1", 640, 480, "横屏"),  # 固件已修复，重新纳入；预期值 TODO-CONFIRM 待真机 ffprobe 校准
```

**② 解除禁用**（保留空映射常量，避免 `video.py` NameError）：

```python
BLOCKED_VIDEO_PROFILES: Mapping[str, str] = MappingProxyType({
    # 历史禁用项 480p_1（报错刷屏）已于 2026-09-17 解除：固件已修复，重新纳入 VIDEO_PROFILES。
})
```

### 3.2 `ATS/config/scenarios/stress.yaml`

在 480p_0 与 480p_2 两个 video task 之间插入 480p_1，参数与相邻项对齐
（`repeat: 1`、`duration: 20`），注释标注 TODO-CONFIRM。

### 3.3 `ATS/config/scenarios/video_size_traverse.yaml`

仅修正 L7 过时禁用注释措辞（480p_1 现可用，未列入 tasks 系策略选择），
**不把 480p_1 加入该场景**。

## 4. 验证结果

- `resolve_video_profile('480p_1')` 成功返回
  `VideoProfile(key='480p_1', command='cam_set video 480p 1', width=640, height=480, orientation='横屏')`，
  不再抛 `VideoProfileError`。
- `480p_1` 不在 `BLOCKED_VIDEO_PROFILES` 中；`VIDEO_PROFILES` 总数 12。
- `stress.yaml` 解析：video resolutions 顺序中 `480p_1` 位于 480p_0 与 480p_2 之间。
- `video_size_traverse.yaml` 未加入 480p_1（仅注释修正）。

## 5. 还会再有吗

- **预期宽高 TODO-CONFIRM**：`640×480` 为用户口述估计，与 480p_0 相同，真机需 ffprobe
  实测确认两者是否真的同为 640×480；若不符以实测为准回填 `width/height` 并关闭 TODO-CONFIRM。
- 解除禁用后 `resolve_video_profile` 对 480p_1 的拒绝逻辑自动消失，无残留。

## 6. 经验沉淀

- 「禁用」表达为「缺 profile 定义 + 进 BLOCKED 列表」两处；解除时需两处同步
  （加 profile、移出 BLOCKED），并保留空 BLOCKED 常量避免下游 NameError。
- 预期宽高是「预期值非实测值」语义，用户口述估计应标 TODO-CONFIRM 并在真机
  ffprobe 后回填，避免把估计值当成已验证事实。
