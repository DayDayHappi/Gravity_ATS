# BUG-007 修复：删除录像前 FTP 死代码 + 启动成功回显后清理残留恢复标志

## Date
2026-10-09 10:51

## Task
BUG-007（Level 1 模块内部变更）：修复健康监测 FTP 盲区 + 恢复标志残留，致录像启动约 54ms 即被打断（0 帧 → `文件过小 0KB` FAIL）。

## Changed
仅改 `ATS/modules/video.py`，落地 bugfix 文档定稿的方案 A + B：

1. **方案 A（根治）**：删除 `_run_once` 录像前阻塞式 FTP LIST `before = set(self._list_video_dirs(ftp))`（该值全模块零使用，纯 WiFi/TCP 路径无串口输出，目录累积后阻塞 ~50s，落入 watchdog 串口盲区被误判 SUSPECTED）；同步删除两个零引用死方法 `_list_video_dirs`、`_wait_new_dir`。保留 `_VIDEO_DIR` 常量（路径正则仍用）。注释序号 1~5 重排为 1~4。
2. **方案 B（兜底防御）**：有下载分支与无下载分支，在 `dfs_video_start` 成功回显（`r.success`）后、进入 `runtime_control.wait()` 前，调用 `runtime_control.clear_recovery()` 清一次已事实失效的残留恢复标志。附注释说明安全性：只清「进入等待前」残留标志，不影响 `wait()` 内部按 1s 步长的实时检测，真死机会重新置位、不掩盖真恢复。

## Files
- `ATS/modules/video.py`

## Reason
录像前 FTP LIST 阻塞是「FTP 盲区」触发源（无串口输出 → watchdog 误判）；恢复标志生命周期过长跨 Task 残留，导致 `wait()` 第一轮即返回、录像被立即打断。二者叠加造成真机 cycle 37 `video[hd1080p_2]` 0 帧 FAIL（板子本身健康）。
