# preview 窗口尺寸可配置（ffplay -x/-y）

## Date
2026-09-20

## Task
Windows 下 ffplay 画面观察窗口过大（跟随视频原始分辨率如 3k/4k），且无法 resize/移动。按已拍板方案 A：ffplay 启动加 `-x <宽> -y <高>` 指定窗口初始尺寸，值从 `preview.yaml` 读取，默认 960×540。

## Changed

1. **`ATS/config/modules/preview.yaml`**：新增 `window_width: 960`、`window_height: 540`（0 或留空 = 跟随原始分辨率，不传 `-x`/`-y`）。

2. **`ATS/drivers/preview_manager.py`**：
   - `__init__` 读取 `self._window_w = int(self.config.get("window_width", 0) or 0)`、`self._window_h = int(self.config.get("window_height", 0) or 0)`。
   - `_argv()` 改为条件拼入：`_window_w > 0` 时 `argv += ["-x", str(_window_w)]`；`_window_h > 0` 时 `argv += ["-y", str(_window_h)]`；url 保持最后。

## Files
- `ATS/config/modules/preview.yaml`
- `ATS/drivers/preview_manager.py`

## Reason
ffplay 默认按视频原始分辨率开窗，3k/4k 录像超屏且 SDL 窗口无法移动/缩放，影响人工观察。-x/-y 只指定窗口初始尺寸（非视频缩放），是最小改动方案。

## Verification
- `_argv()` 全分支断言通过：默认 960×540 传 `-x 960 -y 540`；全 0/空配置不传；仅 width 只传 `-x`；仅 height 只传 `-y`；负值按 0 不传；url 始终在 argv 末尾。
- `load_module_config('preview')` 读到 `window_width=960` / `window_height=540`。
- `py_compile` 通过。

## Known limitation
- `-x/-y` 是窗口**初始尺寸**，非视频缩放；ffplay 仍不会保持该尺寸（视频分辨率不同时会随流调整）。
- 「无法移动 / 无法 resize」是 ffplay SDL 窗口固有行为，`-x/-y` 只解决「框太大」；若需可缩放窗口属 ffplay/SDL 限制，超出本次范围。
- 未在真机 3k/4k 流上目视验证实际窗口表现。
