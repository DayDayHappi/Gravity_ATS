# WiFi 职责重划源码实施（ADR-008）

## 日期
2026-08-24

## 变更来源
ADR-008「WiFi 职责重划」已 Accepted，`docs/05_handoff/next_step.md` P0-1 给出源码改动清单。

## 做了什么
1. normal 场景 tasks 移除 `wifi_check` / `wifi_scan` / `wifi_join`，WiFi 不再作为 normal 独立测试项（7 项 → 4 项：emmc/photo/video/rtmp）。
2. `prepare.wifi_connect` 重新定位为「状态收敛器」：先 `check_wifi_connected` 检测，已联网则设 `ctx.evb_ip` + `ctx.wifi_ready=True` + `ctx.skip_wifi=True` 直接返回；未联网则走交互/非交互 join。
3. `wifi_check` 重新定位为「状态检测器」：只检测 ifconfig，产出 `ctx.evb_ip` + `ctx.wifi_ready`（True/False），不 scan/join/改配置。

## 改了哪些文件
- `ATS/config/scenarios/normal.yaml` — tasks 移除 wifi_check/scan/join
- `ATS/core/scenario_manager.py` — `_action_wifi_connect` 改收敛器（加已联网检测）
- `ATS/modules/wifi.py` — `wifi_check` 产出 `ctx.wifi_ready`，模块 docstring 更新定位

## 如何验证
1. 收敛器离线单测：已联网 → 不 join、wifi_ready=True；未联网非交互 → 自动 join；未联网交互回车 → 默认 join，均设 evb_ip → PASS。
2. 场景解析：normal tasks = emmc/photo/video/rtmp → PASS。
3. 模块保留：wifi_check/scan/join 仍注册 → PASS。
4. fail-fast：photo/video（depends ftp）、rtmp（depends wifi_join）在依赖模块不作为 task 时不被误 SKIP → PASS。

## 已知遗留（待 Document Agent 评估）
`rtmp.depends = ["wifi_join"]`、`photo/video.depends = ["ftp"]` 现为死依赖（依赖模块不再作为 task 执行），不影响功能但语义过时，是否清理需 Document Agent 定夺。

## 验证方式说明
无真机，仅离线单测。真机验证见 next_step.md P0-2。
