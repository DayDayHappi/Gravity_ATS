# 压测首轮上电误判修复：读空响应重试 + 探测后延时错开

## 问题描述

`--power-stress` 压测（TC-PS-001）中，cycle1 的 `power_on()` 总判「上电失败」，但物理上电
实际已成功（真机观察确认）。

根因（已用 power_switch.log 实证）：`detect_power_switch` 用上电帧探测（ADR-015），会发一次
`A0 01 03 A4` 并收到 ON 响应；紧接着压测 cycle1 第一步又是 `power_on()` 发同帧。两次上电帧
间隔约 3ms，控制器对极短间隔重复帧去抖忽略、不回响应 → `power_on()` 读 3s 超时得 `b""` →
硬判据 FAIL。物理上电在探测帧时已完成，「上电成功」真实，脚本误判。

关键事实：
1. 两次上电命令是设计行为（探测帧 + cycle1 上电帧），非重复 bug，但间隔太近。
2. cycle1 下电起（间隔 10s）所有帧正常回响应，证明只有紧跟探测的这帧被去抖忽略。
3. 控制器响应帧返回的是切换前状态，发一次即生效（此点无需改动）。

## 修复内容（Level 1 模块内部时序问题，无需 ADR，两层都做）

### 1. 驱动层 ATS/drivers/power_switch.py — 读空响应重试（保底）

- 新增模块级常量 `_RETRY_DELAY = 0.5`（模块内常量，不新增配置项，红线）。
- 新增 `PowerSwitch._send_and_read(frame)`：发帧 → 读帧，空 `b""` 时延时 `_RETRY_DELAY`
  重发一帧再读一次，返回第二次结果。覆盖所有「紧跟探测/重复帧被忽略」场景，不只压测首轮。
- `power_on()` / `power_off()` 改调 `_send_and_read`（DRY），正常回帧行为不变（帧仍只发一次）。
- `reboot()` 调 `power_off()`/`power_on()` 自动继承重试，语义不变。
- 不改 `_read_frame` 签名、不改 `detect_power_switch`、不改 `power_commands.py` 帧常量与判据。

### 2. 压测层 ATS/tools/power_switch_stress.py — 探测后延时错开

- 新增常量 `_DETECT_SETTLE_DELAY = 0.5`。
- `detect_power_switch` 成功后、进入 cycle 循环前加 `time.sleep(_DETECT_SETTLE_DELAY)`，
  让 cycle1 上电帧与探测帧错开（≥0.3s），消除首轮误判。
- 判据逻辑不变（上电回 ON 硬判据、下电回合法帧）。

## 验证结果

- `py_compile` / `compileall ATS/` 通过。
- fake-serial 单测：
  - 首帧回空、重试帧回 ON → `power_on()` 返回 ON，发两帧（重试生效）；
  - 正常回帧一次即成功，帧只发一次（行为不变，无副作用）；
  - 两次都空 → 返回空，发两帧（保底重试）；
  - `power_off()` 同样继承读空重试。
- 压测端到端 mock（3 周期，含探测后延时 + 驱动层重试）：上电硬判据 3/3、下电合法回帧 3/3、
  失败事件 0、退出码 0。

**待真机**：`python3 -m ATS.main --power-stress`，cycle1 上电不再 FAIL，30 周期 60 次切换
全回合法帧，上电硬判据 30/30；新 power_switch.log 中探测帧与 cycle1 上电帧间出现 ≥0.3s 间隔。

## 还会再有吗

读空响应重试是「保底」：若真机仍出现个别帧被忽略，重试可自动覆盖；压测层延时从源头消除
首轮误判。两层叠加后首轮误判应不再复现。重试延时 `_RETRY_DELAY`/`_DETECT_SETTLE_DELAY`
均为模块内常量，真机若需调优（如控制器去抖窗更长）可在真机校准后微调。

## 经验沉淀

- 二进制帧控制器存在「去抖」窗口：极短间隔（毫秒级）重复帧会被忽略、不回响应，导致发帧方
  读空误判。发帧后读响应接口应有「读空重试」兜底，探测帧与业务帧之间应留错开延时。
- 复用「上电帧探测」识别控制器（ADR-015）时，探测帧与后续业务上电帧语义重叠但目的不同，
  需注意二者时序衔接（探测结束不是业务开始，中间要有 settle）。
