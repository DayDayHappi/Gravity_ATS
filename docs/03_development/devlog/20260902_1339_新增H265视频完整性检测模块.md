# 新增 H265 视频完整性检测模块

## 日期
2026-09-02

## 变更来源
需求文档：`docs/03_development/archive/新增需求_H265视频完整性检测模块.md`（已评审，§0~§20）。

## 问题描述
缺少对已下载 `.h265/.hevc` 本地文件的 HEVC 码流完整性检测能力：需识别解码异常、参考帧缺失
（`Could not find ref with POC N`）、RPS 构造异常、NAL 解析异常、POC discontinuity、固定 GOP 下
missing picture，并给出失败位置的大致时间定位。

## 根因分析
属于**新增能力**（非 bug）。按需求 §0 结论，落在既有 `Scenario/Runner/Module/Config/Driver` 边界内，
通过 `@register` 扩展机制实现，不改 core、不改架构。唯一需处理的是 `base.TestModule._merge()` 顶层
浅合并会把 override 的嵌套 `input` 整段替换模块默认 `input`（丢失 patterns/recursive/empty_input_policy），
需求 §7 指定模块内 deep-merge 解决。

## 修复内容

### 1. 新增 `ATS/drivers/h265_validator.py`（Driver：FFmpeg 三阶段诊断）
- `H265ValidationResult` dataclass（字段以 §11/§20.7 为准，统一 `first_decode_error`）。
- `H265Validator.validate(file, work_dir)`：Stage 0 文件预检查（存在/普通文件/大小>0/扩展名/可读）→
  Stage 1 全文件 decode → 失败则 Stage 2 showinfo 定位 → Stage 3 trace_headers 码流分析。
- 错误分类（§10 + §20.2）：`PASS / TOOL_NOT_FOUND / INPUT_NOT_FOUND / INPUT_NOT_READABLE /
  INVALID_INPUT / NO_MATCHING_VIDEO / PROCESS_TIMEOUT / DECODE_ERROR / MISSING_REFERENCE /
  REFERENCE_CHAIN_ERROR / NAL_PARSE_ERROR / MISSING_PICTURE / TRACE_HEADERS_UNAVAILABLE / UNKNOWN_HEVC_ERROR`。
- POC gap 判定（§9）：固定 GOP 下 trace 解析出的 POC LSB 序列分段严格 +1 递增，回退即 GOP 边界；
  仅「前进跳过且缺失值从未出现」才高置信报 `MISSING_PICTURE`，否则退化为 decode 级分类，绝不硬算全局索引。
- 内存安全（§14）：所有 FFmpeg 调用 argv list（无 shell=True）；showinfo/trace 海量日志直接写文件、
  Python 按行解析；所有调用带 timeout，超时 `kill`+`wait` 回收不留僵尸；路径含空格/中文/特殊字符安全。

### 2. 新增 `ATS/modules/video_integrity.py`（Module：选择文件 + 聚合）
- 覆盖 `_merge()` 对 `input/analysis/hevc/diagnostic` 递归合并（§7 方案 A，不改 core）。
- 文件选择（§5/§6）：`current_run`（扫 `<log_dir>/videos`）| `directory`；`all/latest/latest_unchecked/explicit`；
  `latest_unchecked` 用 `video_integrity/manifest.json`（path+size+mtime_ns）去重，避免 stress 每轮重检上一轮文件。
- 过滤 `.part` 下载中文件、不递归默认、忽略目录本身（§20.3）。
- 聚合：一次 task 返回**单个** aggregate TestResult（§12），任意 FAIL→FAIL，存在 ERROR→ERROR，全 PASS→PASS；
  detail 逐文件一行。empty_input_policy fail→FAIL / skip→SKIP（§15）。
- 不依赖串口（容忍 `console=None`），standalone 脱机可跑。

### 3. 配置与注册
- 新增 `ATS/config/modules/video_integrity.yaml`（§5 字段语义）。
- 新增 `ATS/config/scenarios/video_integrity.yaml`（standalone：`prepare: []`，directory+all）。
- `ATS/modules/__init__.py` 追加 `from . import video_integrity` 触发 `@register("video_integrity")`。

## 如何验证
- `python3 -m py_compile` 三个文件 → PASS。
- `python3 -m ATS.main --list-modules` 显示 `video_integrity 依赖: 无`；`--list-scenarios` 显示 `video_integrity` → PASS。
- 离线实测（真实样本 `good.h265` 87MB / 人为损坏样本）：
  - good.h265 → PASS（全文件解码通过）。
  - 损坏样本 → FAIL，`error_type=MISSING_REFERENCE`，`last_good_decoded_frame=1126`、`last_good_pts_time=37.53s`。
  - directory+all（good + corrupt）→ FAIL，`PASS=2 FAIL=1`，detail 逐文件列出。
  - empty 目录 + fail → FAIL；+ skip → SKIP；目录不存在 → ERROR；ffmpeg 缺失 → ERROR。
  - `decode_timeout=0.5s` → `PROCESS_TIMEOUT`，且 `pgrep -c ffmpeg` 无残留进程。
- 单元验证 `_detect_missing_poc`：合成 `[0..15,0..15,17..29]`（GOP1 缺 16）→ `(16, 1)`；wrap `[13,14,15,0,1,2]` → `(None, None)`；连续 `[0..5]` → `(None, None)`。
- 单元验证 deep-merge：override 只改 source/directory/selection 后，patterns/recursive/empty_input_policy/current_run_subdir 仍保留。
- 端到端 `python3 -m ATS.main --scenario video_integrity`（真机断开、不探串口）→ 正常跑完，报告生成。

## 经验沉淀
- ffmpeg `-err_detect explode` 下即使解码报错（如 `Could not find ref with POC`）returncode 仍可能为 0
  （错误隐错机制），Stage 1 判据必须「rc==0 **且** error stderr 为空」，不能只判 rc。
- 分类优先级：`Could not find ref with POC N` 比 `Error constructing the frame RPS` 更具诊断性
  （后者常是前者的连锁），故 `MISSING_REFERENCE` 应排在 `REFERENCE_CHAIN_ERROR` 之前。
- POC gap 检测不能简单 `current != previous+1 → 丢帧`：IDR reset / CRA / POC LSB wrap / 多 slice 同图
  都会造成非单调，必须先按「回退=GOP 边界」分段、再在段内判「前进跳过 + 缺失值从未出现」。
