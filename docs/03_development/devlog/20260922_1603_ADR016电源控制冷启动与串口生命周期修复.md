# ADR-016 电源控制冷启动与串口生命周期修复（NEW-P0-05/06）

## 问题描述

设计文档（`docs/03_development/archive/ADR016_电源控制冷启动与串口生命周期修复设计.md`）指出
两个灾难级 P0：

- **NEW-P0-05 冷启动依赖反转**：`serial_init → power_switch_init` 顺序下，EVB 初始断电时
  serial_init 必然失败（EVB UART 不存在），PowerSwitch 永远得不到初始化机会，形成死锁式依赖。
  真实依赖应为 `PowerSwitch 上电 → EVB UART 出现 → 才能开 SerialConsole`。
- **NEW-P0-06 运行中 PowerCycle 后串口未重建**：Power OFF→ON 使 EVB UART 失效/重枚举，
  但恢复链路仍复用旧 SerialConsole._ser，旧 fd 收不到 reboot 后新 RX。

两个问题必须同时修复，仅交换 YAML 顺序不算完整修复。

## 修复内容（按设计文档 §34 Stage 1~4）

### Stage 1（冷启动）
- `system.yaml`：`serial` 增 `power_on_detect_timeout: 30` / `power_on_detect_interval: 0.5`；
  `power_switch` 增 `port: "auto"`（生产机可填 `/dev/serial/by-id/...`）。
- `scenario_manager._action_power_switch_init`：recovery=power_cycle 时 fail-closed（power_switch
  未启用/无候选/探测失败/POWER_STATE_ON 未确认均抛 ScenarioError，禁止 WARN+skip）；显式 port 优先；
  探测成功后发 POWER ON 确认 POWER_STATE_ON（冷启动前置）。
- `scenario_manager._action_serial_init`：若 ctx.power_switch 已存在（冷启动），在
  `power_on_detect_timeout` 内 bounded polling 等 EVB UART 枚举（`_detect_evb_with_wait`），
  排除 PowerSwitch 端口，避免「上电后 UART 未枚举完成的 race」。
- `recovery_validation.yaml`：prepare 顺序改 `power_switch_init → serial_init → ...`。

### Stage 2（运行中串口生命周期）
- `serial_console.SerialConsole.reconnect(port, baudrate)`：关闭旧 pyserial transport 后重新
  open，**保持对象身份不变**（不创建第二个 SerialConsole，避免 Runner/Coordinator/listener
  引用分裂）；listener 不清空、`_buffer_seq` 保持单调（fresh-ready 游标跨 reconnect 有效）。
- 新增 prepare action `serial_reconnect`：只重建 EVB UART transport（重新识别 EVB UART，排除
  PowerSwitch 端口），不负责 board_ready。

### Stage 3（restore 顺序）
- `recovery_coordinator._restore_environment`：移除隐式 `board_ready` prepend，严格按 YAML
  `restore` 声明顺序执行（serial_reconnect → board_ready → ...）。
- `recovery_coordinator.validate`：restore 顺序校验（serial_reconnect 必须在 board_ready 前）。
- `power_cycle.recover`：移除非严格 fallback——`reboot_checked` 不存在时抛 RuntimeError，
  禁止静默退化（设计文档 §23）。

### Stage 4（contract + capability + P1 收尾）
- `scenario_manager._validate_scenario_runtime_contract`：recovery=power_cycle 时校验
  `power_switch_init < serial_init < health_monitor_start`。
- 新增 `_validate_system_capability`：recovery=power_cycle 时 `system.power_switch.enabled`
  必须 true（dry-run/run 共用，设计文档 §22）。
- `runner` continue 分支加 success 校验（设计文档 §24：continue 必须 success，否则 abort）。

## 验证结果（离线）

- `compileall ATS/` 通过。
- `python3 -m unittest discover -s tests`：36 用例全过（新增 6 个：cold_boot 契约顺序、
  power_switch disabled fail、restore 顺序、SerialConsole.reconnect 身份/listener/seq 保持）。
- recovery_validation 新顺序通过校验；power_switch_init 排在 serial_init 后报 ScenarioError；
  power_switch.enabled=false 报 ScenarioError。
- SerialConsole.reconnect：对象身份不变、port 更新、listener 不清空、buffer seq 单调。
- restore 反向顺序（board_ready 先于 serial_reconnect）报 ValueError。

**待真机**（设计文档 §28~31）：冷启动（EVB 初始 OFF，直接 `--scenario recovery_validation`）+
运行中 PowerCycle 恢复（观察 UART 重枚举、serial_reconnect、fresh-ready）；校准
`power_on_detect_timeout` / `reboot_delay` / serial reconnect timeout。真机前禁止凭经验固定值。

## 还会再有吗

- 真机若确认 EVB UART 不重枚举（UART bridge 独立供电），`serial_reconnect` 退化为幂等 reopen，
  仍正确（reconnect 是结构上必需，不依赖重枚举事实）。
- `power_switch.port` / `serial.port` 的稳定 by-id 路径需真机确认后填写，禁止凭猜测硬编码 VID/PID。
- 测试结束自动下电需新增显式 `power_switch_off` action（不能暗藏进 close）。

## 经验沉淀

- 电源控制能力是 EVB 串口能力的基础设施前置，EVB 串口不能反过来成为 PowerSwitch 初始化的
  前置——依赖方向必须同时贯彻「首次冷启动」和「运行中恢复」两个生命周期。
- 恢复时重建 transport 必须保持 SerialConsole 对象身份不变（只换底层 pyserial），否则
  Runner/Coordinator/listener 引用分裂，后续命令/监听全部失效。
- bounded polling（明确 timeout + 间隔 + 实际指纹检测）优于固定 sleep：既避免 race，又可校准、
  不浪费等待。
- 恢复链路必须「电源控制链路成功（OFF/ON 回帧）」+「EVB 启动链路成功（fresh-ready）」双满足，
  任一失败 fail-closed，不得静默继续。
