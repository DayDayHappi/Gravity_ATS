# UI 与 Windows Phase 1~9 源码实施

- Date: 2026-09-07
- Baseline: `feature/ats-ui-windows` / `6086eda` / `ats-ui-windows-baseline-v1.0`
- Scope: Application、Event、Cancellation、Platform、PySide6 GUI、Windows 验收与打包源码

## 1. Change

在 ADR-011 已冻结的依赖方向内完成 UI/Windows 演进源码：

```text
CLI / GUI
    ↓
Application / TestService
    ↓
ScenarioManager → Runner → Module
    ↓
Driver / Context
    ↓
Platform Services
```

主要变化：

1. 新增 `RunRequest` / `RunResult` / `TestService`，CLI 仅保留参数解析、交互和退出码映射。
2. 新增结构化 EventBus，覆盖 run/cycle/task/result/log/artifact 生命周期；监听器异常与主流程隔离。
3. 新增协作式 CancellationToken，并接入 Runner、串口等待、FTP、录像、RTMP、FFprobe、H265 FFmpeg 等长耗时路径。
4. 新增 ResourceLocator、SerialPortProvider、ProcessController、RTMP readiness backend、串口租约和跨平台终端输入适配。
5. PreviewManager 改为 Python 重连 worker，不再依赖 bash、DISPLAY、终端模拟器或 POSIX killpg。
6. 新增 PySide6 五页 GUI：测试、环境、串口终端、H265 完整性、报告；GUI 只调用 TestService/Platform 接口。
7. 新增通用 Artifact 模型，photo/video/H265 产物通过统一结构进入事件和报告。
8. 新增 Windows release smoke、运行时准备、真机验收、PyInstaller onedir 与 Inno Setup 配置。
9. 保持 photo/video/rtmp/video_integrity 的既有业务判据，不复制 Module 或 Scenario。

## 4. Known Limitation / External Acceptance

以下不能由当前无 EVB、无 Windows GUI、无干净安装机的容器代替，仍需运行 `scripts/windows_acceptance.ps1` 和 `scripts/build_windows.ps1` 关闭：

- 最终 ATS 自动 COM 探测 → health_check → exec_sync/exec_async 真机证据；
- Windows 主动 FTP 列目录、JPEG、大 H265 与断点续传；
- GUI normal/STOP/重复 Start、高日志量实际运行；
- Windows RTMP/Preview 全链路；
- `release_smoke` 三轮真机执行；
- PyInstaller/Inno Setup 实际构建和无 Python 干净机安装；
- normal 10 次、stress 10 cycles、连续 Start/Stop 20 次的真机资源泄漏回归。

H265 的全文件 Decode 是当前冻结的 PASS/FAIL 主判据，因此 GUI 中固定启用；Showinfo 与 Trace Headers 仍可按需关闭。
