# Windows CLI 平台抽象层接入（P0 实施）

## Date
2026-09-20

## Task
`feature/windows-cli` 分支 P0 实施：新增 `ATS/platform/` 平台抽象层并接入六处 Linux 专属点，使上位机测试脚本在 Windows 下可用（CLI 形态）。按已定案设计 `docs/02_design/windows_cli_port_plan.md`（方案 A，7 项决策全定案）实施。

## Changed

1. **新增 `ATS/platform/` 平台抽象层**（CLI 最小裁剪版）：
   - `serial_ports.py`：`PySerialPortProvider` + `SerialPortInfo`，基于 `serial.tools.list_ports.comports()` 枚举 COMx/ttyUSB*，含 VID/PID/蓝牙过滤/USB 优先排序。
   - `console_input.py`：`create_console_key_reader()`，posix(`termios/tty`) / windows(`msvcrt.getwch`) / 非 tty(`stream.read(1)`) 三态分派，OS import 延迟到 reader 类内部。
   - `processes.py`：`ProcessController`（裁剪版，无 CancellationToken），`creation_kwargs` 区分 `creationflags(CREATE_NO_WINDOW/CREATE_NEW_PROCESS_GROUP)` vs `start_new_session`；`start` 强制 shell=False + argv list；`terminate` taskkill `/T`→`/F` 兜底 vs `killpg` SIGTERM→SIGKILL 兜底，末尾 `wait(grace)` 回收防僵尸。
   - `resources.py`：`ResourceLocator.find_tool()`（仅工具查找能力，自动处理 `.exe` 后缀 + bundled runtime/tools + PATH）。
   - `__init__.py`：导出四个核心类。

2. **`core/serial_console.py`**：`_list_candidate_ports(port_provider=None)` 改为惰性构造 `PySerialPortProvider`、返回 `candidate_names()`；删掉 `glob.glob("/dev/...")` 与 `os.access` 过滤；`detect_port` 增加 `port_provider` 注入参数（测试可传 mock）。删掉 `import os`/`import glob`。

3. **`tools/serial_terminal.py`**：删除顶层 `import termios/tty` 与 `tcgetattr/setcbreak`，改 `with create_console_key_reader() as keys: keys.read_key()` 逐字符读取。

4. **`drivers/preview_manager.py`**：构造注入 `ProcessController` + `ResourceLocator`；删掉 bash `-c` wrapper、终端模拟器候选、`setsid`/`killpg` 直启逻辑，改为 Python 重连 worker 线程（`threading.Event` 停止信号替代 CancellationToken）；ffplay 查找走 `find_tool()`；Windows 直启带窗口、Linux 无 DISPLAY 跳过。

5. **`drivers/rtmp_receiver.py`**：`_find_ffprobe` 改走 `ResourceLocator.find_tool("ffprobe", preferred)`（兼容 `.exe` 与 bundled 目录）。

6. **`drivers/h265_validator.py`**：`_resolve_ffmpeg` 改走 `ResourceLocator.find_tool("ffmpeg", path)`。

7. **`core/logger.py`**：新增 `_enable_windows_vt()`，`init_logger` 时用 `ctypes` 调 `SetConsoleMode` 启用 `ENABLE_VIRTUAL_TERMINAL_PROCESSING`（Win10+，零依赖），Windows 旧控制台 ANSI 颜色不再乱码。

## Files
- 新增：`ATS/platform/__init__.py`、`ATS/platform/serial_ports.py`、`ATS/platform/console_input.py`、`ATS/platform/processes.py`、`ATS/platform/resources.py`
- 修改：`ATS/core/serial_console.py`、`ATS/tools/serial_terminal.py`、`ATS/drivers/preview_manager.py`、`ATS/drivers/rtmp_receiver.py`、`ATS/drivers/h265_validator.py`、`ATS/core/logger.py`

## Reason
Linux 专属点（`/dev` 设备树、`termios/tty`、`os.setsid`/`os.killpg`、`bash -c`）在 Windows 直接 ImportError/行为错误；方案 A 把 OS 差异隔离进主线不存在的新目录，同步零冲突。对外 API（`detect_port`/`SerialConsole`/`run_terminal`/`PreviewManager.start/stop`）签名不变。

## Verification
- `py_compile` 全部通过。
- 平台层导入成功。
- `ProcessController`：win/posix 两分支 creation_kwargs 断言通过、shell 字符串拒绝、posix 真实进程 start→terminate 回收。
- `PySerialPortProvider`：mock 枚举器（COM/tty/蓝牙）排序与 candidate_names 断言通过。
- `create_console_key_reader`：非 tty→stream、win+tty→msvcrt 分派断言通过。
- `_list_candidate_ports` mock 注入返回正确；真实枚举返回本机 `['COM10', 'COM9', 'COM3', 'COM4']`（EVB 插入后实测）。
- `PreviewManager` skip 路径（无 ffplay / Linux 无 DISPLAY）+ mock worker start/stop 生命周期断言通过。
- `--list-modules` / `--list-scenarios` 正常。
- `find_ffprobe` / `find_ffmpeg` 在本机（Windows）正确解析到 `.exe`。

## Known limitation
- 已真机验证（2026-09-20 stress）：串口枚举 / WiFi / ffplay 拉起均正常。
- 真机发现环境问题（非代码 bug）：FTP LIST 反复超时（photo 每项 ~68s），根因是 Windows 防火墙拦截 FTP 主动模式（PORT）数据端口回连；放行防火墙后 photo 时长应回到 ~13s。
- `run_terminal` Windows 分支未在真实控制台交互验证（msvcrt.getwch 需真实 tty）。
- `_resolve_ffmpeg` 的 bundled `tools/ffmpeg/` 目录在 Windows 需 `.exe` 布局，`find_tool` 已按 `.exe` 变体搜索，但仓库当前未提交 Windows 二进制。
- 合主线时：升正式 ADR + 补 devlog README 索引 + 复核 `.gitignore` 解除 `/tests/` 忽略的分支专属行为。
