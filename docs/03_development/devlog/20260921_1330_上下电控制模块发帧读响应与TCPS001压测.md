# 上下电控制模块补强：发帧读响应 + TC-PS-001 压测脚本

## 问题描述

`docs/04_testing/test_case.md` 新增 TC-PS-001：串口控制器交替上下电压测（10min，仅控制器不接 EVB 板）。
判据要求每次发帧后收到合法 4 字节状态帧（校验和正确）、上电回 ON 为硬判据、下电回帧不强制 OFF、
全程长连接不重开。但当前 `power_switch.py` 的 `power_on()/power_off()` 是 fire-and-forget
（发帧不读响应），无法满足压测判据。

## 修复内容（Level 1 模块内部，无需 ADR）

### 1. ATS/drivers/power_commands.py（判据唯一来源，ADR-011）

- 新增 `is_valid_state_frame(frame)`：4 字节 + 帧头 `A0 01` + 末字节 = 前三字节求和 & 0xFF。
- 新增 `frame_state(frame)`：取合法帧的 state 字节（0x01=ON / 0x00=OFF）；非法帧返回 -1。

### 2. ATS/drivers/power_switch.py（接口增强）

- `power_on()`：发上电帧**并读响应帧**返回（复用 `_read_frame` + `POWER_FRAME_TIMEOUT`）；
  只回读不判状态，判据由命令层 `is_valid_state_frame` 判定。
- `power_off()`：发下电帧**并读响应帧**返回（同上）。
- 新增 `query_state()`：被动读一帧（不主动发帧；控制器不主动推送，实际状态以最近一次发帧回帧为准）。

### 3. 新建 ATS/tools/power_switch_stress.py（测试代码，TC-PS-001 实现）

- 独立压测脚本：探测控制器（长连接）→ 上电 10s / 下电 10s 交替 30 周期（60 次状态切换）。
- 判据：上电回 ON 硬判据、下电回合法帧（不强制 OFF）、结束后长连接存活性检查。
- 节拍/周期可经 `system.yaml` 的 `power_switch.stress_*` 覆盖（默认 cycles=30 / hold=10s）。
- 启动：`python3 -m ATS.main --power-stress`。

### 4. ATS/main.py

- 新增 `--power-stress` CLI 参数 + 独立分支（对齐 `--terminal` 的 tools 挂接模式，不走 Scenario）。

## 验证结果

- `py_compile` / `compileall ATS/` 通过。
- `is_valid_state_frame` / `frame_state` 判据单测：合法 ON/OFF 帧、非法帧（校验和错/帧头错/长度错/空）
  全正确。
- fake-serial 验证 `power_on`/`power_off` 增强后发帧+读响应正确、超时返回空、`query_state` 读帧正确。
- TC-PS-001 压测脚本 mock 冒烟（2 周期）：上电硬判据 2/2、下电合法回帧 2/2、长连接存活、退出码 0。
- `--power-stress` CLI 参数解析正常。

**待真机**：`python3 -m ATS.main --power-stress`（前置 `power_switch.enabled: true`，仅接控制器不接 EVB）。

## 还会再有吗

`query_state()` 因控制器不主动推送，语义有限（只能读到上一次发帧的残留回帧），文档已注明；
真机若需「严格验证下电生效」，观察连续状态是否最终稳定为 OFF（时序 TODO-CONFIRM）。

## 经验沉淀

- 压测判据需要「发帧 + 读响应」，能力接口应预留回读能力（fire-and-forget 无法自证）。
- 判据（帧合法性/校验和/状态提取）沉淀到 commands 唯一来源，业务/压测代码只 import 引用，
  符合 ADR-011。
- 独立能力压测走 `ATS/tools/` + CLI 独立分支，不污染 Scenario/模块红线（不写 for 循环进模块、
  不感知场景类型）。
