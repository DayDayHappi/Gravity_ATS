# 新增 download 场景（仅下载不测试）

## 日期
2026-08-31

## 变更来源
Document Agent Request：`docs/03_development/archive/新增需求_download场景仅下载不测试.md`。

## 问题描述
纯视频脚本（`stress_traverse_photo_mode`，`video_ftp_download=false`）只录不下载，拍摄阶段不启
WiFi/FTP。拍摄完成后需要**独立的「只下载、不做测试」场景**，把板端文件按需下载到电脑，
与拍摄脚本完全解耦（拍完手动启动）。

## 根因分析
下载能力早已具备（`FtpClient.download()` 断点续传、`_list_entries()` 列目录、`ftp_ready` 幂等
启动、`wifi_connect` 掉电记忆检测），缺的是「把这些积木组合成一个独立场景 + 一个下载模块」。

## 修复内容
全部复用现有积木，不新造轮子，不新增 ADR（Implementation 级）。

1. **`ATS/modules/download.py`（新增）**
   - `@register("download")` 模块，一个「从板端 FTP 下载文件」动作 + 参数接口。
   - 参数：`sources`（列表，每组 {label, dir, pattern}）、`latest_n`（每源取最新 N 个目录）、
     `download_dest`、`download_timeout`、`download_retries`。
   - 逻辑：列 `source.dir` 子目录 → 目录名降序取前 `latest_n` → 每目录列匹配 `pattern` 文件 →
     `FtpClient.download()` 逐个下载到 `downloads/<日期>/<label>/<子目录>/<文件>`。
   - 单文件失败不中断整体，按 source 汇总（成功数/失败数/总大小）；全部失败才 FAIL。
   - 不删除板端文件（不用 DELE）。
2. **`ATS/modules/__init__.py`**：追加 `from . import download`。
3. **`ATS/config/modules/download.yaml`（新增）**：sources 默认 video(/emmc/VIDEO/*.h265) + photo(/emmc/PIC/*.jpg)，latest_n 20。
4. **`ATS/config/scenarios/download.yaml`（新增）**：prepare=serial_init→wifi_connect→ftp_ready，loop 关，tasks 仅 download，cleanup 只 close_serial。
5. **`.gitignore`**：`downloads/` 加入忽略（与 logs/reports 同为本地产物）。

## 如何验证
1. `python3 -m py_compile ATS/modules/download.py` → PASS。
2. `importlib.import_module('ATS.modules')` 后 `get_module_cls('download')` 非 None → 注册成功。
3. `--list-scenarios` 能看到 `download` → PASS。
4. `--scenario download --dry-run` 通过，日志目录 `logs/download/<日期>`、任务 `['download']` → PASS。
5. 待真机：纯视频脚本走完后 `python3 -m ATS.main --scenario download --no-interactive-wifi`，
   应自动串口→WiFi→ftp_server→列 /emmc/VIDEO 最新 20 个目录→下载到 downloads/<今天日期>/video/。

## 还会再有吗
- 两个 TODO-CONFIRM 待真机核实：
  1. 时间戳目录名「字典序=时间序」假设（实测 `YYYYMMDD_HHMMSS[_序号]`，若序号不补零再改用 mtime/解析排序）。
  2. 跨进程重发 `ftp_server` 是否触发固件崩溃循环（`ftp_ready` 语义为「本次进程内只发一次」，跨进程重发是预期行为）。
- 板端文件不删除（本次需求明确），后续若需清理需另立需求。

## 经验沉淀
模块红线「一个动作 + 参数接口」：下载模块只负责「列目录→下载文件」，数量/来源/保存位置全部由
config 驱动，模块内不写业务 for 循环，扩照片/混合下载只改 YAML 不动代码。
