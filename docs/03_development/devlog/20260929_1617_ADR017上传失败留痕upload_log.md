# ADR-017 上传失败留痕：新增 upload.log 独立通道

## 问题描述

ADR-017 真机（20260929_160736）暴露：上传因 token 未配置失败，但 run.log 无任何痕迹。
根因：main.py 顺序为 `gen_report → _record_test_problem → logger.close() → upload_run`，
`logger.close()` 之后 `_RUN_FP=None`，上传成功/失败的 `logger.warn/info` 只打 stdout 不写
文件，事后无法排查。

## 修复内容

### 1. logger.py：新增 log_upload + close 拆分

- 新增全局 `_UPLOAD_FP` + `log_upload(msg)`：懒加载 open `upload.log`（模式同 `log_recovery`），
  `_LOG_DIR` 为 None 时静默 return。
- 拆分 `close()` 为两段：
  - `close_run_logs()`：关 serial/run/power_switch/recovery（上传前调用，让待上传文件落盘，
    **保留** upload 通道）。
  - `close()`：调 `close_run_logs()` + 最后关 `_UPLOAD_FP`。
- 职责边界新增：`upload.log` = 上传控制流留痕（与 serial/power_switch/recovery/run 并列）。

### 2. main.py：上传接线顺序调整

- `logger.close()` → `logger.close_run_logs()`（上传前只落盘常规日志，保留 upload 通道）。
- 上传前 `logger.log_upload("开始上报 ...")`；成功/未完成/失败/异常均 `log_upload` 留痕。
- 上传后（退出码计算前）`logger.close()` 关掉 upload 通道。

### 3. portal_upload.py：上传各阶段留痕

- token 缺失前的跳过文件、run_id + 待上传清单、登记成功、逐文件 PUT 完成（含字节数）、
  finalize 的 upload_state 均写 `logger.log_upload(...)`。
- token 值仍不写日志（红线）。

## 验证结果（离线）

- `compileall ATS/` 通过。
- 验证：`close_run_logs()` 后 `log_upload` 仍可写（upload.log 生成含 2 行）；`close()` 后
  `_UPLOAD_FP` 置 None。
- `python3 -m unittest discover -s tests`：42 用例全过（新增 UploadLogTest 1 用例）。

**待真机**：复现 token 未配置场景，确认 `logs/<scenario>/<date>/<run_ts>/upload.log` 含
「上报失败（不影响测试结论）: 未读取到上传 token ...」，且退出码仍由测试结果决定。

## 还会再有吗

- `upload.log` 不进 `artifacts`（避免自引用/上传未写完文件），默认不纳入上传清单。
- `close()` 语义保持「关全部日志」，新增 `close_run_logs()` 仅内部使用（main 上传前调用），
  不改变外部既有 `close()` 调用方行为。

## 经验沉淀

- 上传作为「运行结束后」动作，若复用已关闭的 run.log 通道，成功/失败都静默丢失；
  必须给上传阶段独立的懒加载通道（upload.log），且其生命周期跨越常规日志 close。
- 「先落盘再算摘要」与「上传仍要留痕」两个需求需要拆分 close 粒度：关待上传的常规日志、
  保留上报通道、最后统一收口。
- 上传失败信息务必落盘（而非仅 stdout），否则无人值守/后台运行时排查无据。
