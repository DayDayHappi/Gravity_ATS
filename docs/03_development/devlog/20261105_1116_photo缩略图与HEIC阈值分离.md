# photo 缩略图与 HEIC 大小阈值分离（BUG-008）

## Date
2026-11-05 11:16

## Task
修复 photo 辅助校验对固件缩略图 `*_thum.jpg` 与 HEIC 套用主图 10KB 阈值导致的假 FAIL
（BUG-008，Level 1 模块内部 + 新增可选配置键，Document Agent 已预复核）。
保留两条判据红线：「已下载必校验」「未列出图片是固件假成功信号」。

## Change

1. **产物分类**（`ATS/modules/photo.py` 模块级私有函数 `_classify_image(name)`）：
   - `*_thum.jpg`（大小写不敏感）→ `thumbnail`
   - `.heic` / `.heif` → `heif`
   - 其余 `.jpg` → `main`
2. **分档阈值表**（模块级 `_min_kb_by_kind(config)`）：
   - `main` ← `photo_min_size_kb`（缺省 10，**未改**）
   - `thumbnail` ← `photo_thumb_min_size_kb`（缺省 4）
   - `heif` ← `photo_heif_min_size_kb`（缺省 4）
3. **校验入口改名 + 分类传参**：`_verify_jpeg(local, min_kb)` → `_verify_image(local, kind, min_kb_by_kind)`；
   函数内顺序保持「先大小阈值、后格式头」，格式分支改由 `kind` 决定（不再看文件扩展名）。
4. **FAIL/PASS 文案保留分类信息**（便于事后 grep）：
   `文件过小 9135B < 4KB（缩略图）`、`JPEG OK 15KB（缩略图）`、`HEIF 头校验失败 ... （HEIC）`。
5. **配置**（`ATS/config/modules/photo.yaml`）新增两个可选键：

   | 键名 | 缺省值 | 适用产物 |
   |---|---|---|
   | `photo_min_size_kb` | 10（现有，未改） | 主图 |
   | `photo_thumb_min_size_kb` | **4**（新增） | 缩略图 `*_thum.jpg` |
   | `photo_heif_min_size_kb` | **4**（新增） | `.heic` / `.heif` |

   老场景不配置新增键时，代码内缺省值与 yaml 一致，行为与用例 1~4 相同。

未改：`_list_jpgs` 下载范围（缩略图仍下载留证且参与校验）、主判据、下载失败降级语义、
FAIL 判定语义（已下载且校验失败 → FAIL）。

## Reason
固件缩略图是 480×360 小图（实测 8.4–22.5KB，亮场景约 9.0–9.3KB），HEIC 6.9–83KB，
与主图（1008×4032 等，≥11.7KB）不是同一量级，不可能共用 10KB 阈值。
真机 run `logs/stress/20261104/20261104_182626` 累计 245 条 photo FAIL 全部来自
缩略图（run.log 中 `_thum.jpg 校验失败` = 245），主图 0 失败。

## Known limitation
- 缩略图尺寸随画面亮度漂移（8.4–22.5KB），4KB 是安全下界；若后续出现更暗/更简单场景仍有风险，
  需增加「按 480×360 尺寸 + 格式头」的第二重判据（不在本任务内，见任务单 §8 TODO-CONFIRM）。
  真机 58 cycle 中固件侧 `thumbnail saved` 中位数 9185B、最小 9093B，距 4KB 仍有 5KB 余量。
- `*_thum.jpg` 是否属产品交付产物未确认；若固件后续移除缩略图，`photo_thumb_min_size_kb`
  将成为死配置，届时清理。
- 任务单 §7 边界外发现（仅记录不扩大改动）：`_classify_image` 依赖 `_thum.jpg` 后缀，
  若固件改名（如 `_thumb.jpg`）会回落到主图档位；当前固件实测命名固定，暂不加兼容。
