# portal 上传自签名证书 SSL 校验（方案 2-b）实施

## 问题描述

Windows 下跑完 stress 后，结果上报 ATS Portal 失败：

```
登记清单失败（重试 3 次）: HTTP -1: b''
```

`HTTP -1` 是 `_post_json_with_retry` 对网络层 `PortalUploadError` 的兜底编码，真实异常是
`SSLCertVerificationError: certificate verify failed: self-signed certificate`。

**根因**：`system.yaml` 配 `https://10.1.64.183:8443`（HTTPS 自签证书），但 `portal_upload.py`
`_request()` 直接 `urllib.request.urlopen(req)` 未传 `context`，走系统默认校验 → 自签不受信任。
「配置（HTTPS 自签）」与「代码能力（无证书处理）」不匹配。

完整排查见归档文档：
`docs/03_development/archive/Windows_CLI_portal上传自签名证书SSL校验_排查与修复方案.md`

## 修复内容（方案 2-b，Document Agent 已定案）

精准信任指定自签证书，不全局禁用校验、不改环境。

### 1. `ATS/config/system.yaml`
upload 段新增一项：

```yaml
ca_cert: ""   # 自签名证书 PEM 路径（2-b）；空 = 走系统默认校验；相对路径归一化到工程根
```

### 2. `ATS/application/portal_upload.py`
- 顶部 `import ssl`。
- 新增 `_PROJECT_ROOT`（工程根目录）与 `_resolve_from_project_root()`：把 `token_file`/`ca_cert`
  相对路径归一化到工程根，修「附带隐患」（token_file 相对路径随启动 cwd 漂移）。
- 新增 `_build_ssl_context(upload_cfg)`：`ca_cert` 空返回 `None`（默认校验）；非空
  `ssl.create_default_context(cafile=...)`。
- `_request()` 增 `ssl_ctx=None` 形参，`urlopen(..., context=ssl_ctx)`。
- `_post_json_with_retry` / `_put_file_with_retry` / `_finalize_with_retry` 均增 `ssl_ctx` 形参并透传。
- `upload_run()` 开头 `ssl_ctx = _build_ssl_context(upload_cfg)`，传给三个 helper。

### 3. `tests/test_portal_upload.py`
- `_mock_request` fake 签名同步加 `ssl_ctx`。
- 新增 `SslContextTest` 6 例：
  - `ca_cert` 空/空白 → `None`
  - `ca_cert` 有效 PEM → context 且 `get_ca_certs()` 非空（Python 3.12 无 `.cafile` 属性，改此法断言）
  - `ca_cert` 相对路径 → mock `ssl.create_default_context` 断言 cafile 归一化到 `_PROJECT_ROOT`
  - `_resolve_from_project_root` 各种输入
  - `upload_run` 透传 ssl_ctx（3 次调用均非 None 且证书已加载）

## 验证结果

- `python -m unittest tests.test_portal_upload -v`：10/10 通过。
- 端到端（本地 HTTPS mock 服务 + 自签证书）：
  - 配 `ca_cert` → 三步协议走通，`upload_state=complete: True` ✅
  - 不配 `ca_cert` → 仍按预期失败 `HTTP -1`（证明是「精准信任」而非「禁用校验」）✅
- `python -m py_compile` 两文件通过。

## 还会再有吗

- 真机路径尚未验证（需 Windows + EVB + 真实 portal 服务）；本机已验证 workaround
  （`SSL_CERT_FILE` 环境变量）端到端通过，代码路径等价。
- 相对路径归一化已同时覆盖 `token_file`（附带隐患），但需确认无调用方依赖「相对 cwd 解析 token」的旧行为。

## 经验沉淀

- HTTPS 自签场景：优先「精准信任指定 CA」（`ssl.create_default_context(cafile=...)`），
  而非 `verify_ssl: false` 全局关校验（安全弱）或装系统受信任根（换机失效）。
- Python 3.12 起 `SSLContext` 无 `.cafile` 属性，断言用 `get_ca_certs()`。
- 相对路径配置项应在解析处一次性归一化到确定锚点（工程根），避免随 cwd 漂移的隐式 bug。
