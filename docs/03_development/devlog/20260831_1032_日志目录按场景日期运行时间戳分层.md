# 日志目录按「场景/日期/运行时间戳」三级分层

## 日期
2026-08-31

## 变更来源
Document Agent Request：`docs/03_development/archive/新增需求_日志目录按场景日期运行时间戳分层.md`。

## 问题描述
日志目录散乱：normal 平铺在 `logs/<run_ts>/`，非 normal 在 `logs/<scenario>/logs/<run_ts>/`（多一层冗余 logs），
没有按「天」聚合，一天内多次运行散成一堆时间戳目录，难以按天查看。

## 根因分析
`main.py::_resolve_output_dirs` 只按场景分（无日期层），`logger.init_logger(log_root)` 与 `reporter.generate`
天然支持 `root/<run_ts>` 语义，只需把 root 提前拼好日期即可，改动集中在 main.py。

## 修复内容
只改 `ATS/main.py`（目录拼接）+ 注释同步，不改 logger.py 创建逻辑 / reporter.py / 各模块：

1. **`ATS/main.py::_resolve_output_dirs`**
   - 返回值从 `(log_root, report_root)` 改为 `(log_root, report_root, problem_root)`，log_root/report_root 已含当天日期（`%Y%m%d`），problem_root 不含日期。
   - 日志：所有场景（含 normal）统一 `logs/<scenario>/<date>/`（去掉中间冗余 logs 层）。
   - 报告：normal → `reports/<date>/`；非 normal → `logs/<scenario>/report/<date>/`；`--output-dir` 时报告走 `<output-dir>/<date>/`，日志/问题路径不受影响。
   - 问题记录根：`logs/<scenario>/problem/`（不按天打散，run_ts 已含日期）。
2. **`ATS/main.py::_record_test_problem`**
   - 参数 `log_root` → `problem_root`（解耦，接受不含日期的 problem 根目录），写入 `problem_root/<run_ts>.log`。
   - 文档注释同步：问题记录统一 `logs/<scenario>/problem/`（normal 为 `logs/normal/problem/`，不再用顶层 `logs/problem/`）。
3. **`ATS/main.py::main` 调用点**：接三个返回值，problem 记录改传 `problem_root`。
4. **`ATS/core/logger.py` 模块 docstring**：不再写死 `logs/<run_ts>/serial.log`，改为「由 init_logger(log_root) 决定，log_root 由 main.py 按场景/日期拼好」。
5. **`ATS/config/system.yaml`**：`report` 段注释同步为新分层结构。

## 如何验证
1. `python3 -m py_compile ATS/main.py ATS/core/logger.py` → PASS。
2. 单元验证 `_resolve_output_dirs`：
   - normal → `('logs/normal/<date>', 'reports/<date>', 'logs/normal/problem')`
   - stress → `('logs/stress/<date>', 'logs/stress/report/<date>', 'logs/stress/problem')`
   - stress + `--output-dir` → 报告走 `<odir>/<date>`，日志/问题路径不变 → 均符合预期。
3. 待真机冒烟：`python3 -m ATS.main --scenario normal --no-interactive-wifi`，确认日志在
   `logs/normal/<今天日期>/<run_ts>/`、报告在 `reports/<今天日期>/<run_ts>/`。

## 还会再有吗
- 历史旧日志**不迁移、不清理**（只影响新日志），`logs/` 下旧平铺目录与 `logs/<scenario>/logs/` 旧路径仍在，需人工按需移入新结构。
- 跨零点长时间压测按**启动时刻**归档（默认，已确认）；若后续需按结束时刻归档另行处理。

## 经验沉淀
把「日期层」提前拼进 root 而非改 logger/reporter 的创建逻辑，是最小改动点——logger/reporter 已支持
`root/<run_ts>`，上层只需变换 root 的构成即可完成分层调整，避免触碰通用代码。
