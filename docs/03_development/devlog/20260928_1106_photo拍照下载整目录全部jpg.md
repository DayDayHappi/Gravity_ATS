# photo 拍照下载改为整目录全部 jpg（不只第一张）

## 问题描述

photo 模块拍照后 FTP 下载只取目录下第一张 jpg（`jpg0 = jpgs[0]`），无法对整目录
（auto 模式会生成多张 jpg）做完整辅助验证。需求：遍历 `/emmc/PIC/<ts>/` 下全部 jpg，
逐张下载 + JPEG 头/大小校验。

## 修复内容（ATS/modules/photo.py `_test_one()` 下载段，Level 1 模块内部）

- `_list_jpgs` 已返回目录下全部 `.jpg`，无需改（能力现成，缺的是循环下载一环）。
- 下载段从「取 `jpgs[0]` 下载+校验一张」改为「遍历 `jpgs` 全部下载+逐张校验」。
- 本地落盘建子目录 `tmp_dir/{safe_mode}_{new_dir}/`（`safe_mode` 用 `re.sub` sanitize
  mode 名，避免 `single 1080p` 含空格、多张同名冲撞）。
- 判据语义（决策点落定，维持辅助性质）：
  - FTP 下载失败 → **辅助降级不判 FAIL**（test_strategy.md 红线）；单张下载失败 continue
    下一张；全部下载失败 → PASS「下载验证失败」。
  - 「已成功下载的 jpg」逐张 JPEG 头+大小校验，**任一失败判 FAIL**（与历史单张语义一致，
    只是覆盖范围从第一张扩展到全部）。
  - 全部下载成功且校验通过 → PASS，message 含张数与本地目录。

## 验证结果（离线 mock）

- `py_compile` 通过。
- 4 场景 mock：
  1. 3 张 jpg（第 3 张坏头）→ 全部下载、FAIL、message 含坏文件名；
  2. 2 张全合法 → PASS「全部 2 张 jpg 校验通过」；
  3. 全部下载失败 → 辅助降级 PASS「下载验证失败」；
  4. mode 含空格 `single 1080p` → 子目录 sanitize 为 `single_1080p`。

**待真机**：auto 模式（一次生成多张 jpg）拍照，确认整目录全部下载、逐张校验；FTP 会话
3s 空闲断开问题由 `download()` 内部每次 `connect()` 重建覆盖（循环多张安全），真机验证。

## 还会再有吗

- 下载范围维持仅 `.jpg`（`_list_jpgs` 已过滤）；若目录下存在非 jpg 文件（缩略图/其他格式）
  不在本次范围，未来需要可扩展。
- 判据仍为辅助性质（下载/校验失败不反向救回主判据 Capture completed successfully.），
  未升级为主判据，故不牵动 module_design/ADR，只写 devlog。

## 经验沉淀

- 辅助判据「下载全部」与「已下载必校验」是两件事：下载失败降级（不阻断主判据），
  但一旦下载成功就要严格校验（否则辅助验证失去意义），二者边界清晰。
- 本地落盘用 `{safe_mode}_{new_dir}/` 子目录 + sanitize，避免含空格 mode 名和多张同名冲撞。
- 模块红线：下载循环属「单次测试动作」内部实现（遍历一个目录的文件），非「重复测试动作」，
  可写 for 循环，不违反模块红线。
