# 消除 photo/video 下载时每个文件重复 LIST 父目录

## Date
2026-11-06 11:29

## Task
消除 `FtpClient.download()` 内为取文件大小而**重复 LIST 父目录**的开销（耗时报告 O1 项，
Level 1 模块内部 + driver 可选参数，Document Agent 已预复核）。判据语义、下载行为、
续传/重试逻辑均不变。

## Change

1. **`ATS/drivers/ftp_client.py`** — `download()` 新增可选参数 `size_hint: int = None`：
   - `total = size_hint if (size_hint and size_hint > 0) else self.size(remote_path)`
   - `size_hint=None` / `0` / 负数 → 回退原 `size()`，**行为与改动前完全一致**，其它调用方零影响。
   - 新增保底复核（任务单 §7 可选项，本次采用）：传输正常结束但 `local_sz < total` 且本次用了
     hint 时，先 `self.size()` 复核一次真实大小再判续传——防止 hint 过期导致误判「提前结束」
     而多跑一轮无谓续传。复核后 `hint_used=False`，同一轮内不再重复复核。
   - 续传/REST/重试逻辑**未改**；`total` 的 4 处后续用途语义不变。
   - `size()` 本身未改（仍 LIST 父目录，供无 hint 的调用方使用）。

2. **`ATS/modules/photo.py`** — `_list_jpgs()` 返回值由 `[name, ...]` 改为 `[(name, size), ...]`
   （底层 `ftp.list_files_detail()`，该函数原本全工程无调用方）；下载循环解包 `for jpg, size in jpgs`
   并传 `size_hint=size`。`len(jpgs)` 语义不受影响。

3. **`ATS/modules/video.py`** — `sz` 已在 L152 取到（失败会重试一次再取），下载时传
   `size_hint=sz`，不再让 `download()` 内部重复 `size()`。

4. **测试** — `tests/test_photo_heif.py` 的 `_FakeFtp` 补 `list_files_detail()` 并改断言；
   新增 `tests/test_ftp_download_size_hint.py`（9 例）。

## Reason
`ftp_client.py` 的 `size()` 用 `CWD → LIST → CWD` 解析（该 FTP 不支持 SIZE 命令）。photo 一次拍照
目录有 N 张图，`_list_jpgs` 已 LIST 过该目录拿到名字，`download()` 又为每张图各 LIST 一次父目录
→ 1 + N 次 LIST，其中 N 次纯重复。video 同形态（`size()` 一次 + `download()` 内再 `size()` 一次）。

## Verification

### 离线（全绿）
- `python3 -m unittest discover -s tests` → **80 tests OK**（改前 71 + 新增 9）
- `python3 -m ATS.main --scenario stress --dry-run` → exit 0

新增用例覆盖：`size_hint` 合法 → 不调用 `size()`；`None`/`0`/负数 → 回退 `size()`；
hint 过期时保底复核不误判；真截断仍判失败；hint 偏大但实际已够仍成功；
`_list_jpgs` 返回 `[(name, size), ...]` 且过滤不变；异常返回 `[]`。

### 真机（已回填实测）

**环境**：EVB 重启 + eMMC 清空后运行。验证用临时场景（不入库，`/tmp/ats_verify_config`），
只跑 `photo[auto]`（10 图目录）+ `video[sd1080p_0] 20s`，2 cycle。

> 说明：常规 `stress` 场景每 cycle 含 rtmp 600s，用户要求只跑拍照+录像压缩时间，故用临时场景。
> 另：板端 FTP 若已在运行，`ftp_server` 回 `already running` 而非 `service launched success`，
> 脚本会判失败（**与本次改动无关的历史缺口**，见 Known limitation）。本次用运行时 harness
> 放宽该正则完成验证，未修改仓库代码。

#### 主指标：真实 LIST 次数（instrumented 精确计数，`photo[auto]` 一次 10 图目录）

| 模式 | `_list_entries()`（真实 LIST） | `size()` 调用 | download 次数 | 结果 |
|---|---|---|---|---|
| 改前（还原旧路径） | **11** | **10** | 10 | PASS |
| **改后** | **1** | **0** | 10 | PASS |

→ 10 次重复 LIST 全部消除，实测与离线单测结论一致。

#### 关于任务单 §4「connect 次数 3/11/12 → 恒为 2」的修正

**该期望不成立，connect 次数改后仍为 11。** 原因：FTP 红线要求「每次下载前重建连接」
（板端 3s 空闲断会话），故 N 个文件必然 N 次 connect；任务单假设的「2 次」与既有架构约束冲突。
本次实际收益体现在 **单文件内部少一次 LIST**，而非减少 connect 次数。已在下方用耗时与
LIST 计数两个直接证据替代该指标。

#### 耗时（同一 photo[auto] 块，10 图目录）

| 指标 | 改前（`20261105_133805`，n=58） | 改后（本次 n=4） | 变化 |
|---|---|---|---|
| photo[auto] 块耗时 中位 | **26.48s** | **14.71s** | **−44%** |
| photo[auto] 块耗时 均值 | 26.42s | 14.35s | −46% |
| 单文件间隔（连接→连接）中位 | 1.84s（n=530） | **0.71s**（n=20） | **−61%** |

（改后 4 个样本：13.7 / 12.1 / 15.7 / 15.8s，跨两个独立 run，稳定。）

#### 功能回归
- `photo[auto]` 全部 PASS，`全部 10 张图片校验通过` 张数与改前一致。
- `下载提前结束` = 0，`下载异常` = 0，`文件过小` = 0（3 个 run 均为 0）。
- video 下载正常：40.8MB / 13.2s、40.8MB / 13.4s。
- **续传验证（真机）**：预置本地 492902B（远端 1643008B 的 30%）后
  `download(size_hint=1643008)` → True，本地 1643008B，**字节完全一致**。
- 离线断网/异常路径：`_list_jpgs` 异常返回 `[]`、`size_hint` 路径不抛异常（单测覆盖）。

## Known limitation
- **本次发现的既有缺口（未修，范围外）**：`start_ftp()` 只认 `service launched success`，
  板端 FTP 已运行时固件回 `[FTP] Ftp server is already running!!!`，脚本判「FTP 服务启动失败」，
  photo/video 全 SKIP。历史各轮都是冷启动（板子重启后首次跑）所以未暴露。修复方向：判据增加
  `already running` 幂等分支。**需 Document Agent 立项/授权后再改**（`ftp.py`/`ftp_commands.py`
  不在本任务单白名单）。同轮还发现固件有 `ftp_force_restar` 命令可用于重启 FTP 服务。
- 主指标口径与任务单 §4 不一致（connect 次数不适用），已在上文用 LIST 计数 + 耗时替代。
  建议 Document Agent 同步修正任务单/耗时报告中的该指标。
- 保底复核采用「hint 不足时复核一次」，仅在异常路径多一次 LIST；正常路径零额外开销。
- 缩略图仍下载校验（任务单 §8 O2 未决），本次只省掉其重复 LIST（每张约 0.7s）。
