# ADR-016 第三轮验收修复（2 NEW-P0 + 1 NEW-P1 + QA-GAP-02 根因）

## 问题描述

第三轮验收（`docs/03_development/archive/ADR016_第三轮验收问题与修复建议.md`）确认上一轮
问题已关闭，但发现 3 个软件问题 + QA-GAP-02（tests 未入 git）+ HW-RISK-01（真机门槛）。
本轮修复 3 个软件问题 + QA-GAP-02 根因，HW-RISK-01 留真机确认。

## 修复内容

### NEW-P0-03：after_recovery=continue 语义统一
- `core/runner.py` 的 Outcome 处理增加 `continue` 分支：恢复成功且
  `after_recovery=continue` 时，不重跑当前 Task、直接继续下一个 Task，不产生
  `board_recovery ERROR`、不 ScenarioAbort。消除了「Coordinator 校验允许 continue 但
  Runner 当未知 action 误判恢复失败」的接口不一致。

### NEW-P0-04：PowerCycle 严格校验 OFF/ON 回帧
- `drivers/power_switch.py` 新增 `reboot_checked()`：下电后验证合法状态帧
  （`is_valid_state_frame`，不强制 OFF——ADR-015 实测下电首发改常回 ON，不凭猜测加强
  语义）→ 延时 → 上电后严格验证 `POWER_STATE_ON`。任一步失败抛 `PowerSwitchError`。
- `recovery_backends/power_cycle.py` 的 `recover()` 改调 `reboot_checked()`（旧
  PowerSwitch 无该方法时兼容退回 `reboot()`）。
- 原 `reboot()` 保留作普通能力接口，不破坏 ADR-015 已有使用方。

### NEW-P1-03：--dry-run 执行静态契约校验
- `scenario_manager.py` 抽公开 `validate_scenario()`（包装 `_validate_scenario_runtime_contract`）；
  `run()` 与 `main.py` 的 load 后均调用，使 `--dry-run` 也能校验
  health_monitor/recovery 接线与 action 顺序（不做串口/网络探测）。

### QA-GAP-02 根因：.gitignore 忽略 tests/
- `.gitignore` 移除 `/tests/` 忽略规则（改为注释说明），使 `tests/`（30 个 unittest）
  纳入 git 跟踪。已 `git check-ignore` 验证不再被忽略。

## 验证结果（离线）

- `compileall ATS/ tests/` 通过；`git check-ignore` 确认 tests/ 放行。
- `python3 -m unittest discover -s tests`：30 用例全过（新增 7 个：reboot_checked
  OFF+ON 合法/空/非法帧、continue 语义、validate_scenario 公开入口）。
- NEW-P0-03：continue → 不重跑、不产生 board_recovery ERROR、继续下一 task。
- NEW-P0-04：reboot_checked OFF 合法+ON 合法成功；OFF 空/ON 空/ON 非法帧均抛
  PowerSwitchError。
- NEW-P1-03：validate_scenario 对违规场景抛 ScenarioError、对 recovery_validation 通过。

**待真机**：HW-RISK-01（PowerCycle 后 EVB UART 是否 USB 重枚举）→ 之后执行
TC-BH-001~003 + TC-RCV-001~005。跑 recovery_validation 前须把 system.yaml 的
`power_switch.enabled` 改 true（配置设计，非 bug）。

## 还会再有吗

- HW-RISK-01 若确认串口重枚举，需新增 `serial_reconnect` 恢复 action（属 Scenario/
  Application runtime restore，不放 PowerSwitch）；若串口不消失则当前 fresh-ready 直接可用。
- `reboot_checked` 的 OFF 判据当前只要求「合法状态帧」不强制 OFF（遵循 ADR-015 真机
  协议事实）；若真机确认下电回帧能稳定 OFF，可再收紧为 `frame_state==0x00`。
- 本轮完成后不再扩展功能，直接进真机验收。

## 经验沉淀

- 策略枚举与消费方必须同源一致：Coordinator 校验允许的枚举值，Runner 必须真正支持，
  否则「合法配置」会被误判成「未知 action」导致恢复成功反而中止。
- PowerCycle 恢复必须同时满足「电源控制链路成功（OFF/ON 回帧校验）」+「EVB 启动链路
  成功（fresh-ready）」，fresh-ready 只能证明收到新 RX，不能证明控制器真的断电重启。
- dry-run 的语义是「校验配置」，静态契约校验必须与 run 共用同一入口，避免 dry-run 报
  PASS 而真机 run 才报错的不一致。
- .gitignore 的忽略范围要定期核查：源码/测试类交付物被误忽略会导致「声称已交付」但
  实际未入 git（本轮 tests/ 即此）。
