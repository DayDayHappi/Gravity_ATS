## Change

### 1. 用户更正：4k / 3k 不支持 60fps（本 session 内确认）

任务单 §6 Q4 原写「4k/3k 支持 60fps」，用户在本 session 更正为**不支持**。据此矩阵由 192 条
降为 **168 条**；`fps` 对 4k / 3k 强制为 30。

### 2. 最终取值域

| 参数 | 取值 | 数量 |
|---|---|---|
| `res` | 4k / 3k / 1080p / sd1080p / 720p / 480p | 6 |
| `fps` | 30 / 60（**4k、3k 仅 30**） | 2（受 res 约束） |
| `eis` | 0 / 1 / 2（**3k 仅 2**） | 3（受 res 约束） |
| `codec` | h264 / h265 | 2 |
| `bitrate` | 8000000 | 1 |
| `gop` | 30 | 1 |
| `vui` | 709 / 6010 / 6011 | 3 |

组合数 = 4k(1×3×2×3=18) + 3k(1×1×2×3=6) + 4 档×(2×3×2×3=36 → 144) = **168 条**
（按 22.4s/条估算纯录像约 1.05 h）。

### 3. 协议层 `ATS/drivers/video_commands.py`（重写）

**移除**：`VIDEO_PROFILES`（13 个旧组合）、`VideoProfile`、`DEFAULT_VIDEO_PROFILE`、
`BLOCKED_VIDEO_PROFILES`、`resolve_video_profile()`、`VideoProfileError`。

**新增**：

```python
VIDEO_RESOLUTIONS = ("4k", "3k", "1080p", "sd1080p", "720p", "480p")
VIDEO_FPS = (30, 60)
VIDEO_EIS_MODES = (0, 1, 2)
VIDEO_CODECS = ("h264", "h265")
VIDEO_VUI = ("709", "6010", "6011")
VIDEO_BITRATE_RANGE = (50000, 25000000)
VIDEO_GOP_RANGE = (0, 1000)
VIDEO_EIS_FORCED_OFFLINE = {"3k": 2}          # 3k 只允许 eis 2
VIDEO_FPS_FORCED = {"4k": (30,), "3k": (30,)}  # 用户 2026-11-10 更正
VIDEO_SET_COMMAND = "cam_set video {res} {fps} eis {eis} {codec} bitrate {bitrate} gop {gop} vui {vui}"
VideoParams(frozen dataclass)  # .key → 4k-30-e0-h265-b8m-g30-v709；.command → 完整命令
resolve_video_params(mapping) -> VideoParams   # 7 键必须写全，非法即抛 VideoParamsError
iter_video_params() -> Iterator[VideoParams]   # 固定顺序枚举，供矩阵生成与计数
```

校验规则：res/codec 严格枚举；fps/eis 受 res 约束；bitrate/gop 上下限；`bool` 显式拒绝
（`True` 不能当 fps）；`vui` 的 YAML 整数写法（`709`）归一化为 `"709"` 后匹配；缺键报错。

`VIDEO_SET_ERROR` 追加 `busy`（宽匹配 `\bbusy\b`，TODO-CONFIRM 待真机原文后收紧）。

### 4. 模块层 `ATS/modules/video.py`

- 参数接口 `video_resolution` → `video_params`；`resolve_video_params()` 校验后下发 `params.command`。
- **不做尺寸断言**：detail 由「录像组合 / 设置命令 / 尺寸来源」改为
  「录像参数 / 设置命令 / 尺寸断言: 无」。
- 报告名改为 `video[<key>]`（如 `video[4k-30-e0-h265-b8m-g30-v709]`）。
- 视频路径扫描由硬编码 `\.h265` 改为模块级 `_VIDEO_FILE_RE`（`\.(h265|h264)`，codec 可配）。
- 模块内仍不写参数循环（红线 2）。

### 5. 配置层

- `ATS/config/modules/video.yaml`：`video_resolution: "sd1080p_0"` → `video_params`
  （默认 `4k/30/0/h265/8000000/30/709`，任务单 §4.3 建议值）。
- **新增** `ATS/config/scenarios/video_matrix.yaml`：168 条 video task + 1 条末尾
  `video_integrity`（`all_unchecked` + `empty_input_policy: skip`；矩阵内 `ftp_download: false`，
  该 task 实际无输入会 SKIP）。每条 `duration: 10`、`ftp_download: false`；
  参数顺序固定 res → fps → eis → codec → bitrate → gop → vui。
- **新增** `scripts/gen_video_matrix.py`：从 `video_commands.py` 取值域生成场景文件，
  文件头写生成时间 / 取值域 / 组合数 / 重生成命令；支持 `--dry-run`。
- **删除** `ATS/config/scenarios/video_size_traverse.yaml`，原件归档至
  `docs/03_development/archive/video_size_traverse.yaml.archived`。

## Reason

固件 `cam_set video` 改为「所有参数显式写出」的新语法，旧的 13 个预置组合 ID 全部失效；
用户要求全排列遍历，且每条命令字段显式、顺序固定，便于日志比对与失败二分。
`busy` 若被判成功会造成参数错位、整批数据失真，因此必须在跑矩阵前落地。
