# recovery 冷启动语义变更：串口控制器首次上电改「先下电再上电」

## 问题描述

recovery 冷启动语义变更需求：串口控制器首次上电（`power_switch_init` 识别控制器后），
从「只发上电」改为「先下电 → 再上电」，使板子从**确定的下电状态**启动（而非可能是
上电残留态）。依据：`docs/05_handoff/next_step.md` 新增 P0 条目（Document Agent 定稿）。

## 修复内容

`ATS/core/scenario_manager.py` `_action_power_switch_init`：
- 识别控制器后的 `ps.power_on()`（只发上电）改为 `ps.reboot_checked(delay=reboot_delay)`
  （下电验合法帧 → 延时 reboot_delay → 上电严格验 ON）。
- 顶部 import 补 `PowerSwitchError`。
- 保留 required 的 fail-closed 语义：required（recovery=power_cycle）时 `reboot_checked`
  失败抛 `ScenarioError`；非 required 只 warn 继续，`ctx.power_switch` 仍设置。
- 探测阶段（`detect_power_switch` 发上电帧识别控制器）**不动**。

## 验证结果（离线）

- `compileall ATS/` 通过。
- 离线 mock：
  1. 识别控制器后调 `reboot_checked(delay=3.0)` 1 次，`power_on` 0 次（不再只发上电）。
  2. required 时 `reboot_checked` 抛 `PowerSwitchError` → `ScenarioError`（fail-closed）。
  3. 非 required 时失败 → warn 继续，`ctx.power_switch` 仍设置。
- `python3 -m unittest discover -s tests`：48 用例全过（新增 3 个冷启动语义测试）。

**待真机**：recovery_validation 冷启动（EVB 初始 OFF），确认 power_switch.log 显示
下电→延时→上电序列（非只上电），板子从确定下电状态启动、serial_init 正常等到 UART 枚举。

## 还会再有吗

- `reboot_checked` 的下电判据仍只要求「合法状态帧」（不强制 OFF，遵循 ADR-015 真机协议）；
  上电严格验 ON。
- 探测阶段（detect_power_switch）仍只发上电帧识别控制器（不涉及下电），保持其「识别身份」
  的单一职责不变。

## 经验沉淀

- 冷启动「先下电再上电」比「只发上电」更稳：前者把板子强制带到确定的下电基线再上电，
  避免上电命令撞上「板子本就是上电残留态」导致的状态不确定。
- 复用 `reboot_checked()`（已有严格回帧校验）而非重写一段「下电→延时→上电」逻辑，保持
  PowerSwitch 的上下电协议与回帧判据单一来源（ADR-011）。
- fail-closed 语义随能力必需性区分：recovery 必需时冷启动失败即中止；非必需时降级 warn
  不阻断（与 power_switch.enabled 可选能力的语义一致）。
