# TC-PS-001 节拍改为 15min×2 周期 + 长等待进度心跳

## 问题描述

用户需求：上下电压测从「上电 10s / 下电 10s × 30 周期」改为「上电 15min / 下电 15min × 2 周期」
（对称交替，总时长 1h，4 次状态切换）。属参数调整 + 长等待体验改进，Level 1，无需 ADR。

伴随问题：`run_stress` 里 `time.sleep(hold_on/off)` 改成 900s 后，15 分钟无任何输出，
易被误判卡死。`docs/04_testing/test_strategy.md` 明确「>10s 的 sleep 改成分段 sleep + 周期打印」。

## 修复内容（Level 1 参数 + 长等待体验，无需 ADR）

### 1. ATS/tools/power_switch_stress.py — 默认节拍

- `_DEFAULT_CYCLES`：30 → 2。
- `_DEFAULT_HOLD_ON`：10.0 → 900.0（15min）。
- `_DEFAULT_HOLD_OFF`：10.0 → 900.0（15min）。
- 文件顶部 docstring 节拍描述同步：10s→15min、30 周期→2 周期、10min→1h、60 次→4 次切换。

### 2. 长等待进度心跳（test_strategy 原则）

- 新增常量 `_HEARTBEAT_STEP = 60.0`（分段粒度，60s 打印一次，不刷屏）。
- 新增 `_sleep_with_heartbeat(duration, label, cycle, cycles)`：分段 sleep + 周期打印
  `[cycle 1/2] 保持上电 12/15 min` 心跳；分段 sleep 天然支持 KeyboardInterrupt 随时中断。
- `run_stress` 的两处 `time.sleep(hold_on/off)` 改调 `_sleep_with_heartbeat`。

### 3. 配置可选覆盖（保持现状）

脚本已支持 `power_switch.stress_cycles / stress_hold_on / stress_hold_off` 覆盖；默认值改好后
本次不改 system.yaml（跑默认即 15min×2）。协议字节仍只从 power_commands.py import，不新增配置项。

## 验证结果

- `py_compile` / `compileall ATS/` 通过。
- 默认节拍断言：2 周期 × 上电 900s / 下电 900s = 60 分钟。
- 心跳文案验证：900s 保持期按 60s 分段打印 `1/15 min` … `15/15 min`（共 15 次），
  且 `[cycle 1/2] 保持上电 15/15 min` 收尾正确。
- 端到端 mock（2 周期，缩短 hold=0.15s / 步长 0.05s）：上电硬判据 2/2、下电合法回帧 2/2、
  失败事件 0、退出码 0，心跳分段打印正常。

**待真机**：`python3 -m ATS.main --power-stress` 跑满 1h，4 次切换全回合法帧；
打印「预期总时长约 60 分钟」，保持期按 60s 打印进度心跳。

## 还会再有吗

分段心跳步长 `_HEARTBEAT_STEP=60s` 是模块内常量，真机若嫌刷屏可调大、若嫌间隔长可调小；
节拍走既有 `stress_*` 键，无需新增配置。Ctrl+C 中断在任意分段点生效，不会残留 15min 不可中断等待。

## 经验沉淀

- 长等待（分钟级）必须分段 sleep + 周期心跳，否则无人值守场景无法区分「正常运行」与「卡死」，
  且中断响应迟钝（单一 900s sleep 内 Ctrl+C 也要等满）。
- 节拍类参数收敛为模块级常量 + 既有配置键覆盖，默认值变更零配置、零协议改动。
