# 上传 HTTPS 自签名证书信任修复（SSLContext cafile）

## 问题描述

ATS Portal 切到 `https://10.1.64.183:8443` 后，运行结束的上报在「登记清单」阶段即失败，upload.log 报：

```
登记清单失败（重试 3 次）: HTTP -1: b''
```

实测（logs/stress/20261019/20261019_144923/upload.log）四文件 sha256 均算好、网络/token/文件清单全正常，死在第 1 步 TLS 握手。

## 根因分析

`ATS/application/portal_upload.py` 全程标准库 `urllib.request.urlopen()`，未加载/信任目标服务器自签名证书，依赖系统默认 CA 信任链 → `CERTIFICATE_VERIFY_FAILED: self signed certificate`（URLError 被 `_post_json_with_retry` 转成 status=-1、body 空 → 日志特征 `HTTP -1: b''`）。

不带 `SSL_CERT_FILE` 请求 `https://10.1.64.183:8443/api/health` 复现同样 URLError；`source ~/ats/env.sh`（设 `SSL_CERT_FILE=~/ats/cert.pem`）后 health 返回 200，印证根因。

## 修复内容（Level 1 模块内部 + 新增可选配置键，向后兼容）

### 1. ATS/application/portal_upload.py

- `import ssl`。
- 新增 `_DEFAULT_CERT_FILE = "~/ats/cert.pem"`（与 `ubuntu-upload-setup.sh` 生成路径对齐）。
- 新增 `_ssl_context(upload_cfg)`：证书来源优先级 `ATS_PORTAL_CA_CERT` 环境变量 →
  `upload.cert_file` 配置 → 默认 `~/ats/cert.pem`；`expanduser` 后 `isfile` 存在则
  `ssl.create_default_context(cafile=cert_file)`，否则回退 `ssl.create_default_context()`
  （系统默认信任链，保持向后兼容）。
- `_request()` 增加 `context=None` 形参，透传给 `urlopen(..., context=context)`（http:// 下
  urllib 忽略 context，行为不变）。
- `_post_json_with_retry`/`_put_file_with_retry`/`_finalize_with_retry` 增加 `context` 形参
  逐级透传；`upload_run()` 构造一次 `context` 后传给三步。对外 `upload_run` 签名不变。

### 2. ATS/config/system.yaml

`upload` 段新增环境级配置：

```yaml
cert_file: "~/ats/cert.pem"   # 自签名 HTTPS 证书（SSLContext cafile）；http:// 忽略。可被 ATS_PORTAL_CA_CERT 环境变量覆盖
```

### 3. tests/test_portal_upload.py

- `_mock_request` 的 fake 签名补 `context=None`（对齐 `_request` 新签名）。
- 新增 `test_ssl_context_uses_cert_file_when_present`（证书存在 → cafile 传入指定路径）、
  `test_ssl_context_falls_back_when_cert_missing`（证书缺失 → 不传 cafile、不抛异常）。

## 验证结果

- `python3 -m compileall ATS/application/portal_upload.py` 通过。
- `python3 -m unittest discover -s tests`：59 测试全过（新增 2 例）。
- 真机代码路径验证（不设 `SSL_CERT_FILE`，仅靠 `_ssl_context` 加载 `~/ats/cert.pem`）：
  `_request('GET', 'https://10.1.64.183:8443/api/health', ..., context=ctx)` → `200 {"status":"ok","version":"1.0.0"}`。

## 还会再有吗

- `cert_file` 为可选键：不配置时回退系统默认信任链（本机 `http://127.0.0.1:8080` 明文路径与
  既有无证书行为完全不受影响）。
- 证书轮换后需同步更新 `~/ats/cert.pem`（或 `cert_file` 指向的新文件）。
- 已 fix 尚未走完整三步上传真机归档（需 ATS Portal 在线时跑一次含 upload 的场景回归）。

## 经验沉淀

- `urlopen` 的 `context` 参数仅对 HTTPS 生效，对 http:// 透明，故可无条件透传、无需按
  scheme 分支——单一 `_ssl_context` 构造点即可覆盖明文/自签名两种部署。
- 自签名信任不该靠 `source env.sh` 手动前置，应沉淀为「配置驱动的 SSLContext 构造点」，
  让运行入口零手工依赖。
