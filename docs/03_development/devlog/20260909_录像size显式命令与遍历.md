# 录像 size 显式命令与遍历

日期：2026-09-09。范围：当前对话用户明确发布的录像 size 调整。

## 问题与依据

最新源码仍在 video.run 中发送 `cam_set video {resolution}`，缺少决定实际 size 的尾参数。
用户给出 12 行手测表，其中 480p 1 会报错刷屏，明确排除；其余 11 项作为可信映射。
当前源码/YAML 优先于历史 devlog。本次不执行其他会话的 FTP 解耦任务。

## 实施

新增 ATS/drivers/video_commands.py：不可变完整命令表、宽高/方向元数据、查询和禁用校验，
不负责 IO 或编排；video.py 查询命令而非拼接命令。video_resolution 选择完整组合 ID。
默认配置明确为 sd1080p_0，既有 3k 场景迁移为 3k_2；未提供尾参数的自定义配置报 ERROR，
不猜测旧 1080p 的模式。video_duration 支持有限正小数，不修改原默认 180 秒。

新增 video_size_traverse.yaml，使用既有 video task 和 Runner repeat/duration/loop；
按用户顺序覆盖全部 11 个组合，默认各一次、10 秒、一轮。没有新增 stress 专用模块或调度机制。
新增 24 个 unittest 测试方法；详细命令及输出见交付根目录的验证报告。

保留启动 f_index 兜底、最终完成标志、完整路径扫描、TT ERROR 标注和 FTP 辅助判据。
相关小调整：设置命令返回 Usage 则失败；异常/中断补发停止并摘除 listener；
下载本地名增加组合 ID 与板端目录前缀，避免 size 遍历时的同名文件复用。
没有改原始串口日志、FTP driver、H265 检测模块或 core 调度层。

## 验证

提取源码构建的隔离环境：回归先红后绿；24 项离线测试通过；新 Python 文件语法检查通过；
三份交付 YAML 解析通过。不是完整仓库全量测试，没有连接 EVB。
报告预期 size 来自用户手测，不冒充本次文件实测。

## 剩余限制

真机响应/真实视频宽高/FTP 大文件/长期循环尚未验收。异常停止是尽力清理，不能保证固件已恢复。
原有 FTP 下载不完整仍可能 PASS 的辅助判据保留；本次不把下载架构或检测架构扩入范围。
自定义录像场景需迁移裸档位；跳过某项应删除/注释 task，不使用 repeat: 0。
