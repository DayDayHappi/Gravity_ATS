# utest 细粒度判据实施：单文件 → 包迁移 + D1 叠加判据

## 1. 问题描述 / 需求

utest 判据从「仅 result 行」细化为「result 行 + per-case 业务关键串叠加校验」，
模块从单文件 `utest.py`（单模块内分派）拆为每 testcase 一个模块（8 个 `utest_<case>`）。

需求归档：`docs/03_development/archive/新增需求_utest细粒度判据.md`（§3 D1~D7 已人工拍板，
§8 Code Agent 交接请求，本记录为其六步实施）。

## 2. 根因分析

原 `utest.py` 单模块用 `override.testcase` 分派，判据只看 result 行，不看中间业务串。
需求要求每 case 独立模块 + 细粒度字符串检查，属 Level 3 架构变更（已由 Document Agent
出稿并获人工确认），Code Agent 按既定决策实施。

## 3. 修复内容（§8 六步）

### Step 1 — 协议迁到 `drivers/utest/` 包

删除 `drivers/utest_commands.py`，新建 `drivers/utest/`：
- `__init__.py`
- `_common.py`（原 utest_commands.py 整体迁入：命令 / result 行正则 / UTEST_TESTCASES
  超时表保留 qspi_test 映射并注「1 lane fail! 合法中间态」/ UnknownTestcaseError /
  script_timeout_for）
- 8 个 `*_commands.py`：各含 TESTCASE 名 + BUSINESS_RES 业务关键串正则（D7 严格/宽松）
  - efuse：2 条严格（回引 `val == expect`）
  - filesystem：3 条宽松（mount/write/read）
  - i2c：5 条严格（回引 want==readback / expect==got，尾 PASS）
  - imu：1 条严格（`collected n/n frames` 回引帧数完整）
  - pvt_auto：2 条宽松（PVT0/PVT1 monitor started）
  - pvt：3 条宽松（single voltage/temperature/convenience）
  - flash_xip_speed：SPEED_RE + MIN_SPEED_KBPS_KEY（阈值配置项，默认 0）
  - flash_read：BUSINESS_RES 空（D5，暂只 result 行）

### Step 2 — 模块迁到 `modules/utest/` 包

删除 `modules/utest.py`，新建 `modules/utest/`：
- `__init__.py`（import 8 case 模块触发 @register）
- `base.py`：`UtestCaseModule(TestModule)` 实现 D1 叠加判据模板（result 行优先 +
  business_res 补充 + `_extra_missing` 钩子）
- 8 个 case 模块：`@register("utest_<case>")`，testcase 名 + business_res 来自对应
  commands 文件

### Step 3 — 更新注册入口

`modules/__init__.py` 的 `from . import utest` 语义不变（utest 由 .py 变包后仍导入包），
注释标注「utest 为包」。

### Step 4 — 改 scenario

`config/scenarios/utest.yaml` tasks 从 8 个 `module: utest` + `override.testcase` 改为
8 个 `module: utest_<case>`（testcase 内置模块，`override.timeout` 单项覆盖能力保留）。

### Step 5 — 叠加判据语义（base.py 已实现）

result 行 FAILED/ERROR/SKIPPED → 对应状态（业务串不救回）；result 行 PASSED →
业务串齐全才 PASS，缺失/不符 → FAIL（detail 列缺失串）；无 result 行 → FAIL 兜底。

### 补充改动（需求文档未显式列出但实施必需）

- `core/config.py` `_MODULE_FILE_MAP` 补 8 个 `utest_<case>` → `utest` 映射
  （否则 `load_module_config` 找不到 `utest_<case>.yaml` 报 ConfigError）。
- `config/modules/utest.yaml` 补 `min_speed_kbs: 0`（D4 阈值配置项，默认不校验）。

## 4. 验证结果

- `python3 -m ATS.main --list-modules`：出现 8 个 `utest_*`，旧 `utest` 已移除。
- `python3 -m ATS.main --scenario utest --dry-run`：8 个 task 均识别，无 ERROR。
- mock 串口自测（res/utestlog.txt 样本）：8 个 case 全 PASS（result 行 + 业务串叠加）。
- 负向路径验证：
  - 业务串缺失（缺 flash_vendor）→ FAIL，detail 列缺失串。
  - result 行 FAILED 但业务串齐全 → FAIL（业务串不救回）。
  - 无 result 行 → FAIL。
  - flash_xip_speed 速率 500 < 阈值 1000 → FAIL；6826 >= 1000 → PASS；默认 0 不校验 → PASS。
- 无残留 import（旧 `utest_commands.py` / 旧 `utest.py` 已删）。

## 5. 还会再有吗

- 真机 `python3 -m ATS.main --scenario utest` 跑通待验证（离线 mock 已过）。
- `FAILED/ERROR/SKIPPED` 的 result 行确切格式只有 PASSED 有实测样例，其余状态格式待真机补充
  （沿用 `_common.py` 注释预留）。
- `qspi_test` 本期不恢复（D6），超时映射保留、commands 侧已注「1 lane fail! 合法中间态」。
- `flash_xip_speed` 的 `min_speed_kbs` 默认 0（不校验），真机如需阈值另配 override。

## 6. 经验沉淀

- 文件 → 包迁移时，相对导入层级随目录深度变化（`modules/utest/base.py` 访问 `ATS.core`
  需 `...core`，访问同层 `ATS.modules.base` 需 `..base`），迁移后第一时间跑 import 冒烟。
- 「每 case 一模块」用共享基类 + 子类只设常量（testcase / business_res）的方式，把
  叠加判据逻辑收敛到 base，8 个子类各 5 行，避免复制粘贴 8 份判据代码。
- config 层 `_MODULE_FILE_MAP` 是模块注册名 → 配置文件的映射，新增模块注册名时需同步
  补映射，否则 runner 阶段 `load_module_config` 才报错（非 import 期，易被漏测）。
