# video 加 FTP 下载开关，支持纯录像（仅录像不下载）

## 日期
2026-08-28

## 变更来源
Document Agent Request：`docs/03_development/archive/新增需求_testvideo仅录像不下载.md`（testvideo 分支，用户口述整理）。

## 问题描述
`video.py` 录像流程硬编码 FTP：开头 SKIP 依赖 FTP 客户端、录像前 `ensure_ftp` + `_list_video_dirs`、停止后大小校验 + 下载到本地。
testvideo 分支只做录像（`dfs_video_start` → 等时长 → `dfs_video_stop`），不需要任何 FTP，但旧代码会因 FTP 不可用而 SKIP、且停止后强制走 FTP 下载。

## 根因分析
FTP 逻辑与录像主体耦合在 `run()` 一条直线流程里，缺少「是否走 FTP」的开关，场景层无法旁路。

## 修复内容
模块红线：加参数接口，不硬删代码。`ensure_ftp` / `_list_video_dirs` / `_wait_new_dir` 方法保留不删，仅按开关旁路。

1. **`ATS/modules/video.py`**
   - 新增布尔参数 `video_ftp_download`（默认 true）。
   - `run()` 开头：`video_ftp_download=false` 时改走新方法 `_run_no_ftp()`，不再 `if ftp is None: return self._skip(...)`。
   - 新增 `_run_no_ftp(ctx, console)`：与 FTP 模式同款 `cam_set` 临时禁用（TODO-TEMP-DISABLE-CAM_SET）、`dfs_video_start` 判据 `Record Start|f_index=`、失败清理 `dfs_video_stop`、停止判据 `Video recording completed successfully.`，成功后直接 PASS，不做任何 FTP 操作。
   - docstring 更新为双流程说明（FTP 下载模式 / 纯录像模式）。
2. **`ATS/config/modules/video.yaml`**
   - 新增 `video_ftp_download: true`（默认保持 normal/stress 等既有场景行为不变）。
3. **`ATS/config/scenarios/stress_traverse_photo_mode.yaml`**
   - `prepare` 移除 `ftp_ready`（场景完全不依赖 FTP）。
   - `preview.enabled` 改 `false`（无 RTMP 流可看）。
   - video task 加 `override.video_ftp_download: false`。
   - 顶部注释改写为纯录像场景说明（文件名/name 仍沿用 stress_traverse_photo_mode，后续可重命名为 testvideo.yaml）。

## 如何验证
1. `python3 -m py_compile ATS/modules/video.py` → PASS。
2. `yaml.safe_load` 解析 scenario/video.yaml → PASS（prepare 4 项、override 生效、video_ftp_download 默认 true）。
3. `from ATS.modules import video` 确认 `_run_no_ftp` 存在 → PASS。
4. 待真机冒烟：`python3 -m ATS.main --scenario stress_traverse_photo_mode --no-interactive-wifi`，日志应无 ensure_ftp / FTP 下载 / ftp_server，停止后 PASS。

- 纯录像路径与 FTP 路径的 `cam_set` 临时禁用（TODO-TEMP-DISABLE-CAM_SET）仍需后续恢复（与既有 devlog 20260827_0739 同源）。
- 场景文件名/name 仍为 stress_traverse_photo_mode，后续独立命名待定。

## 经验沉淀
模块红线「加参数接口不硬删」的标准做法：默认值保持历史行为 + 场景层 override 旁路，比在场景层写 if/else 更干净，也避免破坏既有场景。
