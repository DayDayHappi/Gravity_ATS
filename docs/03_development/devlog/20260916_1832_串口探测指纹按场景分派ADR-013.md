# 20260916_1832_串口探测指纹按场景分派ADR-013

## 问题描述

utest 自检固件的 msh 提示符形态是 `msh >`（无斜杠），旧固件是 `msh />`（带斜杠）。现有 `serial_console.py` 指纹正则第三条（`msh\s+/[^>]*>|msh\s*/>`）与就绪正则（`_READY_RE`）都要求 `msh` 后出现 `/`，无法匹配 `msh >`，导致 utest 场景自动探测失败、`wait_for_ready()` 超时。

## 根因分析

探测指纹与就绪正则是两处独立正则，均以旧固件日志归纳，未覆盖新固件的 `msh >` 形态。不能全局放宽正则（会改变旧固件探测语义、破坏向后兼容），需按场景分派。

## 修复内容（ADR-013）

- `ATS/core/serial_console.py`：
  - 新增 `_FINGERPRINT_SETS`（default=原三条逐字不动；utest=原三条 + `msh\s+[^>]*>`）与 `_READY_RE_SETS`（default=原正则；utest=认 `msh\s+[^>]*>`）映射，及 `_FINGERPRINT_SET_RE` 预编译。
  - `_probe_port_baud(..., fingerprint_set="default")` 按指纹集编译正则探测。
  - `detect_port(..., fingerprint_set="default")` 透传指纹集。
  - `SerialConsole.__init__(..., ready_set="default")` 存 `self._ready_re`；`wait_for_ready` 改用 `self._ready_re`。
  - 旧调用方不传参 → default，行为逐字一致。
- `ATS/core/scenario.py`：`Scenario` dataclass 加 `serial_fingerprint: str = "default"`。
- `ATS/core/scenario_manager.py`：
  - `_parse_scenario` 解析 `sc.get("serial_fingerprint", "default")`。
  - `run` 透传 `ctx.serial_fingerprint = scenario.serial_fingerprint`。
  - `_action_serial_init` 给 `detect_port`/`SerialConsole` 传 `fingerprint_set`/`ready_set`。
- `ATS/config/scenarios/utest.yaml`：加一行 `serial_fingerprint: utest`。

（ADR-012 utest 模块/场景落地已在上一 devlog `20260916_1720` 完成，本次仅 ADR-013 增量。）

## 验证结果

- `py_compile` 通过；`--scenario utest --dry-run` 通过。
- 指纹集分派单测：
  - default 不认 `msh >`（False）、认 `msh />`（True）、认 `JX009`（True）。
  - utest 认 `msh >` / `msh />` / `msh /emmc>`（均 True）。
  - `_READY_RE_SETS`：default 不认 `msh >`，utest 认。
  - `SerialConsole(ready_set=)` 默认与 utest 两种构造行为正确。
- 场景透传：utest 场景解析 `serial_fingerprint=utest`；normal/no_network 未声明 → `default`（零影响）。

## 还会再有吗

- 待真机确认：utest 固件 `health_check()` 的 `echo "EVBTEST_HELLO"`（带引号语法）是否支持；utest 冷启动是否打印 `JX009`/`GravityXR.cn` banner（不打印则 `msh >` 是唯一命中途径，方案已覆盖）。
- 未来新增固件变体：仅需在 `_FINGERPRINT_SETS`/`_READY_RE_SETS` 加一套 + 场景声明选择键，不改核心编排逻辑。

## 经验沉淀

- 指纹（探测）与就绪（wait_for_ready）是两处独立正则，固件提示符形态变化时必须同步改，单改一处仍会卡在另一处。
- 用「场景声明选择键 + 代码内映射」而非「场景名硬编码」或「全局放宽正则」，既隔离了固件变体，又保持 default 路径逐字向后兼容。
