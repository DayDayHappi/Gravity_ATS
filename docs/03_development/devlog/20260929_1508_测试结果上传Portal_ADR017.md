# 测试结果上传 ATS Portal 实施（ADR-017）

## 问题描述

ADR-017（Document Agent 定稿）：运行结束后，把本次运行结果（4 个 log + result.json）通过
HTTP 三步协议上传 ATS Portal（本机 127.0.0.1:8080），使网站展示用例 PASS/FAIL、提供日志
阅读下载。属 Level 3 系统边界变更（新增结果上报流），但 ADR 已定稿，本请求即其实施。

## 修复内容

### 1. 新建 ATS/application/portal_upload.py（协议唯一来源）

封装三步协议（标准库 urllib，无第三方依赖）：
- `upload_run()`：登记清单（POST /api/v1/runs）→ 逐个 PUT 文件 → finalize（POST）→ 检查
  `upload_state == "complete"`。
- token 读取优先级：`ATS_PORTAL_TOKEN` → `ATS_PORTAL_TOKEN_FILE` → `token_file` 配置 →
  默认 `~/.config/ats-portal/token`（不写日志、不进仓库）。
- `_sha256_size()`：流式计算 sha256（64 hex）+ 字节数。
- 重试：临时错误（网络超时/408/429/5xx）有限退避重试（3 次，1s/2s），复用同一 run_id 与清单；
  非临时错误（400/401/403/404/409/413/422）不盲目重试。
- 懒加载缺失文件跳过（power_switch.log/recovery.log 不存在时只登记实际存在的文件）。
- 文件名 URL 编码 `urllib.parse.quote(name, safe="")`（TC-UP-006）。
- 协议常量（路径/头/字段名）集中在本模块，业务不内联 URL/头（ADR-011 精神）。

### 2. config/system.yaml 增 upload 段

`enabled: false`（默认关零影响）、`server`、`token_file`、`timeout: 60`、`artifacts`（4 log + result.json kind=report）。

### 3. main.py 收尾接线

- 记录 `started_at`（init_logger 后，ISO 8601 带时区）。
- `gen_report` + `_record_test_problem` + `logger.close()` **之后**调用 `upload_run`（协议 §2
  先落盘再算摘要）。
- `execution_state`：`env_error or manager.scenario_aborted` → aborted，否则 completed。
- 上传失败只 `logger.warn`，不改写测试结论、不影响退出码（红线）。

### 4. 配合改动（最小）

- `core/runner.py` / `core/scenario_manager.py`：新增 `scenario_aborted` 标记，供 main 正确设
  `execution_state=aborted`（ScenarioAbort 中止时）。

## 验证结果（离线 mock）

- `compileall ATS/` 通过；system.yaml upload 段加载（默认 enabled=false，artifacts 5 项）。
- 离线 mock 三步协议：只登记存在的 2 个文件（serial/power_switch/recovery 缺失跳过）、
  run_id `ats-`+uuid、mode.id=scenario.name、sha256 64hex、PUT 2 次 + finalize 1 次、
  finalize 返回 upload_state=complete → upload_run True。
- token 缺失 → PortalUploadError（fail 但不影响测试结论）。
- 文件名 URL 编码 `a# b中文.log` → `a%23%20b%E4%B8%AD%E6%96%87.log`。
- `python3 -m unittest discover -s tests`：41 用例全过（新增 test_portal_upload.py 4 用例）。

**待真机**（TC-UP-001~006）：关闭回归零网络请求；含 report 归档展示 PASS/FAIL；上传失败不影响
退出码；懒加载缺失跳过；中文/空格/# 文件名 PUT 成功。

## 还会再有吗

- token 读取依赖 `~/.config/ats-portal/token`（网站安装创建）或环境变量，真机需先配置。
- `source` 字段初版留空 `{}`，未来多机器环境再填 host/device（ADR §5）。
- 上传 `enabled=false` 时零行为（不 import portal_upload、不发网络请求），向后兼容所有场景。

## 经验沉淀

- 协议文档（ATS-Portal-Upload-Protocol-v1）是「现有接收协议」，实现端只需遵守清单/校验/
  Bearer/finalize 顺序即可，无需改后端。
- 上传是「运行结束后独立数据流」，挂接点在 logger.close() 之后（文件落盘再算摘要），且
  失败语义与测试结论解耦（只 warn 不改退出码）——上报能力不得反噬测试可靠性。
- 重试只对「临时错误」退避（复用 run_id+清单），对 4xx/422 等确定错误不盲目重试（协议 §9.2
  规则 6 与状态码表）。
- 懒加载文件（power_switch.log/recovery.log）的「缺失跳过」是对既有日志懒加载语义的自然延续。
