# 修复记录：连续运行 emmc 模块报错（状态残留）

**时间**: 2026-08-12 23:02
**修复类型**: Bug 修复
**影响模块**: `modules/emmc.py`、`main.py`
**严重程度**: 中（连续运行第二次起必现，需重启板子才能恢复）

---

## 一、问题描述

板子第一次上电运行 `python3 -m ATS.main --skip rtmp` 正常通过。但**不重启板子**再次运行时，`emmc` 模块报错：

```
[FAIL] emmc (0ms) - 无法进入 /emmc 目录
```

且 PASS/FAIL **交替出现**（一次过一次不过），规律明显。

## 二、根因分析

两个问题叠加：

### 2.1 目录残留（主因）

第一次运行时 `cd emmc`（相对路径）进入 `/emmc` 目录后**没退出**。第二次运行时板子当前目录还在 `/emmc`（提示符 `msh /emmc>`），再发 `cd emmc`，msh 尝试进入 `/emmc/emmc`，该目录不存在，命令失败。

证据（失败时的串口提示符）：
```
msh /emmc>echo "__EVBTEST_END_xxx__"
```
提示符是 `msh /emmc>`，说明当前在 `/emmc` 目录。

### 2.2 FTP 崩溃循环刷屏（次因）

上次测试残留导致 FTP 服务在崩溃循环（`[W/ftp] service go wrong` 反复刷屏），海量错误日志把 `cd emmc` 的命令回显和响应淹没，哨兵匹配不到，0ms 直接判失败。

### 2.3 为什么交替出现

PASS 那次：板子状态恰好没残留（或 FTP 没刷屏干扰），`cd emmc` 勉强成功。
FAIL 那次：目录残留 + FTP 刷屏叠加，必失败。

## 三、修复内容

### 3.1 `modules/emmc.py`：cd 改绝对路径

```diff
-        # 默认路径：cd emmc 验证可进入
-        r = console.exec_sync("cd emmc", timeout=10.0)
+        # 默认路径：cd /emmc 验证可进入（用绝对路径，避免上次运行残留当前目录导致 cd emmc 失败）
+        r = console.exec_sync("cd /emmc", timeout=10.0)
```

**作用**：绝对路径 `/emmc` 不管当前在哪个目录都能正确进入，彻底消除目录残留问题。附带收益：耗时从 ~2000ms 降到 ~150ms（绝对路径不依赖当前目录解析，更快）。

### 3.2 `main.py`：预清理加 `cd /` 回根目录

```diff
     # 6. 板子状态预清理（确保干净起点：回根目录、停录像、断WiFi、恢复FTP服务）
+    #    上次运行可能残留：当前目录在 /emmc、录像进行中、FTP 崩溃循环刷屏
     logger.info("预清理板子状态...")
     try:
-        console.exec_sync("dfs_video_stop", timeout=8.0)   # 停可能进行中的录像
-        console.exec_sync("wifi disc", timeout=8.0)        # 断开 WiFi
-        # 若 FTP 服务在崩溃循环，重发 ftp_server 恢复（不启动新的，只是触发恢复）
-        console.exec_sync("ftp_server", timeout=8.0)
+        console.exec_sync("cd /", timeout=5.0)             # 回根目录，避免 cd emmc 残留
+        console.exec_async("dfs_video_stop",               # 停录像（未在录则忽略）
+                           expect=r"Save Video|Please start|recording completed",
+                           result_timeout=8.0)
+        console.exec_sync("wifi disc", timeout=8.0)        # 断开 WiFi
+        # 恢复 FTP 服务（若在崩溃循环，重发 ftp_server 触发恢复）
+        console.exec_sync("ftp_server", expect=r"init success|service launched", timeout=8.0)
+        time.sleep(1.0)                                     # 等服务稳定，避免日志刷屏干扰后续命令
```

**作用**：
- `cd /` 回根目录：每次测试起点一致，避免目录残留
- `dfs_video_stop` 改 `exec_async` + 正向 expect：容错（未在录像时返回 `Please start recording`，不再判失败）
- `ftp_server` 加 expect + `sleep 1.0`：恢复 FTP 后等服务稳定，避免崩溃日志刷屏干扰后续命令
- 顶部补 `import time`

## 五、还会再有吗

**不会**。绝对路径 `cd /emmc` 彻底消除了目录残留依赖；预清理的 `cd /` 保证每次起点一致。已连续两次验证稳定。

## 六、经验沉淀

1. **shell 命令尽量用绝对路径**：相对路径依赖当前目录状态，有状态残留风险
2. **状态残留类 bug 看"交替出现"规律**：PASS/FAIL 交替通常是上一次运行改变了环境状态
3. **预清理要彻底**：不只清理资源（录像/WiFi/FTP），还要清理 shell 状态（当前目录）
