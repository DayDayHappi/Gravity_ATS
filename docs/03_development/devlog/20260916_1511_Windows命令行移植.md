# Windows命令行移植实施记录

日期：2026-09-16。基于 all_source(8).txt（166文件），按用户批准方案实施。

## 问题与原因

Windows自动端口枚举不能沿用/dev/ttyUSB*；termios在导入时就阻碍原生终端；Linux工具/Bash包装不能原样执行。
--config-dir原先只影响部分加载点，导致模块与prepare可能读取另一目录；setup时尚未看到运行覆盖参数。
异常路径存在半初始化FTP连接未关闭、模块teardown遗漏、结果丢失和工具中断回收不足。

## 修复内容

- 新增ATS/platform，集中端口、键盘、工具、进程适配。串口协议层和板端命令保持原样。
- config-dir由Context和Runner参数贯穿所有本轮加载点；模块覆盖在setup前合并。
- 新增--list-ports、--no-preview、--no-problem-prompt、--input-dir。
- PreviewManager改为Python监督直接ffplay，保留Scenario生命周期；取消额外Linux终端模拟器。
- H265 stderr直接文件落盘并逐行解析，避免读线程/PIPE回收竞态；三阶段argv与算法未改变。
- Runner/Manager/main保留部分报告和130中断退出；FTP半初始化连接关闭；板端停止未确认明确警告。
- 在额外回归中发现并修复POSIX select+文本缓冲粘贴阻塞：改os.read+增量解码，真实PTY测试覆盖。
- 新增独立CLI依赖、两个不修改正式策略的smoke场景、84项测试、ADR-012与部署验收文档。

关键调用变化：

```diff
- load_module_config(task.module)
+ load_module_config(task.module, self.config_dir)

  module = cls(config)
+ module.config = module._merge(params)
  module.setup(ctx, console)
```

## 验证结果

Debian 13 / Python 3.13.5：84项新增ATS测试通过。真实FFmpeg 7.1.5正常/损坏H265的完整CLI分别返回0/1。
安装器另有10项测试（含冲突拒绝和异常回滚）。源码与不变范围审计及干净基线安装证据附于交付包。
Windows分支使用模拟边界；没有Windows运行环境和EVB，pySerial安装也因网络不可达未完成。
不能写成Windows真机或Ubuntu真机验收通过。详见 ../../04_testing/windows_cli_acceptance.md。

## 剩余风险

Windows工具构建、COM驱动2Mbps、主动FTP回连、防火墙、nginx-rtmp及桌面预览必须现场验收。
保留原始H265算法与FTP辅助验证判据，不顺带声称历史缺陷已解决。
本轮修改包不得和旧UI分支热修复包混装；增量安装器基线冲突时停止而不是强制覆盖。

## 经验

将主机差异与固件协议分开；配置入口必须贯穿到实际资源创建；验证工具要真实执行，不只判断文件存在。
资源回收用拥有的Popen/socket句柄，不按进程名杀；中断不是PASS，且清理尝试不等于板端确认。
