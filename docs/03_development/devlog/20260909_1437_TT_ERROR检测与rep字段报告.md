# 录像/推流过程检测 TT ERROR 并在报告标注 cycle/rep 与命中

## 日期
2026-09-09

## 变更来源
Code Agent Request：在 video/rtmp 过程中检测固件关键错误串 `TT ERROR`，命中**不判 FAIL**，仅在最终报告标注「第几轮（cycle）第几次（rep）」及「第几次命中」。用户已拍板：不判 FAIL、严格匹配 `TT ERROR`（含空格大写无引号）、video 和 rtmp 都要、一次可命中多次。

## 做了什么

### 1. TestResult 新增 rep 字段
- `ATS/core/result.py`：`TestResult` 新增 `rep: int = 0`（1-based repeat 序号；无 repeat 为 1，默认 0 表示未填）。带默认值，向后兼容。

### 2. runner 传递 rep
- `ATS/core/runner.py`：`_run_module` 的 `rep_index` 一路传到 `_record_results` → `_record`；`_record` 在 `rep_index >= 0` 且 `r.rep` 为空时填 `r.rep = rep_index + 1`。`result` 为 list（photo 多结果）时每条都填同一 rep。setup 异常分支也传 rep_index。

### 3. 新增 TT ERROR 检测器（listener 模式）
- 新建 `ATS/modules/tt_error_monitor.py`：`TTErrorMonitor` 订阅串口原始数据，严格匹配 `TT ERROR`（含空格大写无引号），收集命中文本（去 ANSI）。
- **跨 chunk 拼接**（超出 Request 建议，已实现）：串口读线程可能把一行日志分块送达，`TT ERROR` 仅 8 字节易被切断。仅当 chunk 结尾是 `TT ERROR` 的截断前缀（`TT`/`TT ` /`TT E`/`TT ER`/`TT ERR`/`TT ERRO`）时保留前缀拼接，避免污染后续命中行；支持同 chunk 内多次命中。

### 4. video 挂监听
- `ATS/modules/video.py`：新增 `__init__`（存 `_console`/`_tt_monitor`/`_tt_monitor_cb`）；在 `dfs_video_start` 之前 `add_listener`；所有返回路径统一走 `_mk`，`_mk` 内先摘除 listener 再经 `_attach_tt_hits` 追加命中信息；新增 `teardown` 兜底移除。命中不改变 PASS/FAIL 判定。

### 5. rtmp 挂监听
- `ATS/modules/rtmp.py`：`__init__` 增加 `_tt_monitor`/`_tt_monitor_cb`；`rtmp_video_start` 前 `add_listener`；`rtmp_video_stop` 后摘除；最终结果经 `_attach_tt_hits` 追加命中；`teardown` 兜底移除。

### 6. 报告展示 cycle/rep/命中
- `ATS/core/reporter.py`：`_result_to_dict` 加 `"rep": r.rep`；HTML 表头加「轮次/次数」列，行展示 `C{cycle}/R{rep}`（jinja2 与非 jinja2 退化路径都改）。

## 命中信息格式

```
TT ERROR 命中 N 次：
第1次: <命中行>
第2次: <命中行>
...
```

## 已知遗留（Known Limitation）
- 跨 chunk 拼接仅覆盖 `TT ERROR` 被**单次**分块切断的情形；若一次分块恰好只含 `TT ` 而 `ERROR` 落在更后 chunk、中间夹杂其他日志行，可能拼接出跨行假命中（当前按行提取已缓解）。真机如遇漏检/误检再评估，本实现先按 chunk + 截断前缀拼接。
- 真机未跑（本条记录时）；报告 HTML/JSON 的 cycle/rep 列 + 命中详情待真机确认。
