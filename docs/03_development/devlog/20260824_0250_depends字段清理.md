# depends 字段清理（ADR-009 方向 A）

## 日期
2026-08-24

## 变更来源
ADR-009「depends 字段语义定位」已 Accepted（方向 A），`docs/05_handoff/next_step.md` P0-1 给出源码改动清单。

## 做了什么
清空 6 个模块的 `depends` 为 `[]`（ADR-008 实施后这些依赖目标已退出 task 流，成为死字段）：

| 模块 | 改动前 | 改动后 |
|------|--------|--------|
| photo | `depends = ["ftp"]` | `[]` |
| video | `depends = ["ftp"]` | `[]` |
| rtmp | `depends = ["wifi_join"]` | `[]` |
| ftp | `depends = ["wifi_join"]` | `[]` |
| wifi_scan | `depends = ["wifi_check"]` | `[]` |
| wifi_join | `depends = ["wifi_scan"]` | `[]` |

`emmc`、`wifi_check` 本就为 `[]`，无需改动。

`depends` 字段从此只表达「运行时 task 间 fail-fast」（当前三场景均无此用法，字段保留但空）；
逻辑依赖（photo/video 需 FTP 就绪、rtmp/ftp 需 WiFi 就绪）已由 Scenario prepare 编排 + `module_design.md` 表达。

## 改了哪些文件
- `ATS/modules/photo.py`
- `ATS/modules/video.py`
- `ATS/modules/rtmp.py`
- `ATS/modules/ftp.py`
- `ATS/modules/wifi.py`（wifi_scan、wifi_join 两处）

## 如何验证
1. `grep -n depends` 确认所有模块 `depends = []`（无残留非空）→ PASS。
2. 8 个模块仍注册正常（emmc/photo/video/rtmp/ftp/wifi_check/wifi_scan/wifi_join）→ PASS。
3. 三场景解析正常（normal/stress/aging）→ PASS。
