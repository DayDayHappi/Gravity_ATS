# 20260916_1720_新增utest固件自检框架接入

## 问题描述

需求：接入 EVB 固件 `utest` 统一日志框架（9 个板级检测项），作为独立板级自检通道，不与 WiFi/FTP/音视频链路混排。

## 根因分析

ADR-012 已定稿设计：独立模块 `utest` + 独立场景，唯一判据取 testcase 级 result 行，显式传 expect 避开 serial_console 默认 `_ERROR_RE`（防止 `qspi_test` 的 `1 lane fail!` 合法中间态被误判）。

## 修复内容

新增 4 个文件 + 1 处接线，现有代码零改动：

- `ATS/drivers/utest_commands.py`：协议唯一来源（ADR-011）——`UTEST_LIST_COMMAND`（预留）、`UTEST_RUN_COMMAND`、`UTEST_RESULT_RE`（白名单 status 捕获）、`UTEST_RESULT_ANY_RE`（宽松兜底）、`UTEST_TESTCASES` 超时表（9 项：1s 组→10s、10s 组→20s、30s 组→40s）、`script_timeout_for()` 查表。
- `ATS/modules/utest.py`：`@register("utest")`，一次动作 = 跑一个 testcase；result 行 status → 脚本状态（PASSED→PASS / FAILED→FAIL / ERROR→ERROR / SKIPPED→SKIP）；未知 status 词（如 PANIC）走 `_error` 兜底；无 result 行走 `_fail`。不写 for、不感知场景。
- `ATS/config/modules/utest.yaml`：模块能力参数（空，协议全在 commands）。
- `ATS/config/scenarios/utest.yaml`：独立场景，prepare 仅 `serial_init` + `preclean`，9 项 task 逐项声明 `override.testcase`。
- `ATS/modules/__init__.py`：追加 `from . import utest` 触发注册。

## 验证结果

- py_compile 通过；`--scenario utest --dry-run` 通过。
- 模块注册成功（`get_module_cls("utest")` 非 None）。
- 场景加载成功：9 项 testcase 与 ADR-012 表一致，prepare/cleanup 正确。
- 用实测 `res/utestlog.txt` 的 result 行验证正则匹配 PASSED / name；`1 lane fail!` 不命中 result 正则；`1 tests.` 汇总行不命中 ANY_RE。
- 状态映射单测：PASSED/FAILED/ERROR/SKIPPED/未知 PANIC/无 result 行 六种分支全部符合预期。
- 报告命名 `utest[<testcase>]`，9 项不重名。

## 还会再有吗

- 后续新增检测项：仅需在 `UTEST_TESTCASES` 加一行 + scenario 增一行 task，不改逻辑。
- FAILED/ERROR/SKIPPED 的 result 行确切格式待真机补充（当前按白名单推断，未知状态已兜底为 ERROR）。
- 全部未真机验证。

## 经验沉淀

- 显式传 expect（而非依赖 `_ERROR_RE`）是规避「合法中间态含 fail 关键字」的正确方式。
- result 行 status 用白名单正则捕获 + 宽松正则兜底，可在「无样本」时仍给出确定性结果（未知→ERROR，不猜测）。
