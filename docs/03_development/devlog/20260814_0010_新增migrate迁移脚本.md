# 新增 migrate.sh 环境迁移脚本 + 迁移指南

**日期**: 2026-08-14
**改动范围**: `migrate.sh`(新增) + `迁移指南.md`(新增)

## 1. 问题描述

项目要从一台 Ubuntu PC 迁移到另一台。手动逐项准备环境（Python 依赖、串口权限、防火墙、内置工具校验、dry-run）容易漏项、且每次换机器都要重走一遍。

需要一个脚本在新机器上自动完成「检查+装依赖+校验」，把需要人工 sudo 的步骤收集起来提示执行，并配一份说明文档。

## 2. 修复内容

### 2.1 `migrate.sh`

新机器首次运行前执行的一键迁移脚本，8 项检查：

| 步骤 | 内容 | 失败处理 |
|------|------|---------|
| 1/8 | Python 版本 ≥3.7 | 报失败 |
| 2/8 | 装/查 `pyserial` `pyyaml`（pip --user） | PEP 668 限制时提示 venv / `--break-system-packages` |
| 3/8 | 内置二进制 `ffmpeg`/`ffprobe`/`mediamtx`（含执行权限，自动 chmod 修复） | 缺失提示 |
| 4/8 | dialout 组（串口权限） | 收集 `sudo usermod` |
| 5/8 | `/dev/ttyUSB*` 存在+可读写 | 收集 `sudo chmod` |
| 6/8 | 防火墙（ufw） | 收集 `sudo ufw allow 1024:65535/tcp` |
| 7/8 | `--dry-run` 校验配置+依赖 | 打印 dry-run 错误 |
| 8/8 | `--list-modules` 确认模块加载 | 打印日志 |

**设计要点**：
- **不替你 sudo**：串口权限/防火墙需交互密码，收集命令末尾统一打印让你手动执行（安全可控）
- **幂等**：可重复跑，已装好的跳过
- **不依赖 cwd**：`BASH_SOURCE` 定位项目根，任意目录调用都对
- **PEP 668 兼容**：新版 Ubuntu（23.04+）pip 受限时给出 venv / `--break-system-packages` 两条出路
- 退出码：0 全过 / 1 有注意项 / 2 有致命项（可脚本化判断 `./migrate.sh && ...`）

### 2.2 `迁移指南.md`

`migrate.sh` 使用说明 + 完整迁移流程 + 常见问题排查（5 个 Q&A）：
- Q1 pip 报 externally-managed → venv / --break-system-packages
- Q2 未发现 /dev/ttyUSB* → 板子没连/驱动
- Q3 不想加 dialout 组 → 临时 chmod 666
- Q4 RTMP 失败但核心通路过 → pc_ip 探错网卡，写死配置
- Q5 内置二进制无执行权限 → chmod +x

## 3. 验证结果

本机实测 `./migrate.sh`：
- 8 项检查全跑通
- 准确报告本机状态：6 通过 / 2 注意（dialout 组、串口没插）
- sudo 命令正确收集打印
- 退出码 1（基本就绪+注意项）符合预期
- `bash -n` 语法检查通过

## 4. 还会再有吗

- **平台限制**：仅 Linux/macOS（串口终端模式用 termios/tty，但 migrate.sh 本身不依赖此，跨平台可用；只是 Windows 跑测试不行）
- **架构绑定**：内置 ffmpeg/mediamtx 是 x86_64，换 ARM/macOS 需重新下对应架构包（migrate.sh 第 3 步会报缺失）
- **sudo 仍需手动**：脚本不替你执行，是设计取舍（安全），换机器时记得看末尾提示

## 5. 经验沉淀

- **迁移脚本只检测少改动**：除装 pip 包外不改系统状态，可放心跑。sudo 步骤交给用户，避免脚本持有 root 权限的安全风险。
- **PEP 668 是新 Ubuntu 的常见坑**：23.04+ 默认禁止系统级 pip install，迁移脚本必须给出 venv 退路，否则用户卡在依赖装不上。见 [[pc-firewall-allows-highports]] 同类环境适配。
