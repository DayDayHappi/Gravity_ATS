# ffplay 画面确认改用独立终端窗口播放

**日期**: 2026-08-17
**改动范围**: `modules/rtmp.py`（新增 `_find_terminal`/`_launch_ffplay_terminal`/`_launch_ffplay_direct`，run/teardown 调整）

---

## 一、问题描述

用户希望 rtmp 推流命令发出后，脚本**自动开一个独立终端窗口**，在窗口里用 ffplay 播放画面。此前 ffplay 用 `subprocess.Popen` 直启（无独立终端窗口），窗口生命周期太短（约 8s 即被 teardown killpg），且大分辨率首帧解码慢时来不及出画面，用户看不到。

## 二、根因分析

1. **ffplay 直启无独立窗口**：`subprocess.Popen` 直启 ffplay，其 SDL 画面窗口小、且随脚本 teardown 快速关闭，用户几乎看不到。
2. **生命周期受脚本约束**：ffplay 由脚本 `_ffplay_proc` 管理，teardown 里 `killpg` 强制杀掉，展示时间极短。
3. **`-rw_timeout 3s` 太短**：板子推 1080p（1296×2304）编码慢、关键帧稀疏，ffplay 3 秒等不到关键帧就退出（此前记录过"ffplay 要等 15s 左右才有画面"）。

## 三、修复内容

`modules/rtmp.py`：

1. 新增 `_TERMINAL_CANDIDATES`（gnome-terminal/xterm/konsole/xfce4-terminal/terminator/mate-terminal/lxterminal）与 `_find_terminal()`：自动检测可用的终端模拟器。
2. 新增 `_launch_ffplay_terminal(url, terminal)`：用终端模拟器开新窗口，窗口内执行 `bash -c 'echo 提示; ffplay -x 480 -y 360 <url>; echo 已退出; read'`。ffplay **去掉 `-rw_timeout`**（耐心等关键帧，慢流/大分辨率首帧慢也能等到），流断开后 ffplay 自动退出，`read` 等回车关闭窗口。窗口生命周期独立于脚本。
3. 新增 `_launch_ffplay_direct(url)`：回退方式（无终端模拟器时），保留原 subprocess 直启 + stderr 落日志 + `-rw_timeout 3s`。
4. `__init__` 新增 `_ffplay_in_terminal`/`_ffplay_active` 标志。
5. `run()`：发完 `rtmp_video_start` 后，优先用终端窗口启动 ffplay（有 DISPLAY + 终端模拟器），否则回退直启，无 DISPLAY 跳过。
6. `teardown()`：仅 subprocess 直启方式才 `killpg`；终端窗口方式不杀（窗口独立，用户自己关）。

## 四、验证结果

- `ast.parse` 语法 OK；`gnome-terminal --version` 确认 3.36.2，支持 `[-- COMMAND …]` 语法。
- **待真机验证**：跑 `python3 -m ATS.main --no-interactive-wifi`，rtmp 阶段应弹出一个独立终端窗口，窗口内 ffplay 播放画面；流停止后 ffplay 退出、窗口显示"按回车关闭"。

## 五、还会再有吗（残留风险）

1. **依赖终端模拟器**：系统无 gnome-terminal/xterm 等时会回退 subprocess 直启（旧行为），或跳过（无 DISPLAY）。当前机器已确认有 gnome-terminal。
2. **ffplay 窗口不再由脚本清理**：终端窗口方式下脚本不管 ffplay 退出，测试结束后窗口保留（等用户回车或手动关）。这是预期行为，但无人值守时窗口会残留，需注意。
3. **ffplay 无 -rw_timeout 可能卡住**：终端方式下去掉 `-rw_timeout`，若推流始终未上线，ffplay 会一直 `nan` 等待（窗口卡住但可手动关）。可接受，因为判据靠 ffprobe，ffplay 仅辅助。

## 六、经验沉淀

1. **"画面确认"应给独立、长生命周期的窗口**：ffplay 这类给人眼看的辅助工具，若由脚本 subprocess 直启并随 teardown 秒关，等于白起。用终端模拟器开独立窗口、让窗口自行管理生命周期，用户才能真正看到画面。判据交给机器可读的 ffprobe，画面确认交给独立窗口，各司其职。
2. **大分辨率慢流的 ffplay 别设短读超时**：`-rw_timeout` 短会让 ffplay 等不到稀疏的关键帧就退出，与"耐心等画面"的目标冲突。终端窗口方式下可去掉该参数，让 ffplay 自行等待；判据不受影响。见 [[rtmp-ffmpeg-bundled]]、[[20260817_0203_RTMP探测失败_板子编码慢关键帧稀疏加大超时]]。
