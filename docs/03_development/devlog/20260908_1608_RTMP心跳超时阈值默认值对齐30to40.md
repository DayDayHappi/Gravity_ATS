# RTMP heartbeat 超时阈值默认值对齐 30→40

## 日期
2026-09-08

## 变更来源
Code Agent Request（Level 0，纯参数默认值对齐）：heartbeat_timeout 在三处出现 40/30/30 不一致，统一为 40（yaml 是唯一权威，会频繁调整，代码 fallback 写死 30 已脱节）。

## 做了什么
把两处代码 fallback/默认值从 30 改为 40，使三处默认对齐（yaml 不动）：

| 位置 | 改动 |
|------|------|
| `ATS/modules/rtmp.py` L120 | `self.config.get("heartbeat_timeout", 30.0)` → `40.0`，并加注释「此默认值仅当 yaml 未配置时生效；权威值见 rtmp.yaml」 |
| `ATS/modules/rtmp_monitor.py` L11 docstring | 「默认 30s」→「默认 40s」 |
| `ATS/modules/rtmp_monitor.py` L40 用法示例 | `RTMPMonitor(timeout=30.0)` → `40.0` |
| `ATS/modules/rtmp_monitor.py` L50 `__init__` | `timeout: float = 30.0` → `40.0`，并加注释说明默认值仅当调用方未显式传入时生效 |

## 不改的东西
- `ATS/config/modules/rtmp.yaml` 的 `heartbeat_timeout: 40` 不动（权威源）。
- 不碰任何功能逻辑，纯默认值对齐。
- `rtmp.py` L133 `progress_step = 30` 是「每 30s 打印一次进度」，与 heartbeat_timeout 是两回事，保持不动。

## 改了哪些文件
- `ATS/modules/rtmp.py`（L120-121）
- `ATS/modules/rtmp_monitor.py`（L11、L40、L50）

## 验证结果
1. `grep` 两文件 → 除 `progress_step = 30`（进度打印间隔，无关）外，无 heartbeat 相关的 30 残留 PASS。
2. `python3 -m py_compile ATS/modules/rtmp.py ATS/modules/rtmp_monitor.py` → PASS。
3. `python3 -m ATS.main --list-modules` → 识别 rtmp，无 import 破坏 PASS。
