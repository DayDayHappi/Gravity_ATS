# stress_traverse_photo_mode 场景接入 H265 完整性检测

## 日期
2026-09-07

## 变更来源
Code Agent Request（Level 1，纯场景配置改动）：模块与驱动已实现（video_integrity 已注册），仅缺场景接线，在 stress_traverse_photo_mode 的录像 task 之后接入 H265 完整性检测，形成「录像 → 检测」闭环。

## 做了什么
`ATS/config/scenarios/stress_traverse_photo_mode.yaml` 在 video 与 rtmp 之间插入 `video_integrity` task，override 三个字段：

| 字段 | 值 | 理由 |
|------|-----|------|
| input.source | `current_run` | VideoModule 把录像下载到 `<log_dir>/videos/`（video.py tmp_dir），与 video_integrity 的 current_run_subdir: videos 对齐 |
| input.selection | `latest_unchecked` | loop count 200，每轮录像都下载新文件；manifest 去重保证每轮只检本轮最新未检文件，不重复检前面轮次 |
| input.empty_input_policy | `skip` | 默认 fail；但录像失败/下载抖动致 videos/ 无文件时，video 已判 FAIL，完整性检测再判 FAIL 是双重惩罚且语义错误，用 skip 静默跳过 |

## 为什么不加 video_ftp_download
new_arch 的 video.py 没有 video_ftp_download 开关（testvideo 分支独有），run() 无条件下载到 videos/，故 override 不写该字段。

## 时序保证
- scenario 串行执行 photo → video → video_integrity → rtmp，video 先落盘、video_integrity 后扫描。
- video_integrity.depends = []，无依赖约束；video 提前 FAIL 时靠 empty_input_policy: skip 兜底。
- manifest.json 在 `<log_dir>/video_integrity/`，log_dir 每次运行按「场景/日期/run_ts」分层，manifest 不跨 run 残留。

## 改了哪些文件
- `ATS/config/scenarios/stress_traverse_photo_mode.yaml`（tasks 中 video 与 rtmp 之间插入 video_integrity + override）

## 验证结果
1. `yaml.safe_load` 读取 tasks 顺序 → `['photo', 'video', 'video_integrity', 'rtmp']` PASS；override 内容与预期一致。

4. 真机跑一轮（可先调小 loop.count 冒烟）：每轮 video PASS 后紧跟 H265 检测: Video_<n>_0.h265，聚合结果正常（本条 devlog 记录时尚未跑真机）。
