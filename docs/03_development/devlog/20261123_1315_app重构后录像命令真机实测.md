### 全 60 组合实测（关键字式，每条录 5s）

板卡实际跑了 3 轮（第 1 轮全量、第 2/3 轮补跑，冷启动各一次），合并去重后逐组合结果：

- **OK = 47 / 60**（`Video recording completed successfully.` + `Save Video Successful: <path>`，板上确有文件落盘，5s/18Mbps ≈ 23MB/条）
- **SET_FAIL = 12 / 60**（命令被拒，未录像）
- **STUCK = 1 / 60**（录像进入但 stop 卡死，见下）

SET_FAIL 全部为 **fps=60 打在 3k / 1080p**（各 6 条 = eis0/1/2 × h264/h265），固件原文：

```
I/CtrlCfg: fps 60 not supported on 3k, use 30 or pick sd1080p|720p|480p for 60
I/CtrlCfg: fps 60 not supported on 1080p, use 30 or pick sd1080p|720p|480p for 60
```

⇒ **Q2 结论：1080p + fps60 确实不支持**（与工程 `VIDEO_FPS_FORCED` 只限 `4k/3k` 不符 → 应补 `1080p`）。

OK 的 47 条覆盖：3k×fps30×eis2(强制)×h264/h265、1080p×fps30×eis0/1/2×2、sd1080p×(fps30 eis0/1/2 + fps60 eis0/1/2)×2 减去挂死那 1 条、720p×fps30/60×eis0/1/2×2、480p×fps30/60×eis0/1/2×2。

### 🔴 确定性固件 bug：`sd1080p fps 60 eis 2 format h265` 触发状态机挂死

- 第 1 轮跑到该组合（第 36 条）→ `cam_run video stop` 超时未回完成串，`cam_run status` 卡在 **`state: stopping (backend: dfs)`**，之后 24 条全部 `cannot record while stopping`（被连累的假失败）。
- 软恢复全部无效：`cam_run video stop` → `I/Ctrl: not recording`、`cam_run video start` → `cannot record while stopping | video start rejected: busy`、`cam_run photo` → `photo needs idle state (now stopping)`、`dfs_video_stop` → `command not found`；shell 无 `reboot` 命令。**只能断电重启**。
- **断电重启后（回到 idle）第一件事就复跑该组合 → 再次卡死在 `stopping`，确定性复现**（排除累积退化/偶发）。
- 关键：该组合**实际落了 `Video_*_0.h265`（41MB）**，即编码器写盘成功，**是 stop 状态机挂死**，非录像本身失败。
- 同行 sd1080p fps60 的 eis0/eis1/eis2+h264 共 5 条均 OK ⇒ 精确到 **sd1080p + fps60 + eis2 + h265** 这一组合。
