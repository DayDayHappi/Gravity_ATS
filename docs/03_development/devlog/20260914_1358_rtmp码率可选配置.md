# RTMP 模块新增「推流码率设置」可选配置

- **日期**：2026-09-14
- **任务**：RTMP 推流前支持可选设置码率（`cam_set live bitrate <value>`），不配置则行为与现状完全一致。

## 问题描述

`rtmp` 模块当前只推流 + 验证（ffprobe + heartbeat），不设置码率。需求要求在 `rtmp_video_start` **之前**可选发送码率命令。

## 修复内容

1. `ATS/drivers/rtmp_commands.py`（协议唯一来源，ADR-011 范式）新增：
   - `RTMP_BITRATE_COMMAND = "cam_set live bitrate {bitrate}"`
   - `RTMP_BITRATE_TIMEOUT = 10.0`
2. `ATS/modules/rtmp.py`：在 `run()` 的 `# 3. EVB 开始推流` 之前插入，读配置、可选发送：
   - `bitrate = self.config.get("bitrate", 0)`
   - `if bitrate:` → `exec_sync(RTMP_BITRATE_COMMAND.format(bitrate=bitrate), timeout=RTMP_BITRATE_TIMEOUT)`
   - `r.success` 为 False → `self._fail(...)` 直接返回，不继续推流（与 video 模块 cam_set 失败即 FAIL 对齐）
   - 未配置 / 0 / 空 → 不发命令（纯增量，无回归）
3. `ATS/config/modules/rtmp.yaml`：新增 `bitrate: 0`（0=不设置），注释说明 scenario 里 `task.override.bitrate` 可覆盖。

## 边界

- 码率值不做合法性校验（固件自行拒绝非法值）；命令模板 + format，与 `RTMP_START_COMMAND.format(url=...)` 同范式。
- 必须在 `rtmp_video_start` 之前发送（先设码率后推流）。

## 验证结果

- `python3 -m py_compile ATS/drivers/rtmp_commands.py ATS/modules/rtmp.py` 通过。

## 还会再有吗

纯增量可选配置，默认 `bitrate: 0` 不发命令，无回归风险。待真机验证码率生效。
