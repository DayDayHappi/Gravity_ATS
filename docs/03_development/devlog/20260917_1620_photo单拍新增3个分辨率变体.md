# photo 单拍新增 3 个分辨率变体

## 1. 问题描述 / 需求

用户要求 photo 单拍（`single`）新增 3 个带分辨率的变体模式：

| 序号 | 命令 |
|------|------|
| 1 | `cam_set photo single 1080p` |
| 2 | `cam_set photo single 720p` |
| 3 | `cam_set photo single 480p` |

需求由 Document Agent 整理归档在 `docs/03_development/archive/新增需求_photo单拍分辨率变体.md`，本记录为其实施。

## 2. 根因分析（为何无需业务代码改动）

`photo.py` L77 用 `commands.PHOTO_SET_COMMAND.format(mode=mode)` 拼命令，模板为
`"cam_set photo {mode}"`。`str.format` 仅做字符串替换，因此 `mode="single 1080p"`
直接得到 `cam_set photo single 1080p`，**含空格的模式名天然支持**。

`PHOTO_MODES` 的 value 未被业务代码引用（业务走模板拼命令），仅作为「合法模式名唯一来源文档」，
新增 3 条用于保持枚举完整、与 `photo_modes` 配置列表一一对应。

## 3. 修复内容

### 3.1 `ATS/drivers/photo_commands.py`

`PHOTO_MODES` 枚举新增 3 条含空格模式名（插在 `single` 之后），并同步注释
标注 3 个含空格模式名同样待真机核实（TODO-CONFIRM）。

```python
PHOTO_MODES: Mapping[str, str] = MappingProxyType({
    "auto": "cam_set photo auto",
    "single": "cam_set photo single",
    "single 1080p": "cam_set photo single 1080p",
    "single 720p": "cam_set photo single 720p",
    "single 480p": "cam_set photo single 480p",
    "mfnr": "cam_set photo mfnr",
    "hdr_0": "cam_set photo hdr_0",
    "hdr_1": "cam_set photo hdr_1",
    "hdr_2": "cam_set photo hdr_2",
    "hdr_3": "cam_set photo hdr_3",
})
```

### 3.2 `ATS/config/scenarios/stress.yaml`

photo task 的 `override.photo_modes` 从 7 个扩为 10 个，追加 3 个分辨率变体，
并同步注释（7 个 → 10 个）。

```yaml
photo_modes: [auto, single, single 1080p, single 720p, single 480p, mfnr, hdr_0, hdr_1, hdr_2, hdr_3]
```

### 3.3 未改动项（按需求边界）

- 不改 `ATS/modules/photo.py`、Runner、Scenario 数据结构。
- 不改 `stress_traverse_photo_mode.yaml`、`stress_traverse_photo_mode_3k.yaml`。
- 不改 `ATS/config/modules/photo.yaml` 全局默认 `photo_modes: ["auto"]`（保持 `normal` 等场景行为不变）。

## 4. 验证结果

- `stress.yaml` YAML 解析：`photo_modes` 正确解析为 10 项，含空格模式名无歧义。
- `photo_commands` 枚举导入：`single 1080p/720p/480p` 均在 `PHOTO_MODES` 中，
  模板拼命令输出分别为 `cam_set photo single 1080p/720p/480p`。
- 核实 report 消费方（`ATS/core/reporter.py` JSON/XML/HTML）对 `name` 字段为字符串
  透传，无按空格分割解析，含空格 name（`photo[single 1080p]`）与本地文件名
  （`single 1080p_<ts>_<jpg>`）无副作用。

## 5. 还会再有吗

**未真机验证**：3 个含空格模式名是否固件合法 `cam_set photo <mode>` 参数形式，需真机
实测/固件手册确认（与既有 `hdr_0~3` 独立命名 vs 需求文档 `cam_set photo hdr <0-3>`
参数形式的同类疑问）。若固件不接受 `single 1080p` 三 token 形式，需按实际支持的
写法调整枚举与配置（含空格 name 映射为无空格标识等），届时再走变更。

## 6. 经验沉淀

- 命令模板 `"{mode}"` + `str.format` 天然支持含空格参数，枚举/配置层即可扩展，
  不必动业务代码；先核实「拼命令」链路再决定改哪层。
- 含空格用例名/文件名在现有 report 消费链路上无解析敏感，可放心使用，但新消费方
  接入时需重新确认是否按空格切字段。
