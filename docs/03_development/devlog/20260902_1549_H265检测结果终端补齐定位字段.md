# H265 检测结果终端补齐定位字段（POC/帧号/时间）

## 日期
2026-09-02

## 变更来源
Code Agent Request：终端不显示检测异常的关键定位信息（POC / 全局帧号 / 出现时间），需把已计算的数据暴露到终端。

## 问题描述
`video_integrity` 检测失败时，终端每文件行只打 `[status] name error_type`，不含定位字段；POC、全局帧号、
失败时间等已由 driver 计算并落盘 `diagnostic.txt`，但用户必须翻日志才能看到关键定位，无法在终端直接判断。

## 根因分析
信息已计算（`H265ValidationResult` 含 `missing_poc/frame_number/coded_frame_index/approx_timestamp/
last_good_decoded_frame/last_good_pts_time/first_decode_error`），只是模块层 `_check_one` 的终端日志
和 `_aggregate` 的 detail 没把这些字段组装进去。属**展示缺失**，非数据缺失，故只改 module 层，
不改 driver 判定、不改 core。

## 修复内容
仅改 `ATS/modules/video_integrity.py`：

1. 新增 `import re` + 两个正则：`_POC_IN_ERR_RE`（从 `first_decode_error` 提取 POC）、`_FFMPEG_PREFIX_RE`（噪声清理，当前未强依赖）。
2. 新增静态方法 `_poc_from_error(first_decode_error)`：`"Could not find ref with POC 6"` → `6`（等价 driver 已有逻辑，module 层独立提取，不改 driver）。
3. 新增静态方法 `_locate_suffix(res)`：生成**终端紧凑后缀**——
   - `MISSING_PICTURE`：`missing_poc=16 全局帧=1667 ~55.533s`（frame_number 优先，其次 coded_frame_index）；
   - 其它失败（`MISSING_REFERENCE` 等）：`POC=6 last_good_frame=1126 last_good_pts=37.533s`；
   - PASS / 无字段：返回空串（保持轻量）。
4. 新增静态方法 `_detail_fields(res)`：生成 detail/summary 的**完整定位字段**（missing_poc / gop_index /
   coded_frame_index / frame_number / approx_timestamp / last_good_decoded_frame / last_good_pts_time / decoder_poc）。
5. `_check_one`：`status in (FAILED, ERROR)` 时终端行拼 `_locate_suffix`，PASS 不拼（保持轻量）。
6. `_aggregate` 的 detail：非 PASS 行改用 `_detail_fields` 补齐完整字段（进报告）。
7. `_write_summary`：summary.log 行改用 `_detail_fields`。

未改 driver（`h265_validator.py`）、未改 core（`base.py/runner.py`），未新增 `H265ValidationResult` 字段
（decoder_poc 由 module 层从 `first_decode_error` 提取，满足 request 第 3 点的「最小」方案）。

## 如何验证
- `python3 -m py_compile ATS/modules/video_integrity.py` → PASS。
- 实测损坏样本（`/tmp/vi_cases/corrupt.h265`，`MISSING_REFERENCE`）终端行：
  `[FAIL] corrupt.h265 MISSING_REFERENCE POC=6 last_good_frame=1126 last_good_pts=37.533s (22.6s)` → PASS。
- 同一文件 detail：`[FAIL] corrupt.h265 (MISSING_REFERENCE last_good_decoded_frame=1126 last_good_pts_time=37.533s decoder_poc=6)` → PASS。
- 单元验证 `_locate_suffix` / `_detail_fields`：
  - `MISSING_PICTURE`（missing_poc=16, frame_number=1667, approx_timestamp=55.533）→ `' missing_poc=16 全局帧=1667 ~55.533s'`；detail 含 gop_index/coded_frame_index/frame_number/approx_timestamp → PASS。
  - `PASS` → 空串（轻量不变）→ PASS。
  - `MISSING_REFERENCE` 无 last_good 时仅 `' POC=9'` → PASS。

## 还会再有吗
- 真机 normal/stress 场景下终端展示未实机验证（同 H265 模块，需板端链路），但逻辑与离线验证一致，风险低。
- `_FFMPEG_PREFIX_RE` 已定义但 `first_decode_error` 目前在终端只展示其提取出的 POC 值、不展示原始字符串，
  该正则当前未被调用，保留供后续若需展示净化后错误文本时使用（无副作用）。

## 经验沉淀
「数据已算好、只是没展示」的缺陷，修法应只在展示层（module 的日志/detail）组装字段，绝不回改判定层（driver）或 core；
POC 值若 driver 未显式存为独立字段，module 层用正则从 `first_decode_error` 提取即可，无需为此扩张结果结构。
