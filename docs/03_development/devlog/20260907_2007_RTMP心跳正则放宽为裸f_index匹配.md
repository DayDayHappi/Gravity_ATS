# RTMP heartbeat 正则放宽为裸 f_index 匹配（固件日志格式变更）

## 日期
2026-09-07

## 变更来源
Document Agent 已记 `docs/05_handoff/known_issue.md`：固件 RTMP 心跳日志格式从 8 月 `[RTMP] f_index = N` 变为 9 月 `I/App Rtmp: f_index = N`，monitor 正则失配，推流正常也 60s 误判 TIMEOUT。Code Agent Request 修复 `ATS/modules/rtmp_monitor.py`。

## 问题描述
`_HEARTBEAT_RE = re.compile(r"\[RTMP\]\s+f_index\s*=")` 锁死旧固件前缀 `[RTMP]`；新固件改打 `I/App Rtmp: f_index = N` 后一个都匹配不到，`heartbeat_timeout`（60s）后必然 TIMEOUT。实测同一窗口内 `[RTMP] f_index` 0 条 vs `I/App Rtmp: f_index` 88 条。

## 根因分析
固件日志前缀变更（`[RTMP]` → `I/App Rtmp:`），脚本正则锚定旧前缀导致失配；且前缀本身会被串口分块截断（实测 `p: f_index` / `Rtmp: f_index` / 裸 `f_index`），锚定前缀本就脆弱。

## 修复内容
1. `ATS/modules/rtmp_monitor.py`：`_HEARTBEAT_RE` 从锚定 `[RTMP]` 前缀放宽为裸匹配 `f_index\s*=\s*\d+`。
2. 同步在正则注释 + docstring 钉死裸匹配安全前提（窗口隔离）：monitor 仅在 rtmp 推流保持窗口内监听，该窗口内串口仅有 Rtmp 一种 f_index（scenario 串行时序 photo→video→rtmp，video 的 Dfs 心跳在 `dfs_video_stop` 后已停）；且前缀会被分块截断，故不锚定前缀。
3. 一致性修正过时的 `[RTMP] f_index` 描述（均为源码/配置注释与日志文案，非架构文档）：
   - `rtmp_monitor.py` docstring / `check_timeout` reason 文案
   - `rtmp.py` docstring / run() 注释 / ERROR 日志文案
   - `rtmp.yaml` `heartbeat_timeout` 行内注释
   - `video.py` 启动判据注释（说明 rtmp_monitor 同样用裸 f_index，靠串行时序窗口隔离区分）

## 验证结果
- `python3 -m py_compile` 三个模块 → PASS。
- 正则命中验证：旧格式 `[RTMP] f_index = 0, f_len = 39`、新格式 `I/App Rtmp: f_index = 88`、分块截断 `p: f_index=88` / `Rtmp: f_index = 12` / 裸 `f_index = 5` 均 MATCH；`[RTMP] f_index =`（无数字）不匹配（符合预期，避免空值误判）。
- `grep` 确认 `rtmp.py` / `config` / `video.py` 无残留 `[RTMP]` 引用；`rtmp_monitor.py` 仅保留 L9/L21 的历史格式说明注释。

## 已知遗留
- 裸匹配理论上会匹配到其它模块的 f_index，但靠窗口隔离（rtmp 推流保持窗口内只有 Rtmp 一种 f_index）兜底，未引入正则区分。真机一轮 rtmp 需确认不再出现「>60s 无 f_index」ERROR、Push Stop: total frames 正常到达（本条 devlog 记录时尚未跑真机）。

## 经验沉淀
- 日志格式作为「固件行为 → 脚本适配点」应记入 known_issue，正则修复优先裸匹配 + 窗口隔离，而不是在正则里重新锚定易被分块截断的前缀。
