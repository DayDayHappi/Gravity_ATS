## 一、项目背景

为 VX100 EVB 板（双核异构 RISC-V，RT-Thread msh shell）开发**上位机自动化测试脚本**，替代人工手动测试，用于功能验证/产测。

测试链路：PC 通过串口发命令控制 EVB，通过 WiFi/FTP 验证拍照录像等功能的产物。EVB 硬件连接：
- **UART0**（USB-串口，FT2232）接 PC，跑 msh shell，波特率 **2000000 bps**
- **WiFi** 连局域网（实测 G-Demo，密码 `Gdemo@123`）
- **FTP 服务**（RT-Thread 自带，端口 21，loogg/loogg）用于文件传输

## 二、项目需求

按固定流程自动测试 EVB 的：WiFi 连接 → eMMC → FTP → 拍照 → 录像 → RTMP 推流，每个环节验证成功/失败，生成报告。

**关键约束（用户要求）**：
1. 架构要**解耦、灵活、可移植**--测试项/流程可能随时调整，加测试项不改核心代码
2. 串口波特率可配置，默认 2000000，自动探测带回退
3. WiFi 启动时交互连接（默认 G-Demo 或扫描选 AP），连上后跳过 wifi 测试
4. 板子不下电连续测试时，若仍连着 WiFi（ifconfig 有 IP）则跳过 wifi 模块
5. 拍照失败只标记该模式 FAIL，继续下一个模式
6. 照片/视频需**下载到本地**并打印存储路径
7. 每次改 ATS 代码必须在 `doc/devBugLog/` 新建记录文档（已固化为规则）

## 三、架构设计

### 3.1 分层 + 注册解耦

```
ATS/
├── main.py                # 入口：CLI、串口探测、板子预清理、WiFi交互、调度
├── config/test_config.yaml # 数据驱动配置（增删测试项只改这里）
├── core/                  # 框架核心（稳定，加用例不改这里）
│   ├── ansi.py            # ANSI 转义剥离
│   ├── logger.py          # 常驻读线程全量串口日志（logs/<ts>/serial.log）
│   ├── context.py         # 跨模块共享上下文（evb_ip/ftp_client/skip_wifi 等）
│   ├── config.py          # YAML加载 + ${ENV}替换 + schema校验
│   ├── result.py          # Response/TestResult 数据结构
│   ├── serial_console.py  # 串口：哨兵机制+自动探测+波特率回退（核心）
│   ├── runner.py          # 拓扑排序+执行+重试+fail-fast（SKIP不阻断依赖）
│   └── reporter.py        # JSON + JUnit + HTML 报告
├── modules/               # 功能模块（每模块一文件，@register 注册）
│   ├── base.py            # TestModule 基类 + @register 装饰器
│   ├── wifi.py            # wifi_check + wifi_scan + wifi_join
│   ├── emmc.py            # cd /emmc 验证
│   ├── ftp.py             # ftp_server 启动 + ensure_ftp 恢复
│   ├── photo.py           # 拍照 + JPEG 下载校验
│   ├── video.py           # 录像 + 下载
│   └── rtmp.py            # RTMP 推流（待测）
└── drivers/               # PC 端辅助
    ├── ftp_client.py      # ftplib 封装（主动模式+断点续传）
    └── rtmp_receiver.py   # ffmpeg 拉流 + ffprobe 验证
```

**新增测试项**：`modules/` 加文件 + `@register("xxx")` + `__init__.py` 加 import + 配置 `enabled_modules` 加一行，**不改 core**。

**模块间解耦**：通过 `ctx`（共享上下文）传数据，不互相 import。如 `wifi` 存 `evb_ip`，`ftp` 存 `ftp_client`，`photo`/`video` 取用。

### 3.2 串口哨兵机制（核心）

msh 提示符会被后台日志打碎粘连（`msh />[32m...`），不能靠等提示符。方案：
- 同步命令用 `exec_sync`：发 `cmd\necho "TOKEN"`（换行分隔，msh 不支持 `;`），等 TOKEN 出现定界
- 异步/重输出命令（wifi join/拍照/录像）用 `exec_async`：发命令后直接等期望正则（不依赖哨兵，因海量日志会打乱哨兵）
- 解析前剥离 ANSI 转义

### 3.3 测试流程与依赖

```
wifi_check ──> wifi_scan ──> wifi_join ──> emmc ──> ftp ──> photo
                  │             │                    └──> video
                  └─────────────┴────────────────────────> rtmp
```

`wifi_check` 先 ifconfig 检测，有 IP 则标记 `skip_wifi`，wifi_scan/wifi_join 跳过（SKIP 不阻断后续模块）。

## 五、存在的问题与已知固件 Bug

### 5.1 固件 Bug（已规避，非脚本问题）

1. **FTP 服务在拍照/录像后崩溃**：`[W/ftp] service go wrong` 反复。`ensure_ftp(force=True)` 重发 `ftp_server` 恢复。photo/video 用前强制重连。
2. **FTP 服务限制**：只支持主动模式（不支持 PASV）、`LIST <path>` 忽略路径（需先 CWD 再无参 LIST）、不支持 NLST/STOR/SIZE（用 LIST 解析）。需 **PC 关防火墙**（`sudo ufw disable`）。
3. **FTP 传大文件卡死**：socket 阻塞。已用 `socket.setdefaulttimeout` + REST 断点续传解决（见 5.2）。
4. **msh 不支持 `;` 分隔命令**：哨兵改换行分隔。
5. **echo 必须带引号**：`echo "string"`，否则报 Usage。
6. **msh 提示符两种形态**：`msh />`（根目录）和 `msh /emmc>`（子目录），正则已适配。
7. **WiFi join 偶发 "not find ap"**：scan 后立即 join 借缓存可提高成功率；连续运行用 wifi_check 检测已连则跳过。

### 5.2 脚本层面已解决的问题

- **连续运行 emmc 报错**：`cd emmc` 改绝对路径 `cd /emmc` + 预清理 `cd /`
- **依赖链 SKIP 误伤后续**：runner 的 fail-fast 改为 SKIP 不阻断（只 FAILED/ERROR 阻断）
- **下载卡死无超时**：`socket.setdefaulttimeout` + REST 断点续传
- **板子状态残留**：main.py 预清理（cd / + 停录像 + 恢复 FTP）

### 5.3 当前残留注意点

1. **录像时长限制为 2 秒**：5 秒（10MB）虽能下完但断点续传耗时长。配置 `video_duration: 2`。
2. **测试前建议重启板子**：固件状态异常时（FTP 严重崩溃循环）预清理可能不够，重启最稳。
3. **PC 防火墙必须关**：FTP 主动模式需要 EVB 回连 PC 数据端口。
4. **串口权限**：用户需在 dialout 组（`sudo usermod -aG dialout $USER`）或临时 `chmod 666 /dev/ttyUSB*`。
5. **网络认证**：该 PC 网络有网页认证网关，会话过期后 apt/pip 失败，需重新认证。

## 八、给下一位接手者的建议

1. **先跑一次**：`python3 -m ATS.main --no-interactive-wifi --skip rtmp`，确认环境正常（需 pyserial + 关防火墙 + 串口权限）。
2. **遇到问题先查 devBugLog**：固件的坑基本都踩过并记录了。
3. **改代码必须记录**：改 ATS 代码后在 `doc/devBugLog/` 新建 `YYYYMMDD_HHMM_描述.md`，更新 README 索引。
4. **新增测试项**：照 `modules/` 现有模块的模式，继承 TestModule + @register + 配置加一行。
5. **RTMP 是唯一未验证模块**：装 ffmpeg 后测一次，若 `rtmp_video_start` 命令行为与预期不符（如成功标志不同），参考 photo/video 的 exec_async + 正向 expect 模式调整。
6. **固件 FTP 不稳定是常态**：ensure_ftp + 断点续传已处理大部分情况，但极不稳定时建议重启板子。
7. **实测与手册多处不符**：波特率（2000000 非 250000）、文件结构（/emmc/PIC/<时间戳目录>/Image_xxx.jpg 非 /emmc/pic/直接放文件）、FTP 限制等，均以代码和设计文档附录A为准，勿迷信手册。
