# 测试结束询问本次问题并记录到 logs/problem/ 目录

**日期**: 2026-08-19
**改动范围**: `ATS/main.py`（新增 `_record_test_problem()` 并在测试末尾调用）

---

## 一、问题描述

每次跑完自动化测试后，测试人员想顺手把「本次测试遇到的问题」留下来，便于后续排查/交接，
但此前脚本没有这个入口，问题只能靠口头或另开文件记录，容易遗漏。

## 二、根因分析

这是**新功能缺失**，非 bug。测试流程的最后（生成报告后、退出前）没有任何「留痕」环节。

## 三、修复内容

`ATS/main.py`：

1. 新增函数 `_record_test_problem(run_ts, log_root)`：
   - 用 `input()` 询问「本次测试有什么问题？(直接回车表示无问题)」。
   - 空输入（或 `EOFError`/`KeyboardInterrupt`，覆盖无人值守/无 stdin 场景）视为无问题，直接返回。
   - 有输入时，创建 `logs/problem/` 目录，写一个 `<run_ts>.log` 文件，
     内容为「问题原文 + 末尾附本次运行时间戳」。
2. 在 `main()` 生成报告之后、清理之前调用（第 8.5 步）。

只有正常跑完测试流程才触发询问；`--dry-run` / `--terminal` / `--list-modules` /
依赖缺失 / 串口失败等提前退出分支都不会走到这里。

## 四、验证结果

- `python3 -m py_compile ATS/main.py` 语法检查通过。
- **待真机/手动验证**：跑一次完整测试，结束时输入问题确认落盘到 `logs/problem/<时间戳>.log`；
  直接回车确认不生成文件。

## 五、还会再有吗

- 无人值守跑脚本（无 stdin）时 `input()` 会抛 `EOFError`，已捕获并按「无问题」处理，不会阻塞退出。
- 时间戳沿用本次运行的 `run_ts`（`logger.init_logger` 返回值，格式 `YYYYMMDD_HHMMSS`），
  与 `logs/<run_ts>/` 日志目录一致，可对照。

## 六、经验沉淀

- 这类「测试后留痕」入口应放在**报告生成之后、资源清理之前**：此时 logger 仍可用、
  结果已产出，用户能基于完整测试结果回答「有什么问题」。
- 交互式输入必须处理 `EOFError`/`KeyboardInterrupt`，否则无人值守/管道化场景会把脚本卡死或抛异常。
