# VX100 EVB 自动化测试脚本 - 使用手册

**脚本路径**: `/home/gravity/AutoTestScripts_JX009/ATS`
**适用场景**: VX100 EVB 板的功能测试（WiFi/eMMC/FTP/拍照/录像/RTMP）
**运行环境**: Ubuntu 20.04+，Python 3.8+

---

## 一、环境准备（首次使用必读）

### 1.1 安装依赖

```bash
# Python 串口库（必需）
pip install pyserial

# ffmpeg + ffprobe（RTMP 推流验证用，不测 RTMP 可不装）
sudo apt install -y ffmpeg
```

验证依赖：
```bash
python3 -c "import serial; print('pyserial', serial.__version__)"
ffmpeg -version | head -1   # 装了才有
```

### 1.2 串口权限（重要！）

EVB 串口属于 `dialout` 组，默认无权限打开会报 `Permission denied`。

**永久解决**（推荐，一次搞定）：
```bash
sudo usermod -aG dialout $USER
# 然后注销重新登录（或重启）生效
```

**临时解决**（重启/重插失效，每次要重做）：
```bash
sudo chmod 666 /dev/ttyUSB0 /dev/ttyUSB1 /dev/ttyUSB2
```

### 1.3 PC 防火墙（FTP 验证必需）

EVB 的 FTP 服务只支持主动模式，需要 EVB 回连 PC 数据端口，必须放行入站：

```bash
# 临时关闭防火墙（测试期间）
sudo ufw disable

# 或只放行高位端口（更安全）
sudo ufw allow 1024:65535/tcp
```

> 不做这步，FTP 能连上但无法 LIST/下载文件（会超时）。

### 1.4 接线与上电

1. EVB 的 UART0 用 USB-串口线接到 PC
2. 给 EVB 上电，等板子启动到 `msh />` 提示符（约 30 秒）
3. 确认串口设备已识别：
   ```bash
   ls /dev/ttyUSB*
   ```
   应看到 `/dev/ttyUSB0` 等。

### 1.5 网络

- PC 和 EVB 连同一个 WiFi（实测 G-Demo，密码 `Gdemo@123`）
- PC 的 IP 会自动检测，无需手动配置

## 二、基本用法

所有命令在项目根目录执行：
```bash
cd /home/gravity/AutoTestScripts_JX009
```

### 2.1 完整测试（推荐）

```bash
python3 -m ATS.main
```

启动后流程：
1. 自动探测 EVB 串口和波特率
2. 打开串口，等 msh 就绪
3. 预清理板子状态（停录像、断 WiFi、恢复 FTP）
4. **交互式连接 WiFi**：
   ```
   是否连接默认 WiFi [G-Demo]? [Y/n]:
   ```
   - 回车或 `y` -> 用 G-Demo / Gdemo@123
   - 输入 `n` -> 扫描列 AP 让你选并输密码
5. 依次执行模块：wifi_scan -> wifi_join -> emmc -> ftp -> photo -> video -> rtmp
6. 生成报告，打印汇总，返回退出码

### 2.2 跳过某些模块

```bash
# 跳过 RTMP（没装 ffmpeg 时）
python3 -m ATS.main --skip rtmp

# 跳过多个
python3 -m ATS.main --skip rtmp,video
```

### 2.3 只测指定模块

```bash
# 只测 WiFi
python3 -m ATS.main --modules wifi_scan,wifi_join

# 只测串口+eMMC（快速验证板子通不通）
python3 -m ATS.main --modules emmc
```

### 2.4 非交互模式（脚本/自动化场景）

```bash
# 不交互，直接用配置里的默认 WiFi（G-Demo）
python3 -m ATS.main --no-interactive-wifi --skip rtmp
```

适合写进 CI 或批处理脚本，无需人工输入。

### 2.5 指定串口（跳过自动探测）

```bash
python3 -m ATS.main --port /dev/ttyUSB0
```

不指定则自动探测（推荐，会自动找 EVB 并识别波特率）。

## 三、常用命令示例

```bash
# 1. 列出所有可用模块（看模块名和依赖）
python3 -m ATS.main --list-modules

# 2. 校验配置和依赖（不连板子，不测试）
python3 -m ATS.main --dry-run

# 3. 完整测试（交互式 WiFi，跳过 RTMP）
python3 -m ATS.main --skip rtmp

# 4. 完整测试（全自动，不交互）
python3 -m ATS.main --no-interactive-wifi --skip rtmp

# 5. 详细日志（调试用，看串口探测/命令收发过程）
python3 -m ATS.main --skip rtmp -v

# 6. 只测拍照录像（前提：WiFi/FTP 已就绪或先跑 wifi+ftp）
python3 -m ATS.main --modules wifi_scan,wifi_join,emmc,ftp,photo,video

# 7. 强制格式化 eMMC（慎用，会清空数据）
python3 -m ATS.main --format

# 8. 指定 WiFi
python3 -m ATS.main --wifi-ssid "MyWiFi" --wifi-password "mypassword"
```

颜色：绿色 PASS / 红色 FAIL / 黄色 SKIP / 紫色 ERROR。

### 4.2 报告文件

每次运行生成时间戳子目录：

```
reports/<运行时间戳>/
  result.json     # 机器可读，含每用例详情（cmd/输出/耗时/判定）
  junit.xml        # CI 集成（Jenkins/GitLab 可解析）
  report.html      # 人可读可视化报告（浏览器打开）

logs/<运行时间戳>/
  serial.log       # 全量串口收发日志（带毫秒时间戳，含 ANSI 原始字节）
  run.log          # 框架运行日志
  photos/          # 下载到本地的照片（JPEG 校验过）
  videos/          # 下载到本地的录像
```

查看最新报告：
```bash
# 找最新一次运行
latest=$(ls -dt reports/*/ | head -1)
echo "最新报告: $latest"
ls "$latest"

# 浏览器打开 HTML 报告
xdg-open "${latest}report.html" 2>/dev/null || echo "HTML 报告: ${latest}report.html"

# 看 JSON 汇总
python3 -c "import json; d=json.load(open('${latest}result.json')); print(json.dumps(d['summary'],ensure_ascii=False,indent=2))"
```

### 4.3 退出码

| 退出码 | 含义 | 用途 |
|--------|------|------|
| 0 | 全部通过 | CI 判定通过 |
| 1 | 有失败用例 | CI 判定失败 |
| 2 | 环境/配置错误 | 依赖缺失、串口找不到等 |

脚本里可以这样用：
```bash
python3 -m ATS.main --skip rtmp
if [ $? -eq 0 ]; then echo "测试通过"; else echo "测试失败"; fi
```

## 五、配置文件

配置文件：`ATS/config/test_config.yaml`。改配置不改代码。

常用可调项：

```yaml
serial:
  port: "auto"            # auto=自动探测；或填 /dev/ttyUSB0
  baudrate: 2000000       # 实测波特率

wifi:
  default_ssid: "G-Demo"
  default_password: "Gdemo@123"
  interactive: true       # 启动时交互选择 WiFi

camera:
  photo_modes: ["auto"]  # 可扩为 [auto, single, mfnr, hdr_0, hdr_1, hdr_2, hdr_3]
  photo_min_size_kb: 10   # 拍照文件最小有效大小
  video_duration: 5       # 录像时长（秒）
  video_min_size_kb: 100  # 录像文件最小有效大小

rtmp:
  stream_duration: 10     # RTMP 推流时长（秒）
  pc_ip: "auto"           # auto=自动检测 PC IP

test:
  enabled_modules:        # 增删测试项改这里
    - wifi_scan
    - wifi_join
    - emmc
    - ftp
    - photo
    - video
    - rtmp
  fail_fast: true         # 某模块失败是否跳过依赖它的后续模块
```

**敏感字段**支持 `${ENV_VAR}` 从环境变量读：
```yaml
wifi:
  default_password: "${WIFI_PASSWORD}"
```
然后 `export WIFI_PASSWORD=xxx` 后运行，密码不写进配置文件。

## 六、命令行参数完整列表

```
python3 -m ATS.main --help
```

| 参数 | 说明 |
|------|------|
| `--config <路径>` | 指定配置文件（默认 ATS/config/test_config.yaml） |
| `--port <设备>` | 指定串口（如 /dev/ttyUSB0），不填自动探测 |
| `--baudrate <值>` | 指定波特率，覆盖配置 |
| `--modules <a,b,c>` | 本次只测这些模块（逗号分隔） |
| `--skip <a,b>` | 跳过这些模块 |
| `--format` | 强制格式化 eMMC（会清空数据） |
| `--wifi-ssid <名称>` | 指定 WiFi SSID |
| `--wifi-password <密码>` | 指定 WiFi 密码 |
| `--no-interactive-wifi` | 跳过 WiFi 交互，用配置的默认值 |
| `--output-dir <目录>` | 报告输出目录 |
| `--verbose` / `-v` | 详细日志 |
| `--list-modules` | 列出所有可用模块 |
| `--dry-run` | 仅校验配置和依赖，不执行测试 |

## 七、典型场景

### 场景 1：产线快速判定（只测核心通路）

```bash
python3 -m ATS.main --modules wifi_scan,wifi_join,emmc,ftp --no-interactive-wifi
```

### 场景 2：完整功能验证（含拍照录像，无 RTMP）

```bash
python3 -m ATS.main --skip rtmp --no-interactive-wifi
```
约 30 秒完成，照片下载到本地并校验。

### 场景 3：调试某个模块

```bash
# 只测拍照，开详细日志看全过程
python3 -m ATS.main --modules wifi_scan,wifi_join,emmc,ftp,photo -v
```

### 场景 4：CI 集成

```bash
python3 -m ATS.main --no-interactive-wifi --skip rtmp
# 退出码 0=通过，1=失败，2=环境错
# 解析 reports/<时间戳>/junit.xml 上传 CI
```

### 场景 5：RTMP 手动调试（三终端配合，类 Xcom）

RTMP 出问题时，用人工手动操作把整条链路拆开验证，比脚本盲测高效。需要 3 个终端窗口：

**终端 ①：起 MediaMTX 服务端（常驻）**

```bash
cd /home/gravity/AutoTestScripts_JX009
./tools/mediamtx/mediamtx tools/mediamtx/mediamtx_min.yml
# 看到 "[RTMP] started with listener on :1935" 即就绪，保持开着
```

**终端 ②：拉流播放（二选一）**

用 ffplay 走 RTSP over TCP 直接看画面（MediaMTX 同时提供 RTSP，TCP 传输抗乱序帧更稳）：

```bash
./tools/ffmpeg/ffplay -rtsp_transport tcp rtsp://127.0.0.1:8554/live/cam
```

或用 ffmpeg 拉流存盘后再验证（绕开 ffplay 直连对乱序帧敏感的问题）：

```bash
./tools/ffmpeg/ffmpeg -y -rw_timeout 15000000 -i rtmp://127.0.0.1/live/cam -t 10 -c copy -f flv /tmp/rtmp_record.flv
./tools/ffmpeg/ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height:format=duration -of json /tmp/rtmp_record.flv
./tools/ffmpeg/ffplay /tmp/rtmp_record.flv   # 播放存盘文件看画面
```

**终端 ③：串口终端手动发推流命令**

```bash
python3 -m ATS.main --terminal
# 进去后：wifi join G-Demo Gdemo@123  →  rtmp_video_start rtmp://<PC_IP>/live/cam  →  rtmp_video_stop  →  exit
```

**成功判据**：终端①出现 `is publishing to path 'live/cam'` + 终端②出画面或 ffprobe 显示 h264/分辨率/时长 = RTMP 链路通。

> 注意：拉流地址用 PC 上能被 EVB 路由到的 IP（同网段优先）。PC 有多个 IP 时，脚本自动探测可能选错 IP 导致 EVB 推流连不上——手动验证时用能通的那个 IP，脚本侧则把 `pc_ip` 在配置里写死。

### Q1: 报"未发现 EVB 串口"

检查：
```bash
ls /dev/ttyUSB*          # 有没有设备
groups                   # 有没有 dialout 组
```
- 没设备：EVB 没上电/没接好/驱动没装
- 有设备但没权限：`sudo usermod -aG dialout $USER` 后重新登录

### Q2: 串口打开了但收不到数据/乱码

自动探测会试多个波特率。如果还失败：
- 确认板子已启动到 `msh />`（用别的串口工具看）
- 板子状态异常就重启板子

### Q3: WiFi 连不上

```bash
# 用别的串口工具手动试
wifi scan
wifi join G-Demo Gdemo@123
```
- RSSI < -70 信号弱，换近一点的 AP
- 密码错会报 `wifi join failed`

### Q4: FTP 连上但下载失败

检查 PC 防火墙：
```bash
sudo ufw status
```
必须 `inactive` 或放行高位端口。主动模式需要 EVB 回连 PC。

### Q5: 拍照/录像后 FTP 报 "service go wrong"

固件 bug，拍照/录像会触发 FTP 服务崩溃。脚本会自动 `ensure_ftp` 恢复。如果连续失败：
- 重启板子（拔插电源等 3 秒再上电）
- 每轮测试前重启板子最稳妥

### Q6: photo 显示"未列出 jpg 辅助验证"

拍照本身成功了（串口确认 `Save Photo Successful`），只是 FTP 下载校验跳过。不影响 PASS 判定。板子干净时能下载成功。

### Q7: RTMP 模块失败

```bash
ffmpeg -version    # 必须有输出
```
没装：`sudo apt install -y ffmpeg`。

### Q8: 怎么看上次的串口日志

```bash
latest=$(ls -dt logs/*/ | head -1)
tail -50 "${latest}serial.log"
```

## 九、测试稳定性建议

1. **每轮完整测试前重启板子**：保证干净状态，避免上次测试残留导致 WiFi/FTP 异常
2. **板子启动等 30 秒**再跑脚本（等 `msh />` 出现）
3. **一次只跑一个脚本实例**：串口和 FTP 服务不支持并发
4. **网络稳定**：PC 和 EVB 连同一个 WiFi，信号 RSSI > -70
5. **磁盘空间**：录像文件较大（每次约 10MB），定期清理 `logs/` 和 `reports/`
