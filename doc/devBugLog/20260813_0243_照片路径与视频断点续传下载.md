## 一、问题描述

1. **视频未下载到本地**：video 模块只做 `size` 校验，没调用 `download`，录像文件不会保存到 PC。
2. **照片下载后无路径提示**：photo 模块下载成功后，message 只显示 `JPEG OK 674KB | 拍照成功...`，不含本地存储路径，用户找不到下载的文件。
3. **FTP 下载大文件卡死**（开发中发现）：固件 FTP 传大文件（>4MB）中途 socket 阻塞卡死，无超时保护，导致整个脚本挂起。

### 2.3 `drivers/ftp_client.py`：download 重写为断点续传 + 超时保护（核心）

固件 FTP 传大文件卡死的根因：socket recv 无限阻塞。解决方案：

1. **`socket.setdefaulttimeout(timeout)`**：使所有 socket 操作（含数据连接 recv）超时抛异常，不再无限阻塞
2. **REST 断点续传**：卡死后用 `retrbinary(rest=offset)` 从已下载位置继续，不从头重下
3. **追加写入**（`ab` 模式）配合 REST 偏移
4. 多次续传直到 `local_sz >= total`

```python
def download(self, remote_path, local_path, timeout=30.0, retries=5):
    import socket as _socket
    total = self.size(remote_path)
    old_timeout = _socket.getdefaulttimeout()
    _socket.setdefaulttimeout(timeout)
    try:
        for attempt in range(1, retries + 1):
            if self._ftp is None:
                self.connect()
            offset = os.path.getsize(local_path) if os.path.exists(local_path) else 0
            if total > 0 and offset >= total:
                return True
            try:
                mode = "ab" if offset > 0 else "wb"
                with open(local_path, mode) as f:
                    self._ftp.retrbinary(f"RETR {remote_path}", f.write,
                                         rest=offset if offset > 0 else None)
                if total <= 0 or os.path.getsize(local_path) >= total:
                    return True
            except Exception as e:
                logger.warn(f"下载异常(尝试{attempt}/{retries}): {e}")
            self._safe_close()
            self.connect()
        return total > 0 and os.path.getsize(local_path) >= total
    finally:
        _socket.setdefaulttimeout(old_timeout)
```

**关键点**：
- 验证过该 FTP 支持 REST 命令（`REST 5000000` 返回 `350`，从偏移下载得到 `total-offset` 字节）
- 用 `os.path.getsize(local_path)` 作为续传偏移（最准确，避免缓冲区统计偏差）
- 同步实现（非多线程），socket 超时能可靠中断阻塞

## 五、经验沉淀

1. **socket.setdefaulttimeout 是处理第三方阻塞调用的利器**：当库内部 socket 阻塞且无超时参数时，全局 socket 超时能让它抛异常，比多线程 + join 超时更可靠（多线程里阻塞的 socket 关连接不一定能唤醒）。
2. **FTP REST 断点续传**：验证服务器支持 REST（返回 350）后，`retrbinary(rest=offset)` 可从断点继续，避免大文件从头重下。本地用 `ab` 追加 + `os.path.getsize` 做偏移最准确。
3. **多线程超时 vs 同步超时**：本次最初用多线程 + join 超时，但阻塞的 socket 在子线程关连接无法唤醒，导致超时机制失效。改用同步 + socket 全局超时后可靠。教训：能用同步超时就不要用多线程包裹。
4. **文件大小用实际值**：续传偏移用 `os.path.getsize` 而非 write 回调统计，避免缓冲区未刷盘导致的偏差。
