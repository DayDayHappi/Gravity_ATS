# 新增交互式串口终端模式（--terminal，类 Xcom）

**日期**: 2026-08-13
**改动范围**: `ATS/tools/serial_terminal.py`(新增) + `ATS/tools/__init__.py`(新增) + `ATS/main.py`

## 1. 问题描述

RTMP 调试中发现 EVB 的 `rtmp_video_start` 命令行为未知（可能卡死/可能需前置准备/可能路径问题），需要一个人工手动发命令、实时看板子返回的调试手段，像 Xcom 串口助手那样。

现有 ATS 是自动化测试框架（命令-响应模型，exec_sync/exec_async），没有"人工实时交互"能力。需新增一个调试模式：用户全程手动发命令，屏幕实时显示 TX（发送）+ RX（板子返回），脚本不代发、不解析、不判定。

## 2. 根因/设计

与测试框架职责不同（调试 vs 自动化），采用独立工具方案：

- 新增 `ATS/tools/serial_terminal.py`，**直接用 pyserial**（自己开口 + 自己起读线程实时打屏），不碰 `SerialConsole` 类（那是命令-响应模型，不适合实时交互）
- 复用两个**纯函数**：`detect_port`（自动探测串口）+ `ansi.strip`（剥离转义）
- 入口：`main.py` 加 `--terminal` 子命令，独立分支早返回（不走测试流程）

交互行为（与用户确认）：
- `python3 -m ATS.main --terminal` 启动，复用配置的串口参数 + 自动探测
- 敲命令 + 回车 -> 发送（自动补 `\n`），`TX>` 绿色显示
- 板子返回实时 `RX<` 显示
- **Tab 切换** ANSI 颜色码剥离/原始显示
- Ctrl+C 或 `exit`/`quit` 退出

## 3. 修复内容（实现）

### 3.1 `ATS/tools/serial_terminal.py`

- `run_terminal(port, baudrate, strip_ansi)`：主函数
  - 读线程 `_reader_loop`：循环 `ser.read()`，`ansi.strip`（若开启）后带 `RX<` 前缀打屏，流式不强制换行
  - 主线程：cbreak 模式逐字符读 stdin
    - 回车 -> 发送命令 + `TX>` 绿色显示
    - Tab -> 切换 `strip_ansi` 标志 + 状态提示
    - 退格 -> 删字符
    - Ctrl+C / exit / quit -> 退出
  - `print_lock` 串行化 TX/RX print，避免交错撕裂
  - finally 恢复终端设置（termios）+ 关串口 + 停读线程
- `run_from_args(args, config)`：从 CLI + 配置解析 port/baudrate（复用 detect_port 自动探测）

### 3.2 `ATS/main.py`

- `parse_args` 加 `--terminal`（启动终端）+ `--raw`（原始字节，不剥离 ANSI）
- `main()` 配置加载后加分支：`if args.terminal: return run_from_args(args, config)`

### 3.3 关键点：cbreak 模式实现 Tab 切换

`input()` 阻塞时会吞掉 Tab，无法运行中切换。故用 `tty.setcbreak()` 把终端设为逐字符模式：Tab(0x09) 触发切换、回车触发发送、其他字符累积成命令行。代价是不能用 readline 的行编辑（自行实现退格）。退出时 `termios.tcsetattr` 还原终端。

## 4. 验证结果

- 语法检查通过（`ast.parse`）
- `--help` 正确显示 `--terminal`/`--raw` 参数说明
- **真机交互测试未完成**：测试时 USB 物理断开（`lsusb` 不见 FTDI），非代码问题。待 USB/板子恢复后由用户实测。

## 5. 还会再有吗

- **cbreak 兼容性**：Linux termios 标准接口，本机 Linux 5.15 OK。其他平台（macOS）理论兼容，Windows 不兼容（Windows 无 termios，需另用 msvcrt）--当前仅支持 Linux。
- **行编辑简陋**：cbreak 下只实现了退格，无方向键/历史。够用调试，要完整行编辑可后续引入 `readline`（但 readline 与 cbreak+Tab 切换冲突，需权衡）。
- **大流量输出**：板子高速刷屏时（如 FTP 崩溃循环）RX< 会刷屏，可考虑加暂停键（后续按需）。

## 6. 经验沉淀

- **调试工具与测试框架解耦**：实时交互（Xcom 式）与命令-响应（exec_sync 式）是两种模型，硬塞进 SerialConsole 会污染核心。独立工具复用纯函数（detect_port/ansi.strip）是干净边界。见 [[ats-architecture]]。
- **cbreak 实现 Tab 切换**：input() 阻塞挡 Tab，要运行中切换显示模式必须 cbreak 逐字符读。这是终端交互工具的通用技巧。
